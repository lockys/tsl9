# V4.1.60 BT KeyBoard：s4=2 局部靜態證據

## 先前搜尋與來源

搜尋 `analysis/`、`evidence/` 的 `11dce`、`s4=2`，以及 `analysis/` 的 `BT KeyBoard`、`11dd0` 等：找到 dispatcher 指令清單與 `analysis/registered-callbacks-2026-10-24/evidence.json`，未找到此分支的具體語意報告；搜尋範圍不是全倉所有文字。另檢視 `experiments/tsl9-bt-keyboard-local/README.md`：它只分析 s4=8，明確將 2 排除。此報告另置目錄，不修改該分支。

原始證據是 `firmware-downloads/legacy-options-2026-10-20/BINs/ID-2966-V4.1.60-decoded.bin`，映射基址 0x8000，SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。地址為映射 PC，不是檔案偏移。輔助閱讀使用既有 `analysis/registered-callbacks-2026-10-24/evidence.json` 指令清單；這不是 REA Evidence。下述是靜態推導，非執行觀察。

## 入口、判斷與資料流

上游 0x1238a 載入 `s3=*(u32 *)(s0+12)`、`s4=*(u8 *)(s0+10)`，s2 是更早形成的指標；假設中途呼叫遵守 ABI。0x11cc8 經 `[s6]` 間接呼叫，參數為字串 0x1a5d4 `BT KeyBoard`、s5、長度 11；0x11cda 返回值為零則往 0x11d26，非零才進分支。此處不假設間接函式必然為字串比較或會返回。

- 0x11cde 對 s4 != 8 跳 0x11dce；0x11dd0 對 s4 != 5 跳 0x11e16；0x11e18 對 s4 != 2 跳 0x1240c。於是本文以成功抵達且 s4=2 為前提。
- 0x11e1c 讀 `p1=*(u8 *)(s3+1)`，0x11e20 無號比較 `2 < p1`，成立跳 0x1240c；可接受 0、1、2。再讀 `q2=s2[2]`、`q1=s2[1]`、`p0=s3[0]`，形成 `q2<<8 | q1<<16`，並令低位 `(p0+p1)&255`。0x11e3c 跳 0x11c56，該處加低位及 `s2[0]<<24`。因此結果為 `s2[0]:s2[1]:s2[2]:((s3[0]+s3[1]) mod 256)`；低位溢位不進位。此路徑沒有讀 s2[3] 或 s3[2]。
- 0x11c60 結果為零則跳 0x1240c；否則 0x11c64 讀 byte 0x2000bfd3，非零到共用下游 0x12186，零到 0x11c78。其他路徑也進入此共用區，不能把本分支條件推廣至所有來路。

## 零旗標共用下游的可見副作用

從 0x11c78 起依序寫 `1` 至 0x2000bfd3、寫所組合的 32 位結果至 0x2000bfcc、寫 16 位零至 0x2000bfd0、寫 byte 零至 0x2000bfd2。0x11c9a..0x11cae 從 0x40058 載入間接目標，以 `a0=*(u8*)0x2000bfc8, a1=1, a2=480` 呼叫。此處以呼叫邊界停止；不推測其結果、後續副作用或是否返回。非零旗標的 0x12186 與 0x1240c 只作有界出口，未分析其後行為。

## 重現與限制

`python -B -m unittest discover -s experiments/tsl9-bt-keyboard-s4-two -v`：核對完整映像 hash、入口與分支/共用下游的連續原始 bytes、獨立解碼選定 32 位分支與壓縮跳躍；對各窗口突變及截斷做負測試。純 Python 模型涵蓋 0/1/2、3 拒絕、低位回繞、零值出口、兩種旗標與讀取不足。模型不是 CPU 模擬器；其他壓縮指令及暫存器語意依指令清單判讀，不是完整獨立反組譯。模型先驗假定映射、指標有效且可讀，並不證明實際可達、記憶體內容、ABI、間接目標、並行/中斷或裝置行為。無硬體存取、韌體執行或模擬器執行。
