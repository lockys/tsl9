# Scheduler original-VA source-object probe

Offline only: `python experiments/scheduler-9124-original-link/check.py` (optional `--ndk-bin` points to the pinned Android NDK LLVM bin directory). No candidate image or hardware is touched. Temporary objects and ELF are removed automatically.

The unchanged `src/native/receive/scheduler.c` is compiled directly, independently as C11 and C++17. Each object is linked at original addresses with no relaxation, then every symbol's address and size and the complete executable `[0x9124,0x9250)` (300 bytes) are checked against the decoded reference at base `0x8000`. The reference window SHA-256 is `45dd01a76fedc4bd8d01fdb7ff005f410166a68f171d52420d19da2cbba2e992`. Source, reference, compiler, linker and the freestanding `stdint.h` are hash-pinned in the script. The host OS and compiler runtime libraries are not independently pinned; this is not a hermetic toolchain.

For both languages, the baseline is exact. Independent source-copy mutations change the C divisor 625 to 624 (difference `0x91dc`), invert the `0x920a` conditional branch (`0x920d`), or redirect that branch to `0x922c` (`0x920d`); each is rejected by byte comparison. Sizes and all addresses are checked for mutations too. Branches are explicit assembly/relocation ports in the existing source, not C-level branch semantics. This demonstrates sensitivity to these specific changes, not comprehensive mutation coverage, runtime behavior, ABI validity, or hardware correctness. The source also uses explicit architectural assembly elsewhere, so equality is not proof of a purely C reconstruction.
