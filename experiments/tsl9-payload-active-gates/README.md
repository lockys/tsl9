# 新分派路徑與兩個前置檢查

[English](readme.en.md)

前一輪定位到：若 `0x1416E` 與 `0x144AA` 的條件式呼叫依序命中同一項，可形成 `flag=1,type=2`。若該項的 halfword 也不是 `0xFFFE`，且狀態保持至後續檢查，這一項會通過 `0x82D2` 和 `0x838E` 的三項啟用判斷；它們皆以 `0x2000C794` 為基址、四 byte 步進檢查兩項。

兩個函式在啟用路徑正常完成、必要呼叫保留暫存器且沒有干擾時會回傳非零。相應已辨識呼叫點 `0x12CB4` 與 `0x123A8` 對非零回傳分支離開各自的後續路徑。這將新開放的狀態寫入與先前 `0x1A078`／`0x1A638` 路徑的前置條件連接起來；它不證明實機曾接收命令、兩次讀取看到相同狀態，或所有其他入口都受到相同影響。

`python scripts/verify-payload-active-gates.py --tool-dir <LLVM_BIN> --out <NEW_OUTPUT_DIR>` 重新核對前置路徑與候選建置，再比對兩個檢查器和呼叫點的原始指令及合成正反例。不執行韌體或硬體。
