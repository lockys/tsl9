# 時脈記憶體效果與正常返回暫存器重建

此 C11／C++17 元件在先前時脈重建上加入來源特定的暫存器效果。
原始查詢只寫 A2–A5，衍生欄位只寫 A4／A5。查詢留下的 A3 會通過已知的
`9A42 → 1973C → 9F4C → 131C2` 路徑，在 `0x131E0` 傳給未知 callback；
該回呼位址來自 `READ32(0x4004C)`。不能用一般 C 呼叫慣例假設這個值無用。

共用 C 保留先前所有即時 MMIO、GP 與表格存取，另重建全部查詢分支的 A3，
只在 external PLL 路徑寫入 A2，並保留查詢最終 A4／A5。衍生欄位保留
A4=1000，以及截成 halfword 前的完整 A5 乘積。例如輸入 528,000,000，
A5 為 66,000，但實際寫入的 halfword 為 464，兩者不能混用。

## 離線主機檢查

```sh
sh experiments/tsl9-v4160-clock-registers/verify.sh --language both
```

也可直接執行 `python3 -B experiments/tsl9-v4160-clock-registers/verify.py
--language both`。需要 Python 3.10+ 與 C11／C++17 編譯器；`CC`／`CXX`
可指定單一編譯器執行檔，shell 入口用 `PYTHON` 指定 Python。
驗證器不下載資料。沿用未修改的記憶體測試、核對其雜湊，驗證封存的
214 bytes／69 條指令及 50 個 raw 負例，再核對原始整數目的暫存器欄位。
路徑解析支援調查目錄及發佈的 `analysis/` 配置，直接重用封存解碼函式，
不依賴歷史 helper CLI 的舊目錄前綴。

每語言有六組／293,845 項主機檢查。新增檢查涵蓋各查詢路徑的返回值、
A2 條件式賦值順序、即時位移，以及既有 PLL、shift byte 與商數邊界下的
完整衍生輸出。`--tests-only` 明確略過來源證據；紀錄保留實際輸入、
編譯器與主機測試執行檔雜湊。只執行這些合成主機測試。

## 原生限制與後續工作

原生分支使用編譯器專用的空實體暫存器 barrier、明確的 unsigned DIVU，
以及逐函式的暫存器保留旗標。編譯／連結、ELF 暫存器與 CFG 檢查記錄於
`analysis/v4160-clock-abi-2026-10-21/compiler-review/`。
編譯器若無法滿足檢查會失敗，不會偷偷加入堆疊 wrapper 或放寬暫存器範圍。

查詢候選為 196 bytes，超過原始 174-byte 範圍，不能直接替換原址；
衍生欄位候選為 38 bytes，原始為 40 bytes。這些大小不代表映像、呼叫端、
中斷、ROM 或硬體相容。原生查詢的完整分支語意尚未由結構及主機測試證明，
空 barrier 也不能證明非同步時序或中途暫存器狀態等價。
未替換原始入口、未執行或模擬 RV32、未存取周邊，也未產生 BIN。
可燒錄完整映像的最終目標仍未完成。
