# Callback + scheduler original-VA composition

Offline only: `python experiments/callback-scheduler-original-link/check.py` (optional `--ndk-bin` selects the pinned Android NDK LLVM bin). Requires the three earlier `callback-901a-original-link`, `callback-907a-original-link`, and `scheduler-9124-original-link` experiments. All outputs are temporary; no candidate or hardware is touched. Do not run Python with `-O`.

The unchanged full `src/native/receive/callback_table.c` and `src/native/receive/scheduler.c` are separately compiled as C11 and C++17. The linker consumes their **actual object sections**, selected by object and ordered explicitly, not bytes extracted and reassembled as `.byte`. The single executable output section `[0x901a,0x9250)` is 566 contiguous bytes. Each of the 48 region symbols is checked for address, size and section ownership, and all 566 bytes are compared with the pinned decoded image (base 0x8000). Window SHA-256: `26e0e349ace4cf2780c4e1edea385e0ec8eb5c8fe1175013dbbc36f4e3e49797`. The sources, reference image, compiler, linker and `stdint.h` are hash-pinned; host OS and runtime libraries are not, so this is not hermetic.

A separate synthetic probe object calls the callback entry, scheduler entry and a synthetic external stub in another object. Its three call relocations and decoded linked destinations are verified; removing either source object or the stub fails the strict link, and an output-size assertion also requires the full window. **The real callback object has no relocation to the scheduler object:** its 8 branch relocations target callback blocks. Thus probe-to-source cross-object resolution is demonstrated, not a native callback-to-scheduler call. The external stub is a link test only, not an implementation or verification of the actual indirect resident services. The original code uses fixed-address/indirect architectural ports; no synthetic stub replaces bytes in the window.

Both languages reproduced the complete window exactly. Independent temporary source-copy mutations were rejected: early callback constant (difference `0x9024`), late callback constant (`0x9088`), scheduler divisor (`0x91dc`). Missing callback, scheduler and stub objects each failed closed in both modes. This only establishes these specific static link and sensitivity results. Explicit assembly and relocation ports remain in the sources; it does not establish pure C semantics, runtime ABI correctness, resident behavior, execution or flash safety.
