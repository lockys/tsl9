# BT KeyBoard 後續：局部靜態切片

對象是 V4.1.60 decoded APP，基址 0x8000、SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。以下是靜態指令推導，不是執行觀察。上游完整到達條件並未由本切片證明；此處以 0x11cc8 為入口，只界定比較結果非零且 `s4=8` 的局部切片，不聲稱涵蓋整個 callback 或所有名稱。

## 控制流與資料流

- 上游 0x1238a 從 `s0` 讀出 `s3=*(u32 *)(s0+12)`、`s4=*(u8 *)(s0+10)`；`s2` 在更早的表格路徑形成。假設中間呼叫遵守 ABI 保留這些暫存器。s3 是指標，並非 0x40000。`s5=[gp+92]+s7+9`，這需要上游路徑和 ABI 保留假設。
- 0x11cc8 從 `[s6]` 重新載入間接目標，a0=0x1a5d4（`BT KeyBoard`）、a1=s5、a2=11，0x11cd8 呼叫；正常返回後 0x11cda 對 a0 零跳 0x11d26，非零進 0x11cdc。0x11d26 是下一名稱比較入口，本切片在此停止；非零只有在參考比較候選確實適用時才可解讀為前 11 bytes 相等。
- 0x11cdc 的 `s4 != 8` 跳 0x11dce（之後另有 5、2 等分支；不在本切片）；`s4 == 8` 才依序檢查 `[s3+1,+3,+4,+5,+6,+7]` 都為零。每個非零均直接跳 0x1240c；此處只把它視為切片出口，並非斷言其全域語意。
- 通過檢查後 0x11d12..0x11d24 構造 `([s3+0]<<8)+[s3+2]`，並取 `[s2+1]<<16`，跳到共用區 0x11c56；該處加上 `[s2+0]<<24`。因各項位元不重疊，結果是 `s2[0]:s2[1]:s3[0]:s3[2]` 的四 byte 組合。0x11c60 值為零跳 0x1240c，非零進 0x11c64。此路徑不讀 s2[2] 或 s2[3]，也不要求 s3[0] 或 s3[2] 各自非零。
- 0x11c64 讀取另一個靜態位址的 byte，非零在 0x11c74 跳 0x12186，零落入 0x11c78；這些是本局部元件的後續出口。共用區亦可從其他路徑進入，故不能將本切片前提套用到所有 0x11c56 來路。

## 證據與限制

`test_local.py` 直接核對固定映像 hash、入口、檢查與共用區連續原始 bytes，獨立解碼列出的 32-bit 條件分支目標，並測試選定窗口突變、截斷及純 Python 資料組合模型。測試另獨立解碼 0x11d24 的壓縮跳躍；其餘壓縮指令及資料流的解讀可對照 `src/native/receive/registered_callbacks.c` 中相應位址，但該重建檔不是原始證據；測試未獨立完整反組譯。模型假設指標有效及 bytes 可讀，不是模擬器。

`[0x4003c]` 為可變間接目標，實際值、實際比較語意、任何副作用與呼叫是否返回均未知；公開 WCH resident 僅是有條件的候選，見 `experiments/tsl9-wch-memcmp-contract/README.md`。記憶體內容、指標有效性、中斷、ABI 實際遵守與 0x12186/0x11c78 後續行為未證明。沒有硬體、韌體或模擬器執行，也沒有 REA Evidence。

重現：`python -B -m unittest discover -s experiments/tsl9-bt-keyboard-local -v`。
