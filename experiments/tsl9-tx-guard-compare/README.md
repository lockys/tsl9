# TX 候選的一個條件式守衛比較

[English](readme.en.md)

在 V4.1.60 原廠 APP 與 TX 候選的 `0x8A76..0x8A82`，兩者先執行相同的 `bne a4,a0,0x8A96`。落入路徑接著執行相同的兩條壓縮指令；原廠在 `0x8A7E` 比較 `a4==a5`，候選比較 `a5==a0`，目標均為 `0x8A96`。

只要控制流程確由前述分支落入且沒有非同步改寫暫存器，前者成立代表 `a4==a0`，因此兩個相等比較在此局部路徑結果相同。[檢查器](check.py)只讀兩個 APP 各 12 個允許的 bytes，固定指令編碼並解碼三條分支的暫存器與目標；不執行 target。它不排除直接跳入中間的未知入口，不證明其他 TX 差異、整體 ABI、ROM 或硬體相容，也不證明此 BIN 可燒錄。

## 複製迴圈的局部比較

在 `0x8B10`，原廠以 unsigned `a0<s0` 跳到 `0x8B52` 複製，否則落入 `0x8B14` 完成路徑；候選以相反的 `a0>=s0` 跳到 `0x8B2E` 完成，否則落入 `0x8B14` 複製。兩者的索引低 16-bit 擷取相同，迴圈本體指令順序相同，唯一非跳轉差異為地址加法交換兩個來源運算元；兩者均回跳 `0x8B0A`。[檢查器](check-loop.py)固定有限窗口、解碼分支與回跳並比對本體，不執行 target。

在兩版以相同有效暫存器與記憶體進入、正常執行且不從中間跳入或遭非同步干擾時，這支持該段的局部比較、逐 byte 讀寫及校驗累加順序相同。它不證明來源／目的有效、全部呼叫者或後續完成路徑等價，也不證明實機啟動或可刷寫。

## 完成路徑與間接槽

原廠 `[0x8B14,0x8B52)` 與候選 `[0x8B2E,0x8B6C)` 的完成路徑長度均為 62 bytes。除乘法交換來源運算元，以及計算 `a2` 時先加 GP 或先形成 `GP+148` 兩組不同編碼外，其餘對應 bytes 相同。兩種算式均為 `(4*a2初值 + GP + 148) mod 2^32`；後續相同指令從該地址讀 byte，並從 `0x40050` 取得尾跳目標。

在兩版以相同有效暫存器與記憶體進入、正常完成而無中途入口、例外或非同步干擾時，這支持相同的對應記錄讀取及間接槽呼叫。[檢查器](check-tail.py)固定兩段有限 bytes；未執行 target。中間 `a5` 暫存器值可不同，異常或中斷觀察不可忽略；槽實際身分、記憶體有效性、完整 ABI 及實機啟動仍未證實。

## 迴圈前的完整 TX 區段

[前段檢查器](check-prefix.py)比較兩版同位址 `[0x8A56,0x8B0A)` 的 180 bytes，確認除上述 sentinel 比較與 `0x8AD2` 的乘法交換來源運算元外，其餘 bytes 完全一致。兩種乘法均將 `a2*a5` 的 RV32 低 32 bits 寫入 `a5`；檢查器解碼 MUL 欄位，並重跑 sentinel 分支檢查。兩組指令共 4 個位元組不同。

結合本頁迴圈及完成路徑的結果，可針對正常入口、相同有效狀態、正常記憶體與無非同步干擾，支持 TX 主要路徑的局部對照；這仍不排除未知中途入口、例外／中斷、副作用、未驗證的 resident ABI 或其他實機差異，也不是成功燒錄／重啟的證據。僅讀指定 APP 範圍，未讀取排除區或執行 target。

### 前段分支目的地與搬移後版面

[分支檢查器](check-prefix-edges.py)逐一掃描兩版前段的 62 個指令邊界：7 條直接分支的目標均是同一前段內的指令邊界，或 `0x8B6C` 的共用 return；兩版該 return 的兩個 bytes 相同。前段另有兩個間接呼叫，分別位於 `0x8A8E`、`0x8AB4`，以及位於 `0x8ACA` 的 return；本檢查不解析間接呼叫的實際目標或副作用。檢查器也重跑迴圈和尾端的有限窗口檢查。

這排除了這七個已辨識直接分支因本次迴圈搬移而落入不同指令的疑慮；不涵蓋其他函式的計算式中途跳入、間接呼叫效果、例外／中斷或實機執行，因此不構成完整等價或可刷寫證明。

### 允許區內外來的直接跳轉候選

[直接跳轉掃描器](check-direct-entries.py)在原廠及候選 APP 的允許區內，以每兩 bytes 為候選邊界解碼 RV32 `JAL`／branch 與 RVC jump／branch；不掃描 TX 自身及既定排除區。兩版各得到相同 8 個目標落入 TX 的數值候選，全部指向公開入口 `0x8A56`，沒有指向 `(0x8A56,0x8B6E)` 中間的命中。另以 radare2 對這 8 個允許來源窗口獨立解碼，目的地計算一致。

這是**有限直接編碼掃描**，資料或指令中間 bytes 也可能被誤判為命中；它不涵蓋排除區、`JALR`／計算指標、其他映射、runtime 改寫或實際可達性。因此結果降低已掃描範圍內直接中途跳入的疑慮，不能證明沒有其他入口，也不證明可刷寫或啟動。

與[既有來源審查摘要](../../analysis/v4160-tx-image-integration-2026-10-22/source-review/readme.en.md)的九個已記錄呼叫點對照：該摘要另列 `0x14738→0x8A56`，其來源位於目前不讀取的排除區，因此不可能出現在本掃描的八個結果中；排除區仍可能有其他未知入口。本輪比對時誤載入包含排除區指令編碼的歷史參考 JSON，違反既定讀取限制；未輸出該編碼或讀取原 BIN 對應區段，後續改用純文字摘要，不將該載入視為指令重驗。
