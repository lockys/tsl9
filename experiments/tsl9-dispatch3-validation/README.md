# 分流分支的緩衝區檢查

在先前的 76-byte 配置及複製均正常完成、指標有效且不發生位址回繞的條件下，`0x142C0` 要求將 offset `[4,18)` 的 14 bytes 交給函式；隨後 `0x142DA..0x142EA` 逐 byte 檢查 offset `[36,40)`，這兩個範圍均在 76-byte 內。檢查遇到第一個不在 32–126 的 byte 就轉往 `0x14A1E`，不保證四個 bytes 都被讀取。

不論前述逐 byte 檢查是完成或提前失敗，已辨識的兩條路徑都抵達 `0x142EE`，以配置指標請求呼叫 `0x40068`，之後才依保存的結果分流。固定 WCH V1.31 參考標頭將該槽宣告為 `tmos_msg_deallocate`；這不證明實機已釋放、配置／複製成功，或其他路徑與例外也會釋放。前述 14-byte 函式的內部副作用、實際記憶體、resident／IRQ 與 stack 均未完整確認。

[模型](validation.c)只接收合成的函式返回值和四個合成 bytes，不執行內部驗證或釋放。Windows MSVC C11／C++17 各通過 2,048 案例；`verify_instructions.py` 核對 20 條指令、WCH 參考槽與界限算術。模型未整合進候選 BIN，沒有讀取裝置資料或執行韌體。
