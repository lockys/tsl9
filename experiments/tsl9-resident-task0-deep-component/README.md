# Task 0 深層依賴 C/C++

[English](readme.en.md)

補齊前輪 `56972`、`2000156C` 及必要支援函式。共 **六個完整本體／2,130 bytes／713 條指令**，以保留原暫存器情境與明示指令 port 的 C/C++ 重建；實機 ROM／RAM mapping 尚未證明。

| 候選原位址範圍 | Bytes | 自身 frame |
|---|---:|---:|
| `435CE..436A8` | 218 | 32 |
| `55DEA..55E44` | 90 | 0 |
| `55F94..5605C` | 200 | 16 |
| `5627A..56326` | 172 | 16 |
| `56972..56CB2` | 832 | 16 |
| `2000156C..200017D6` | 618 | 48 |

全部原始 bytes、完整 CFG、自身 frame 及 `ret` 後仍可達分支均核對。RAM 本體沿既有啟動 copy mapping 對應實際 SDK Flash bytes。38 個 Xwchc 操作仍屬條件式 ISA 解碼，不是實體晶片識別。

已確認的局部行為：

- `56972` 先讀輸入物件 `+10`；若零，在配置自身 frame 前返回 1。非零路徑會將 `+128` 的半字計數加 1、保留 low16，並清零 byte `+24`。這些數值的完整協定意義仍未證明。
- `55DEA` 會讀到 `A0+487`，並將計算結果的低 byte 存到 `A0+78`。保留三個原始 signed DIV 指令；未以猜測的單位或 C 算式替換。這要求相應記憶體可讀／可寫，不代表已證明實際物件大小或硬體 RAM 容量。
- `2000156C` 的 `17D0` 返回後，`17D2 → 17B6` 仍是原入口可達分支，沒有截去。

C11／C++17 實際物件相同，逐 byte 原位址重編碼、獨立 ELF readers 與非載入式合併通過。累計 **40,874 CODE＋392 DATA bytes／14,060 條指令**；前輪兩個 UND 均由真實本體提供，新加入的靜態直接／far-call 目標也都有本體，**目前零具名 UND**。

零具名 UND **不是執行期閉合**。新本體仍含未串接的 `43648` 間接呼叫；目前這份部分 SDK 物件共 **63 個 register-transfer sites，51 個具有至少一種條件情境，12 個尚未串接**。不涵蓋整份 APP、所有 live 值或實體效果，也不是功能完成率。

原 APP 靜態覆蓋率維持 **95.54%**。啟動來源 4 bytes、實機晶片／ROM／RAM／IRQ／Flash／OTA 與完整功能相容性仍未確認。未執行目標、模型、模擬器或硬體；**未產生 BIN，尚不可宣稱可燒錄**。

功能候選：離線列出各函式的物件存取範圍、欄位寬度與記憶體前提，避免將「可編譯」當成「配置大小足夠」；目前僅提案。
