# 0x148b4 共用框架續段：受限語意模型

本實驗針對已知的 42-byte 續段 `[0x148b4,0x148de)`，不是獨立可呼叫函式。既有原位組譯重建見 `src/native/receive/ota_dispatch_148b4.inc`；此處新增 C 暫存器與記憶體事件投影，不主張 byte-exact C、可達性或完整 dispatcher。

假設半字讀取成功且呼叫者提供該讀取值：`a2` 先以 RV32 取模加一，讀取位址為 `s0 + 2*a2`；若 `a0 < loaded`（無號），跳到 `0x148de`，不寫入且不將 `a2` 截為 byte。否則以原 `a3` 計算 `sp + 48 + 2*a3` 的半字寫入，再將加一後的 `a3` 與 `a2` 截至低 8 bits，跳到 `0x1488e`。C 運算採 `uint32_t` 模 2³²。模型未執行實際 memory：讀取值由呼叫者供應，寫入地址及值僅在 `wrote` 為真時有效；不涵蓋例外、MMIO、別名、副作用、並行或後續指令。

`verify.py` 核對原 BIN 長度、固定 SHA-256 與上述指令原始 bytes，分別以本機 MSVC C11、C++17 編譯執行 4 個邊界 smoke tests：分支、相等、32-bit 位址環繞、無號比較、舊索引及 byte 截斷。另外將編譯後的模型分別與手寫逐指令 oracle 及 `machine.py` 各比較 216,608 組輸入（20,000 組固定種子，及 65,536 個半字讀取值各測相等、較小與較大；讀取值為零時較小值飽和為零，並非所有暫存器組合），並對有號比較、過早截斷與使用新索引三種語意變造各自確認被偵測。`machine.py` 直接解碼固定原始 bytes 的有限 RV32I/C 指令子集並逐步模擬，未知指令拒絕；測試亦在記憶體中改變 C.ADDI 與 LHU 的 immediate，確認解碼後讀取地址隨之改變。讀取值仍由測試提供且寫入只記錄事件。兩個 oracle 均為本實驗自行實作，可能有共同錯誤，亦不模擬 trap、外設、競態或實機。此機器的環境初始化可能列印 `vswhere.exe` 找不到，但只要編譯器或測試失敗腳本就會失敗。

## 其他分類路徑

新增 `step_148de`，對固定 BIN `[0x148de,0x1491a)` 的兩條遮罩分類路徑作暫存器及寫入事件投影，並經 `0x148d8` 將 `a2` 截為 byte 後止於 `0x1488e`。若 `a1 & a6` 非零，以舊 `a4` 在 `sp+24+2*a4` 寫入並將計數器加一截為 byte；否則若 `a1 & a7` 非零，改用舊 `a5` 及 `sp+36+2*a5`；兩遮罩同時符合時前者優先，均不符合則無寫入。`t1`、`t3` 及運算環繞亦納入投影。這是從 `0x148de` 開始的局部模型，不主張此輸入必然可達或寫入成功。

`classification.py` 固定韌體 SHA-256 與 60 個原始 bytes，以另寫的逐指令效果 oracle 對 C/C++ 各比較 85,536 組，包含每個 16-bit `a1` 值；另確認第一遮罩、兩個寫入偏移及兩個計數器共五種語意變造會失敗。另以 `class_machine.py` 直接解碼原始 classifier 與共用尾段的有限 RV32I/C 指令，逐筆比較同一批輸入；測試也變造 store immediate、條件分支目標、尾段 mask、跳躍目標與無效指令。兩個 oracle 均自行實作，仍可能有共同錯誤；不含記憶體、例外、其他路徑或硬體執行。C 與 ctypes 結構大小及所有欄位偏移在呼叫前核對。

## 相鄰迴圈判斷

原 BIN `0x1488e` 的 `bltu a2, s2, 0x148b4` 另以 `gate_1488e` 建模：無號比較成立轉至 `0x148b4`，否則落至 `0x14892`，不變更暫存器或記憶體。測試從固定 BIN 解碼分支立即數，對 12×12 組邊界輸入與 C/C++ 模型比較。單步模型止於下一個 PC，不包含後續呼叫、記憶體安全或硬體行為。

### 前置間接呼叫的候選身分

`0x14848` 從 `0x40048` 讀取函式指標並呼叫三次，每次重新載入指標；參數分別為 `(sp+48,0,112)`、`(sp+24,0,12)`、`(sp+36,0,12)`。WCH SDK 保存的預設表定義將該位置對應 `tmos_memset`（`analysis/wch-resident-candidate-2026-10-21/original-dec2023/wchble_rom.h`），兩個候選 resident 的同一 slot 指向已分析的 byte-fill 程式（`analysis/v4160-config-lifetime-2026-10-22/memset-review/readme.en.md`）。若三次均使用該候選且正常完成，可條件性推知清零 `[sp+24,sp+160)`；實際裝置的 slot、目標、記憶體副作用和正常返回都未證實，不可把候選當成實機觀察。

### 接收長度閘門的數值交集

`ingress_bound.py` 解碼原 BIN `0x89e0` 的上限載入及 `0x89e4` 無號分支，窮舉非零 16-bit 值：1–1040 在此閘門落到 `0x89e8`，1041 以上分支到 `0x89f0`。若僅在算術上假設這裡的長度與後續 `s2` 初值相同，其可通過閘門且使 `((length-2)&0xffff)>>1 > 255` 的值為 1 及 514–1040（後者 527 個）；前述 dispatcher 前置條件排除長度 1。這不是端到端的可達性證明：本測試不模擬封包狀態、checksum、呼叫、長度傳遞或記憶體；零長度走其他分支，不在此測試範圍。

### Dispatcher 入口暫存器與呼叫

`entry_provenance.py` 從固定 BIN 解碼入口 `0x14066`、`0x14068`、`0x1406a`，分別得到 `s1=a0`、`s0=a2`、`s2=a3`；並驗證直接呼叫 `0x14240→0x81aa`、`0x147f8→0x13ba6`、`0x147fc→0x1070a` 的目標，含位元變造檢查。另 `entry_route.py` 對 `0xc0` 使用有限原始指令解碼器，檢查六個合成長度均依指定分支軌跡到達 `0x140ba`，且保留上述三個暫存器；該投影在連線狀態檢查前停止、不呼叫函式。靜態指令紀錄 `experiments/tsl9-v4160-startup/src/gatt_ingress_native.c` 顯示，`0xc0` 到迴圈前尚需連線狀態相符、`0x81aa` 返回非零、payload 前兩 byte 均為 `ff`、第一個後續半字不走特殊出口等條件。若該路徑被選中且中間呼叫均正常返回並保存 `s2`，入口 `a3` 長度可供後續算式使用；這支小型檢查器不執行中間指令或被呼叫函式，也不證明實際可達性。尤其不可由 `length != 1` 推論緩衝區至少有四 bytes。

### 連線識別比對

`connection_gate.py` 從原始 bytes 解碼 `0x140ba` 起的兩次 `LHU` 與分支，測試 327,680 個合成案例。它先將 `s1` 與 `0x2000c796` 的 16-bit 值比較：相等即跳 `0x141ac`；否則再讀 `0x2000c79a`，相等落至 `0x140d8`，不等則跳 `0x14c7e`。兩值都相等時第一個優先；帶非零高 16-bit 的 `s1` 不會等於零延伸半字。測試供應的半字只是假想記憶體，並假定成功且穩定讀取；不代表已讀取裝置 RAM 或證明該狀態實際存在。接續的 `connection_state.py` 分別從兩個相等分支解碼，測試每個選中 byte 的全部 256 種值：第一組讀 `0x2000c798`、第二組讀 `0x2000c79c`，非零到 `0x141d6`、零落到 `0x141bc`；未選中的 byte 不影響結果。此為成功讀取的有限投影，未證實記憶體內容、別名、競態、硬體或後續執行。

### 命令與呼叫返回值的分支

`command_gate.py` 從 `0x141d6` 解碼 `0xc0` 的後續分支與暫存堆疊事件：`0x1423e` 將命令存到 `sp+12`，`0x14244` 取回。對 `0x14240→0x81aa`，測試不執行被呼叫函式，而是假設正常返回、合成堆疊未遭改動並提供 `a0` 返回值；在此模型中，零落到 `0x14248`，非零沿 `0x141fa` 等指令到 `0x143ca`。測試含三種合成 `sp`（含 RV32 位址環繞）、五種返回值與條件分支變造；不代表裝置上的 stack 有效、該函式返回值可控，或後續程式已執行。

### Payload 前綴分支

`payload_gate.py` 從 `0x143ca` 對 `0xc0` 解碼至首個呼叫前，對長度 20 窮舉 65,536 種前兩 byte：只有 `ff ff` 到 `0x147f8`，其餘到 `0x1491a`；首 byte 不是 `ff` 時不讀第二 byte。到 `0x147f8` 前，呼叫參數為 `a0=s1`、`a1=2`，`s0`、`s1`、`s2` 在此片段保留；這裡尚未執行被呼叫函式。另測長度 0、1、2、514 與 RV32 位址環繞：此局部投影在檢查長度前先讀首 byte；長度 1 在 `0x14498` 停止，長度 0 若供應可讀的 `ff ff` 則可沿此片段到 `0x147f8`。這不證明長度 0 可由入口抵達、不證明讀取有效或發生越界，也未執行 `0x147f8` 後的呼叫。

### 第一個被呼叫函式

`state_setter.py` 局部解碼 `0x13ba6`，以合成記憶體執行 327,680 個條件組合。在讀寫成功、無中斷及無競態的假設下，`a0` 先與 `0x2000c796` 的半字比較，相等則將 `a1` 低 byte 寫至 `0x2000c799`；否則再與 `0x2000c79a` 比較，相等則寫入 `0x2000c79d`；皆不符不寫。兩者皆相符時第一個優先；比較使用完整 RV32 `a0` 與零延伸半字。該函式保留 `a0`、`a1`、`sp` 並直接返回，但不代表另一個呼叫 `0x1070a` 的行為已驗證；欄位意義及實機狀態未知。

### 接收模型中的封包案例

`ingress_witness.c` 使用既有 `experiments/tsl9-v4160-gatt-ingress-model/` 的合成後端與接收語意模型，送入 `0xc0` 命令及 20、514-byte payload；兩者首個資料半字都是 little-endian `0x0800`。在該模型及測試後端下，無論整包送入或拆成 1、4、其餘 bytes 三段，正確 checksum 均各產生一次指向 `0x14056` 的 dispatch，參數帶入原 payload 與長度；前兩段未觸發 dispatch，checksum 翻轉一位時也沒有 dispatch。測試逐 byte 比對 20-byte payload 與下節人工追蹤相同。C11 與 C++17 均執行；模型的 dispatch 是外部事件，不執行 `0x14056`，此測試不是原始指令模擬，亦未連接後續迴圈或證明實機可達性。

### 人工組合追蹤：分類寫入重疊

前一版 8 筆人工序列若從正常入口開始，第一筆 `0x1000` 與前置條件衝突：`0x14800` 預讀 `[s0+2]`，值為 `0`、`0x1000` 或 `0x2000` 時不進入此迴圈；在記憶體保持不變下，第一輪恰好再次讀取該半字。`predecessor.py` 以有限 RV32I/C 位元組解碼器測試成功讀取的所有 65,536 個半字：三個特殊值各到不同出口，其餘 65,533 個到 `0x14848`；測試亦檢查 32-bit 位址環繞與拒絕無效指令。這只覆蓋前置片段，不含中間呼叫和記憶體行為。另 `length_bound.py` 從 `0x1486a` 起解碼 `s2` 算術，假設其中間接呼叫正常返回且依呼叫慣例保存 `s2`，驗證全部 65,536 種 16-bit 輸入及 5 個 RV32 邊界均符合 `((length-2)&0xffff)>>1`。算術上長度 0 或 1 得 32767，2 得 0；窮舉可得 16-bit 長度中，恰有 65,024 個使結果大於 255：0、1 和 514–65535。邊界 512、513 均得 255，514 得 256。這些只是算術分類，不代表這些長度可抵達此段（已知前置分支會排除長度 1），也不代表實機會執行這些情況。

`composition.py` 改用符合已檢查的靜態前置條件之 20-byte 假想 payload：`ff ff`，接著 `0x0800`、六個 `0x1000`、`0x2000`、`0x3001`（半字採 little-endian）。首筆 `0x0800` 不是三個特殊值且不觸發分類寫入；長度算式 `((20-2)&0xffff)>>1` 得到 9 次。假設前置間接呼叫正常返回、記憶體穩定、`sp=0x2000`、`s0=0x10000`、讀寫均成功，逐步模型顯示第二分類寫入 `sp+36` 後，第 7 個第一分類索引亦寫入 `sp+24+2*6=sp+36`。程式固定檢查相關前置指令 bytes，但沒有模擬前置呼叫或完整入口，因此這只證明**所檢查的條件相容**，並非實機可達性或漏洞證明。額外以 128 組、每組 32 步人造資料比較四條分類路徑與位元組解碼器。

### 受限組合測試與環繞

另將迴圈判斷與續段模型組合：初始 `a2=a3=0`、`a0=2047`，每次假設成功讀取半字 `0`、寫入成功且沒有其他控制流，測試 263 個 `s2` 值（0–260、32767、65535）。對 0–255，模型在執行 `s2` 次後從判斷離開；對測試的較大值，256 次後兩個計數器回到零。進一步組合四種分類路徑，以 `s2=256` 執行 1,024 次人造讀取（每種路徑各 256 次），逐步比對 C 與位元組解碼器；`a2` 每 256 次環繞、最後迴圈判斷仍然成立。由這些已建模成功路徑的共同尾段可推論：若每次存取與回跳均正常完成、`s2` 保持不變，任何 `s2>255` 都不會由此迴圈判斷離開，讀入資料不限為零。這不是實機無限迴圈證明：記憶體存取可能失敗或有副作用，輸入、堆疊或控制狀態可能遭改動；此投影不模擬實際記憶體、中斷或呼叫。
