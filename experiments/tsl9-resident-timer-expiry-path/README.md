# 計時到期與記錄清理

[English](readme.en.md)

補齊前輪未提供的 `60838`：兩個完整 SDK 候選函式，**258 bytes／84 條指令**。原硬體採用此 ROM 尚未確認。

| 原位址 | Bytes | 已確認的靜態行為 |
|---|---:|---|
| `60838–60856` | 30 | 將傳入記錄 `+49` 寫為 `FF`；以 `A0=0, A1=128, A2=17` 呼叫 `5E3A8`，恢復 RA 與自身 16-byte frame，無連結跳至 `60754` |
| `60754–60838` | 228 | 從 RAM `20003438` 取記錄；釋放 `+68` 指標，清理欄位，停止事件 mask `4/8`，條件式取消 `+49/+48` 計時 ID；旗標非零時清空 callback 指標 |

生產端 `5E76C` 於 `5E88A` 呼叫 `43874`，實際參數為 callback `60838`、記錄 `s1`、延遲值 `uint16(record+56) << 4`，輸出 ID 位址為 `record+49`。時間單位與實際送達未證明。到期入口的傳入記錄與清理端的全域記錄，也只有在額外的記憶體一致性條件成立時才是同一物件。

清理端在 ID 不等於 `FF` 時呼叫 `43A14`，正常返回後寫回 `FF`。RAM `20003240` 非零時，以 `A0=0` 呼叫 `2000078A` 清空 `20002EF8`；**不清除 `20002EFC` 旗標**。保留 `4002420C` 原始讀取、清零、`FENCE.I` 與回存順序；尚未確認該實體暫存器意義或 IRQ 安全性。

C11／C++17 物件相同，原位址重編碼逐 byte 比對、完整 CFG／自身 frame、獨立 ELF readers 與非載入式合併通過。累計 **36,762 CODE＋392 DATA bytes／12,686 條指令**，零具名 UND；不是完整執行期閉合。間接呼叫仍為 **40／51 處**具有至少一種條件證據。原 APP 靜態覆蓋率維持 **95.54%**。

仍缺少啟動來源 4 bytes，以及晶片、ROM、RAM、IRQ、Flash、OTA 與完整功能的實機證據。未執行目標、模型或模擬器，未產生 BIN。

值得新增的功能候選：**離線計時記錄生命週期診斷**，顯示 ID 欄位、`FF` 哨兵與清理條件，協助找出重複取消或指標替換風險；目前是提案，尚未實作或證明既有韌體有此缺陷。
