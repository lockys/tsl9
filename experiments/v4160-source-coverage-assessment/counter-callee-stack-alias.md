# 兩個前綴的合成堆疊別名

`counter-callee-stack-alias.py` 固定原始 BIN 與兩個呼叫前指令片段，依 `sp -= 48` 後的 word store 位移，以模 2³² 位址反推何種**入口** SP 會讓存入的四個位元組之一覆蓋 `0x200040b0`。以入口 SP 四位元組對齊為條件：

- `0x12506`：`0x200040b4`、`0x200040b8`、`0x200040bc`、`0x200040c0`、`0x200040c4`。
- `0x175e8`：`0x200040b4`、`0x200040b8`、`0x200040bc`。

驗證亦檢查 target 為 0、`0xffffffff`、`0x40048` 的模位址邊界；一共 360 組邊界比較。這些是數學上的位址重疊見證，不代表入口 SP 可達、讀寫必然成功、寫入值會改變原值或硬體行為。它們說明若未約束堆疊位置，即使假設 provider 僅操作指定範圍，也不能只憑參數範圍宣稱 counter 不受影響。
