# TX jump-table pointers

The official V1.31 and V1.40 candidate HEX files contain different TX-related pointers: slot `0x40050` contains `0x4354A` and `0x435D6`, and slot `0x4013C` contains `0x4B456` and `0x4B4EE`, respectively. The V1.40 official header declares these slots as `tmos_set_event` and `GATTServApp_ReadCharCfg`, matching the slots and signatures in the previously reviewed V1.30 header. Do not hard-code either version's internal addresses for the other. The [checker](../tsl9-six-dependency-ledger/check-gatt-resident-versions.py) pins both versions' values; this does not establish equivalent behavior, the installed resident, or successful startup.

Both 64-byte candidate routines at slot `0x40050` load a threshold byte from `0x2000319D` (V1.31) or `0x200031ED` (V1.40), then use an unsigned comparison: if input `a0` is greater than or equal to that byte, they restore a previously read control word and return **3**, skipping the lower-value path. If the TX task byte, calling convention, installed resident and execution match this candidate, task ID must be below the current threshold to avoid that error branch. The actual threshold, initialization, subsequent behavior and hardware effects are unknown; passing this comparison does not prove scheduling succeeded. The [checker](../tsl9-six-dependency-ledger/check-gatt-resident-versions.py) pins both candidate bodies and guard encodings without reading excluded APP ranges.

The candidate slot `0x40080` registration bodies at `0x43C4E` and `0x43CDA` use WCH XWCHC compressed byte operations to load the same threshold as old count `n` and the adjacent maximum `m`. If `n >= m` they return `0xFF`; otherwise they store `n+1`, store the input callback at table index `n`, and return `n`. Assuming successful normal registration and no intervening change to the count, the returned ID is below the new threshold and passes the preceding task-ID comparison. Since `n < m <= 255`, the stored increment does not wrap. This does not prove installed behavior, valid table memory, the origin of a particular TX task ID, or event processing. Generic RISC-V disassembly can misidentify these WCH compressed instructions as floating-point instructions; the [checker](../tsl9-six-dependency-ledger/check-gatt-resident-versions.py) pins both bodies and validates their compressed byte fields.
