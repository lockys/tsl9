# 剩餘 CODE 候選函式

[English](readme.en.md)

從官方 ID2966 / V4.1.60 映像的八段窗口，重建十個候選函式：**764 bytes、288 條原始指令**。[C/C++ 來源](safe_gap_functions.c) 保留原始暫存器資料流及明確的組語介面；不是可獨立呼叫的標準 C ABI。

| 原始入口 | 靜態觀察 |
|---|---|
| `0x81CA` | 呼叫 `0x81B0`，回傳值乘以 1000；單位尚未確認。 |
| `0x9B02` | 註冊 `0x9AD2`、寫入 `GP+168`，依參數選擇尾呼叫或寫入 `0x40010814`。 |
| `0x12A6E` | 依原始參數選擇建立堆疊記錄交給 `0x18BA2`，或呼叫 `0x16C72`。 |
| `0x13660 / 0x136D0 / 0x13740` | 經 ROM 指標請求長度 12 的緩衝區，填入標籤 `AB / BA / B9`、欄位與共同回呼 `0x13F36`，交給 `0x9124`。ROM 配置／釋放語意與時間單位仍待確認。 |
| `0x13DD4` | 註冊自身、呼叫 `0x13D48`，依狀態安排 `0x13F88`。 |
| `0x13F36` | 非空記錄的 `+0/+2/+4/+8` 欄位送至 `0x13E98`，再尾呼叫 ROM 指標；空指標直接回傳。 |
| `0x14CC8` | 組合三次 `0x821E`、`0x829E` 回傳值與 `GP+352` 起的原始位元組；沒有自行加上布林正規化。 |
| `0x16C72` | 初始化呼叫序列；入口條件為 `((A0-1)&255)<=1`，通過後仍傳遞完整原始 `A0`。 |

## 已驗證

[原生／靜態收據](audit-result-v1.json)：C11、C++17 實際物件完全相同；64 個正長度 FUNC 區段、43 個直接控制 relocation、6 組 CODE 位址 HI/LO（合計 55 個 relocation）。重編碼為原始位址後，全部 764 bytes 與原廠映像吻合；兩套獨立 ELF 解析器結果一致。獨立物件的 17 個 UND 都能對應到前一里程碑診斷 ELF 的正長度 FUNC。

十個候選入口的靜態遍歷涵蓋全部 288 條指令，沒有普通順序或呼叫回傳位置缺口；此遍歷假設被呼叫函式會正常回傳。另保留 **3 個不透明間接呼叫及 4 個間接尾呼叫**，未以假實作替代。

## 尚未證明

前次已選取的 23,314 條指令與限定 DATA 掃描沒有找到指向這些窗口的參考；這不涵蓋私有排除區、所有間接來源或實機執行。新候選內部則有三個回呼位址參考、自身註冊與 `0x12A6E -> 0x16C72` 呼叫。

本輪尚未完成與正式來源的整合及原始位址實際連結，因此**正式覆蓋率維持 94.54%**，沒有將這 764 bytes 加入分子。ROM 身分／ABI、原硬體啟動、RAM、IRQ、OTA 相容性與實際功能仍未證明；未產生新 BIN，未執行目標／模擬器，未連線硬體或呼叫供應商服務。

## 重現

在專案根目錄執行；`LLVM_BIN` 指向已固定雜湊的 LLVM 工具目錄。本收據使用 Windows Android NDK 27.1 / Clang 18；需要先前 `secondary-message-v2` 診斷 ELF，以及規格固定的工具與輸入。以下是既有輸出的唯讀重播：

```sh
python3 experiments/tsl9-safe-gap-functions/build-v1.py --tool-dir "$LLVM_BIN" --replay experiments/tsl9-safe-gap-functions/build/native-v1
python3 experiments/tsl9-safe-gap-functions/audit-v1.py --tool-dir "$LLVM_BIN"
```

尚未建立 `native-v1` 時，第一行改用 `--trial native-v1`。Windows 可用 `py -3` 取代 `python3`。產物是供檢查的 ET_REL 物件，不能用來刷寫。
