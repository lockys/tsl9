# Candidate copy instruction interpreter

Host-only experiment. `interpreter.py` defaults to the 58 bytes (SHA-256 `558a82658cb54901945d4c2884f2e87e763f64d57c0cafa831307beb44ae0c36`) retained in `analysis/resident-copy-reference-2026-10-21/source/retained-source.json`. It decodes register and immediate fields for a limited RV32 instruction subset, not a general RISC-V emulator. Fetch is restricted to retained instruction boundaries and each site admits only its original instruction class; different register and immediate fields are permitted. Code is a separate immutable fetch region; RAM is a bounded byte array at `0x20001000` that cannot cross the 32-bit address-space limit; only word MMIO address `0x4002420c` exists. FENCE.I is an observed event, not a synchronization implementation. C.JR decodes its source register and clears target bit 0; it terminates only when that target equals the host sentinel `0xfffffffe`, otherwise it halts rather than fetching or silently returning. Unmapped access/fetch, unsupported encoding and exhausted instruction budget raise `Halt`, retaining earlier effects and never restoring MMIO automatically.

Control/ALU inventory (offsets relative to `0x20000332`): `+12` accepts only canonical `FENCE.I` and records an event; `+16/+18` decode C.BEQZ register and signed displacement; `+20` decodes C.LI; `+22` decodes C.BNEZ; `+32` decodes C.JR with the host-sentinel restriction above; `+34/+42` decode ADD registers with 32-bit wrap; `+46` decodes C.ADDI; `+52` decodes BNE registers and signed displacement; `+56` decodes C.J displacement. Branch targets remain subject to the retained-boundary fetch whitelist. This is a site-restricted subset, not a claim to support all valid encodings or arbitrary indirect execution.

Run `python experiments/tsl9-copy-instruction-interpreter/test_interpreter.py` from the repository root. Five cases compare RAM against the existing `scripts/rf_tx_copy_model.py`, including both overlap directions and identical addresses; the RF header writes are accounted for before invoking the interpreter. Hand-encoded tests exercise alternate registers and signed offsets for byte and word memory accesses, compressed immediates and a compressed branch. Negative tests cover unsupported encodings, transplanted RET, invalid return link, non-boundary fetch, bounded RAM addresses, missing byte, truncated fetch and instruction budget.

For the C differential, from the repository root in an MSVC developer command prompt (or after calling `VsDevCmd.bat`):

```bat
cl /nologo /W4 /I experiments\tsl9-resident-copy-reference\src /I experiments\tsl9-boot2580-uid-helper\src /I experiments\tsl9-boot2580-command-adapter\src experiments\tsl9-copy-instruction-interpreter\c_oracle.c experiments\tsl9-resident-copy-reference\src\reference_copy.c /Fe:%TEMP%\tsl9-copy-oracle.exe /Fo:%TEMP%\
set COPY_C_ORACLE=%TEMP%\tsl9-copy-oracle.exe
python experiments\tsl9-copy-instruction-interpreter\test_interpreter.py
```

The comparison is explicitly skipped without `COPY_C_ORACLE`. The deterministic corpus has 403 cases: 12 fixed cases, 119 combinations of lengths 0–16 and destination-minus-source offsets -16, -4, -1, 0, 1, 4, 16, and 272 separate read/write failures at every position for lengths 1–16 (one overlapping layout). RAM is 64 bytes with initial values 0–63; this is not exhaustive over data, addresses, lengths, or failure layouts. Each interpreter run has the default 1000-instruction budget; each C process has a 5-second timeout. Unknown-instruction mutation replaces the first halfword at each of the 18 instruction boundaries with 0000 and starts there; it tests whitelist rejection, not reachability from entry or every possible mutation. The C differential must be rerun after decoder changes; a previously passing MSVC run does not validate the current revision. No hardware is used. It compares ordered successful MMIO read/clear, fence, byte reads/writes and MMIO restore, plus RAM, MMIO and outcome. Cases cover overlap, zero length, null guards and deterministic read/write mapping failures after prior stores, including array boundaries. Failed accesses are not recorded as successful effects. C's `RP_RETURN` is intentionally excluded from the trace because interpreter RET terminates the host run; its return target is not compared.

HALT contracts differ: interpreter `Halt` retains completed effects, with PC advanced past a dispatched failing instruction (fetch and budget stops do not dispatch). Its instruction budget counts decoded instructions, including unsupported ones. C `BC_HALT` retains completed backend effects, reports `RP_PROVIDER_STOP` and the request PC on mapping failure, and requires a new activation rather than PC resumption. C's budget counts effect requests, not instructions; its unknown-value, transfer and other provider boundaries are not equated to interpreter faults. Neither model invents restoration after a stop. The differential only compares the explicitly modeled fully-known mapping-failure subset, not those different budget or unknown semantics.

## RF callsite composition

`test_rf_integration.py` composes modeled 0x64e0e pointer load, two header stores, helper call and 0x64e28 pointer reload with execution of the retained 58 helper bytes. The candidate carrier's fixed callsite windows, target calculation and helper source bytes are checked before comparison; selected callsite byte mutations are rejected. The callsite itself is **not executed**: its selected-path semantics are modeled, with nonzero source, mapped header and pointer word, and no interrupts or intervening external writes. The later 0x64e5c reload and the rest of RF_Tx are outside scope.

The 440 normal cases use deterministic bounded RAM seeds and compare the complete RAM, initial and reloaded pointer against `scripts/rf_tx_copy_model.py`, and independently check helper return value and ordered MMIO/byte effects. They include pointer self-overwrite, header-source alias, both overlap directions and zero length. Eight injected helper read/write faults check partial ordered effect counts, RAM and lack of invented MMIO restoration; the normal-completion Python model rejects missing bytes, so fault outcomes are **not** claimed as differential equivalence. Header and pointer-word mapping faults are not simulated. This is finite synthetic evidence, not proof of reachability or real exception behavior.

For mandatory MSVC validation, run `experiments\tsl9-copy-instruction-interpreter\run-msvc.cmd` in an MSVC developer prompt. It fails if the environment or compilation is missing and sets `COPY_C_ORACLE` itself, so the 403-case C differential cannot silently skip. It also runs the composition test. These are synthetic host comparisons under the candidate's decoded-instruction assumptions. They do not establish the original machine ISA, installed resident, hardware MMIO behavior or any device behavior. No product device is accessed.
