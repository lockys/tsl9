# CF96 selected seam anchors (offline)

This local diagnostic pins the 76,800-byte V4.1.60 reference BIN by SHA-256 and checks nine selected byte windows and eight decoded JAL destinations/registers. It is a starting ledger, not a complete control-flow, instruction-decoder, stack, or ABI analysis. The raw byte labels describe a manual interpretation; the code checks byte fingerprints, not those semantics. The JAL decoder is a separate bounded implementation for eight selected sites.

A halfword-aligned raw scan of every complete four-byte window in the pinned BIN, using linear base `0x8000`, finds one JAL encoding targeting `0xcf96`: `0x14dca`, rd `0`. The checker reports the observed hits; the test suite separately asserts the singleton result. This scan does not establish instruction boundaries or reachability and excludes compressed and indirect transfers; it cannot establish a complete caller set.

Assuming the recorded instruction boundaries and linear base `0x8000`, `0x14dca` encodes a tail jump to `0xcf96`; `0xcff8` encodes a call to `0xa00c`; `0xcff0` encodes a call and `0xd02c` a tail jump to `0x13c4e`. Additional calls are `0xcfdc` to `0xe220`, `0xd022` to `0xf9ec`, `0xd036` to `0xcc54`, and `0xd03a` to `0xbce0`. These are encoded edges, not claims that any callee returns or preserves registers. Matching bytes at a site does not show the site is reachable or identify all callers. Provider effects, preservation of `sp`, `s0`, `gp`, memory aliases and owner identity remain unknown. The checked frame byte sequences do not by themselves prove balanced frames on every path. The model is not an in-place C replacement.

Tests mutate each anchor and each JAL's destination or link register after deliberately disabling the whole-image identity check, and separately check identity and length. Such synthetic mutations test the guards, not instruction semantics independently.
