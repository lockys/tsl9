# 命令 176 與 208 跳表

`0x144F8..0x1452E` 的 54 bytes 由 C／C++ 中的架構指令編譯，包含兩筆直接呼叫與三筆分支重定位；在原位址連結後與既有映像逐 byte 相同。176 在 `s0[0]==1` 時呼叫 `0x13BA6`／`0x13C4E` 後回結尾，否則轉往遠端；208 以 `s0[0]` 為序號走五路跳表。它依賴原 dispatcher frame 與未確認的跳表／狀態契約，不能獨立呼叫或視為功能完整。

208 檔隔離建置重建兩個 76,800-byte 候選，內容與先前映像一致，失敗控制通過。3,128-byte 載體中 1,110 bytes 由來源編譯，2,018 bytes 仍為原始載體；實機 ROM、RAM、完整行為及燒錄相容性未驗證。
