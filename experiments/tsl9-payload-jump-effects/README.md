# 五條分派路徑的型別寫入

[English](readme.en.md)

在 `0xD0` 命令進入既有 `0x1A6A4` 五項相對跳轉表，且索引 0–4 正常落到各目的地時，五條路徑都以 `a0=s1` 呼叫 `0x13BA6`，依索引次序傳入的 `a1` 分別為 **0、3、3、4、3**。

被呼叫函式比較 `a0` 與兩個 halfword；若符合，將 `a1` 的低 byte 寫到第一個匹配項的 type，位置為 `0x2000C799` 或 `0x2000C79D`。兩項均不匹配時不寫。因此，在正常呼叫、指標有效及沒有干擾的條件下，這五次局部寫入均不會把所選 type 設為 2。這連接了新開放分派器與既有 type 2 前置條件分析；不排除其他呼叫、後續寫入或非同步變化，也不證明任何分支實際可達或功能已運作。

`python scripts/verify-payload-jump-effects.py --tool-dir <LLVM_BIN> --out <NEW_OUTPUT_DIR>` 重新驗證跳轉表與完整候選 BIN，並核對兩種建置的 15 條分支參數指令及 14 條 setter 指令；不執行韌體或硬體。
