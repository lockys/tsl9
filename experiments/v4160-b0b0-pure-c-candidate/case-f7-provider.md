# 表項 `0xf7` 與 resident 呼叫邊界

在前述 `0x155d0` 路徑確實進入表格、`a0=0xf7` 且讀取成功的條件下，索引 `0xf6` 的原始相對表項位於 `0x1aacc`，目標為 `0x162fe`。該處設定 `a0=1` 並呼叫 `0x9454`；在此輸入下，其固定指令再以 `a0=2` 呼叫 `0x9410`。上述片段沒有直接寫 a1。

`0x9410` 從 `0x2000becc` 讀 word：非零時在 `0x942a` 透過 `[0x40068]` 間接呼叫，呼叫時 `a0` 為該 word，`a1` 為進入此路徑的值，JALR 目標為讀得指標清除最低位。word 為零時跳過該呼叫，其他後續路徑未分析。

這只在指令與資料未被堆疊寫入等動作別名改變、存取成功且無中斷或其他並行干擾下成立。`case_f7_provider.py` 固定原 BIN SHA、88 bytes 局部編碼，計算表項和直接 JAL 目標，對 262,144 合成指標／a1 組合投影，並逐 byte 變造。壓縮呼叫編碼以固定 bytes 核對，沒有通用 CPU 解碼或執行。它**不證明此路徑可達、resident 的實際身分或 resident 會使用 a1**；不應將呼叫邊界上的差異當作已證實的功能差異。

執行 `python -I -B experiments/v4160-b0b0-pure-c-candidate/case_f7_provider.py`，亦支援 `-OB`。
