# `0xf7` 的零物件分支

在 `case-f7-provider.md` 的假設下，如果 `0x941e` 讀到的 `[0x2000becc]` 為零，`0x9422` 跳到 `0x943e`。由於此案例進入 `0x9410` 時 a0 為 2，該段算得 a0=2×6=12，載入 `[0x40070]` 並在 `0x9452` 尾跳，a1 未被該局部路徑直接改寫。若讀到非零，這項分析不適用；先前實驗只追到 `[0x40068]` 的呼叫邊界。

`case_f7_zero_provider.py` 核對原 BIN SHA、先前固定編碼與新增的 22-byte 尾段，對 196,608 個合成指標和 a1 組合檢查投影，逐 byte 變造尾段。一般與最佳化 Python 模式均通過。此為手寫的條件投影，假設所有存取成功、程式和狀態穩定，且堆疊寫入不干擾後續讀取；未模擬 CPU、provider 或硬體，也不證明該路徑可達或 provider 使用 a1。

另外，兩份本機 WCH 參考 carrier 的 `[0x40068]` 分別為 `0x431ba` 與 `0x43246`，不是 TSL9 已安裝 ROM 的證據。獨立靜態研究指出兩份候選的該函式本體在巢狀呼叫前不直接讀寫 a1，但巢狀 helper 未驗證，不能說整條呼叫不使用 a1。
