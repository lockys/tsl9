# `0x155d0`：進入 `0x1560e` 後的分派

接續 `callee-155d0-prefix.md`，假設已經抵達 `0x1560e`、a0 是 byte、存取成功、程式碼與資料不被並行更動。對 `x=(a0-1)&255`：

- `x=0..7`：將 a1 設為 0，準備並呼叫 `0x9124`；此驗證在呼叫前停止，不假設 callee 保留任何 caller-saved 暫存器。
- `x=253..255`：跳至 `0x1578c` 返回路徑，該分派段本身未改 a1；返回指令可另見前段驗證。
- `x=8..252`：計算表項位置並抵達 `0x15648`，此時尚未讀表，a1 未被此分派段直接改寫。間接目的地與後續行為不在此實驗範圍。

`callee_155d0_dispatch.py` 固定完整 BIN SHA-256 及 66-byte 指令序列，獨立解碼兩個 B-type 目標與一個 JAL；窮舉 256 個 a0、256 個合成 a1，並測每個指令 byte 變造。此為局部手寫語意投影，不是完整 CPU、全程可達或硬體證明；沒有證明透過任一表項後的替換安全。

執行：`python -I -B experiments/v4160-b0b0-pure-c-candidate/callee_155d0_dispatch.py`，亦可用 `-OB` 檢查最佳化模式。
