# `0x155d0` 前段的 a1 傳遞

這是 `0x167d4 → 0x155d0` 的條件性後續，不證明上游可達。`0x167d0` 以 LBU 提供 byte 大小的 a0；假定讀寫與堆疊存取成功、無中斷、無相關別名且原始呼叫正常完成。

- 讀得的狀態 byte bit 3 為 1，且 `((a0 + 6) & 255) > 2` 時，分支至 `0x1578c` 還原並返回 `0x167d8`，前段不寫 a1，因此原始與候選的 a1 差異仍在；後續迴圈或其他呼叫是否觀察它未證。
- 否則，若 `[gp+358]` 非零，清除該 byte 並尾跳 `0x18110`；在 `0x18112` 將 a1 設為 3，然後跳 `0x1802e`。這只證明該段至此的差異被覆寫。
- 否則進入 `0x1560e`，此實驗不追蹤。不可從以上兩條推出其餘路徑安全。

`callee_155d0_prefix.py` 驗證固定 BIN hash、128 bytes 的四個指令窗口與 `0x155f2` B-type 目標，條件性投影 256 個狀態 byte、256 個 a0 byte 與代表零／非零的兩個 gp flag，並直接檢測每個窗口 byte 的變造；普通及 `-O` 模式結果分別為 64,768 個直接返回、33,152 個尾跳、33,152 個未分析。這是固定編碼與手寫局部語意，不是通用解碼器、完整 CFG、硬體或 runtime；假設不能被視為已證明。

執行：`python -I -B experiments/v4160-b0b0-pure-c-candidate/callee_155d0_prefix.py`。
