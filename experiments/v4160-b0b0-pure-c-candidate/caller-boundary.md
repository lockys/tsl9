# `0xb0b0` 候選的直接呼叫邊界

就原始 `0x102e6 → 0xb0b0` 一條直接呼叫，在 store、各讀取及呼叫正常完成且無中斷／其他干擾的條件下，`0x102ea` 先重新載入 a5，因此不讀 leaf 返回的 a5。

- `[gp+309]` 非零：到 `0x10318`，`0x10322` 將 a1 設 5，再於 `0x10326` 呼叫 `0x8248`。
- `[gp+309]` 為零：先寫 1，呼叫 `0xd052`；該原始 leaf 只以 PC-relative 位址讀 byte 回 a0，不讀寫 a1/a5。回傳 byte 非 4 時亦到 `0x10318`、覆寫 a1 為 5；回傳 4 時則經 `0x10300`、`0x10314` 呼叫 `0x167a6`，a1 沿用進入 `0xb0b0` 前值，而本次編譯的候選則為 `0x2000c000`。

例如合成原始入口 a1=1 時，最後一個分支使兩者到 `0x167a6` 的 a1 分別為 1 和 `0x2000c000`。這不是證明該狀態可達。原始 `0x167a6` 前段不修改 a1，但迴圈命中時會在 `0x167d4` 呼叫 `0x155d0`；未分析該 callee 或未命中後續路徑，因此不能斷言差異是否被觀察。

`caller_boundary.py` 固定 BIN hash、124 個局部指令 bytes，獨立解碼五個 JAL 目標，將上述分段語意投影至全部 65,536 個 flag／返回 byte 組合，並逐 byte 變造局部窗口驗證拒絕。這並非逐指令 CPU 執行，分支語意仍依局部反組譯，且要求 no-alias、成功存取、正常返回；也不涵蓋三個 tail jump 的未知還原 ra、其他 caller、例外或實機。執行 `python -I -B experiments/v4160-b0b0-pure-c-candidate/caller_boundary.py`。
