# 新開放分派器的 type 2 呼叫

[English](readme.en.md)

新開放的程式區段另外包含四處直接傳入 type 2 並呼叫 `0x13BA6` 的位置：`0x144AA`、`0x147CA`、`0x147F8`、`0x1492C`。因此，先前五個跳轉表分支只傳 0／3／4 的結果不能推廣成整個分派器不會設定 type 2。

其中一條可明確描述的局部路徑是：正常到達 `0x14486` 且命令為 `0xC0`、保存的長度 `s2=1`、有效輸入首 byte 為 2 時，`0x144AA` 以 `a0=s1,a1=2` 呼叫 setter。若呼叫及記憶體有效、`s1` 與其中一個 unsigned halfword 相符，它會把第一個匹配項的 type 寫為 2；不匹配則不寫。

新開放區段的 `0x1416E` 另可在其前置守衛通過後，以 `a0=s1,a1=1` 呼叫 `0x13E0E`；若 handle 匹配，該函式把對應 flag 設為 1 並將 type 清為 0。若兩次呼叫依此順序成功、使用相同匹配項，且期間狀態不被其他流程改寫，便可得到先前分析所需的 `flag=1,type=2` 局部狀態。這是跨呼叫的條件式可能路徑，不證明實機接受這些輸入、操作已發生、後續查表可達或全域索引有界。不披露驗證資料。

`python scripts/verify-payload-type2-calls.py --tool-dir <LLVM_BIN> --out <NEW_OUTPUT_DIR>` 核對前置跳轉表、四處直接呼叫、局部 guard 和 flag setter 的原始指令，並重新建置候選 BIN；不執行韌體或硬體。
