# 0x81f8 full-graph replay: preliminary result

An offline, local-only replay used the previously successful residual-callbacks integration receipt and its nested table-extension receipt to rebuild their relocatable graphs, substituting the original `direct-successors.o` with a recompiled copy of its source with the 0x81f8 assembly owner removed, plus the separate C candidate from `graph_probe.py`. The candidate was compiled with `-fpic -Oz -mno-relax`, and its data alias was bound to `0x2000beea` in an additional linker script for the address witness only. All other input objects and linker scripts were reused from the earlier baseline build. No historical verifier or source was changed.

For both C11 and C++17, the candidate full address-witness link succeeded, and the 10 bytes at 0x81f8 were `17450020034525cf8280`. A local ELF32 section parser compared the section type, flags, address, size and contents of every SHF_ALLOC section between each witness and its corresponding baseline: 641 sections, zero differences. SHT_NOBITS contents were not compared. The complete ELF files were **not byte-identical**: candidate 320980 bytes versus baseline 320936 bytes. This experiment did not investigate the metadata difference; equality of allocated sections is not equality of full ELF metadata or relocation tables.

A first attempt compiled the candidate without `-Oz`; its section grew to 28 bytes and the address-witness linker rejected the changed size and overlap with the 0x8202 section. This is why the candidate-specific profile matters; the existing component receipt alone does not provide it.

These are exploratory results from pre-existing build objects and machine-local receipt paths, not a portable or independently reproducible clean rebuild. The replay script currently lives only in a temporary location and lacks input-hash checks, mutation tests and full graph/relocation audits. Before any source integration, implement a portable verifier that rebuilds all inputs from pinned sources, preserves and independently checks the link contracts, and tests negative cases. This is neither a complete firmware image nor evidence of runtime, actual ROM identity, device behavior or OTA readiness.
