# v4.1.60：模式寫入前的 `s0` 保留邊界

接續[模式 1 入參證據](v4160-app-event-slot18-mode-s1.zh-TW.md)。以原 APP 位址核對 `0x1074c` 保存入參後、`0x10776` 寫入前的四個直接呼叫：

| 呼叫位置 | 目的 | 原 APP 可確認的範圍 |
|---|---|---|
| `0x10754` | `0xd272` | 本地不改 `s0`，尾跳至 `[0x40048]` |
| `0x10758` | `0xb0fc` | 保存、暫用並從堆疊還原 `s0`；中間經 `[0x40048]`、`[0x40080]`，還原後尾跳至 `[0x4022c]`（取 slot 時仍使用原先建立的基址，須以它被保留為條件） |
| `0x1075e` | `0x820c` | 本地例程不寫 `s0`，沒有再呼叫別處；正常返回時保留 |
| `0x10762` | `0x10032` | 本地不改 `s0`，尾跳至 `[0x40048]` |

WCH V1.31 參考映像的三個 slot 依序為 `0x2000039c`、`0x43c4e`、`0x43932`。它們不是已驗證的實機綁定；也不能僅以 APP 的還原指令證明呼叫鏈保留堆疊內容。下一步按這三個候選入口核對暫存器與記憶體副作用，再決定是否有足夠證據建立條件式模式 1 寫入。

離線 Python `-O` 核對兩份映像 SHA-256、四個 JAL 目標、四段完整 APP 函式窗；另逐指令交叉核對 APP 並讀出候選 slot 值。沒有接觸設備，沒有修改原 BIN 或正式來源。
