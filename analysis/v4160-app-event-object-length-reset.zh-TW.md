# v4.1.60：事件物件長度的重置初值

接續[第 18 槽的更新來源](v4160-app-event-object-length-source.zh-TW.md)。先建立開機基準，再區分後續寫入：更新路徑的來源是 `s0`，但這不等於重置時長度也來自該來源。

- `0x186aa/0x186ae` 設定 `gp=0x20004000`。`0x186de..0x186f8` 的 word 清零迴圈從 `gp+128` 開始，直到 `0x2000c958`（不含），每次寫四個位元組。
- `0xc78c/0xc790` 所建立的物件基址為 `0x2000c290`。上述清零迴圈涵蓋第 18 槽的三個 word；第一個 word 的寫入直接清除 `+2` 長度 byte。因此在正常完成清零且尚未被後續流程改寫的狀態，初始長度為零。這不是第一個事件回呼所見值的保證，也不證明哪個後續寫入最早發生。
- 此結果組合的是 APP 時序與位址，不含任何實機啟動或間接提供者執行。`s0` 所指來源的建立與壽命仍待查；後續以正常 APP 內部路徑區分初始化、複製與消費，不把假設當成全域長度限制。

Python `-O` 通過原 BIN SHA-256、42 bytes 指令窗、GP／清零終點／物件位址及 8,758 筆清零位址投影；其中恰有三筆 word 寫入命中該槽。
