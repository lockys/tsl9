# v4.1.60：事件回呼的記錄讀取範圍

接續[索引寫入盤點](v4160-app-event-record-selector.zh-TW.md)與[回呼登記前的初始化](v4160-app-event-selector-early-fill.zh-TW.md)，本輪只查 `0x176f8` 的記錄分支。

- 第一個事件位元未設且第二個事件位元已設時，路徑在 `0x17780` 讀索引，於 `0x177a0` 呼叫複製提供者，請求從記錄表 `base + 7*index` 複製固定 7 bytes。這段沒有額外的索引比較或長度截斷；範圍論證依賴初始化及寫入方的索引不變量，以及表指標仍指向完整 256-byte 區域。
- 在已知的 `0..35` 索引範圍下，36 筆完整記錄涵蓋表內偏移 `[0,252)`，最後一筆只讀到偏移 251，不會讀入其後四個位元組。
- `0x177a2` 是複製返回後的另一次索引讀取，不是第一次讀取的範圍檢查。若第二次讀到的索引非零，且暫存記錄的第 2 個 byte 與 `0xfc` 相與為零，APP 會清零索引並要求重新讀取第 0 筆。兩次讀取不必相同；本輪不假設提供者保留記憶體，也不推定所有執行路徑都維持不變量。

Python `-O` 通過固定 APP SHA-256、86 bytes 指令、四個分支目的、36 筆記錄範圍與 331,776 組合成分支組合。未執行真正的複製函式或設備。下一步核對回呼對 7-byte 記錄後續欄位的使用，區分選擇、內容判斷與實際消費的欄位。
