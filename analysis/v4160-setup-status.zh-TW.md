# 設定函式返回 0 是哪一個結果？

`0x16e88` 的入口輪詢與後續設定分兩層。`0x16e96` 保存入口輪詢結果至 s1；若非零，跳過全部八次呼叫。若為零則依序呼叫 0x169dc 一次、0x16a30 三次、0x16b50 兩次、0x16a30 再兩次。這八個返回字均未控制 caller 的下一步；`0x16ef8` 取回 s1，而非最後一次呼叫的 a0。

第一個 helper 本身有確認步驟：`0x16a08` 以無號時間差 >5 走返回 1；否則讀狀態並在 `0x16a28` 比對其高三位與要求值，相符則返回 0，不符則重試。因此「helper 有檢查」和「caller 有傳回該檢查結果」不同。若 helper 逾時並正常返回 1，且此後七次呼叫正常返回、保存 s1、無其他干擾，外層最後仍返回 0。若卡在 helper，不能說後續設定已執行。

`python analysis/check_v4160_setup_status.py`：從原 APP 的 poll 返回點解碼 caller，callee 以注入的返回字代替；只追蹤返回值及呼叫序列，不模擬周邊、堆疊還原或所有暫存器。256 種二元組合、八個全 1 位元字、入口逾時及一處改成保留最後呼叫結果的負向控制均通過。不是實機成功率或所有 callee 都會返回的證明。
