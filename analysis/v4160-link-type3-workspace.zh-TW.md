# 類型 3：0x51f78 的輸出與返回狀態

接續[事件位址查找](v4160-link-address-types23.zh-TW.md)。在 V1.31 參考映像、已複製的 RAM helper 及 Xwchc 解碼假設下，以 P 表示 `0x51f78` 請求 `(48,83)` 後的傳回指標。三個輸入暫存器分別是上層的 16-byte 資料、本層呼叫者 `0x50040` 的 `SP+8`、`SP+12`；沒有一個是事件位址 A。

- P 為零：直接設狀態 19 並返回，沒有後續複製或釋放。P 非零：先要求清零 48 bytes，再將第一份 16 bytes 倒序複製到 `P+0..15`，第二份 3 bytes 倒序複製到 `P+29..31`。兩次和後續輸出都呼叫 `0x2000048a`，不是正向 copy。其迴圈先減來源指標再讀偏移 +1，目的位址逐 byte 遞增；來源與目的不重疊時得到相反順序。
- `0x63890(P,P+16,P+32)` 返回後，沒有分支檢查其結果：先保存狀態，將 `P+45..47` 倒序複製至第三參數（呼叫者 `SP+12..14`），再要求釋放 P，最後返回保存的狀態。`0x63890` 自身的正常返回路徑在 `0x638c2` 明設 0，並不轉傳內層服務的狀態。因此正常配置、呼叫及釋放且保存暫存器有效時，呼叫者才會進入三 byte 比較；返回零不是資料已由硬體正確產生的證明。
- 本體的五處直接 store 都保存暫存器到堆疊。若配置區及堆疊與事件分離，上列清零和三次倒序複製都不寫事件。不能擴大為整個呼叫無副作用：`0x63890` 另以 `[0x2000353c]` 指標加 80 做 word 讀改寫，呼叫 `0x63eda` 和條件映射的 RAM 服務 `0x200022be`。這些間接目的地與實機行為不在本次結論內。

重跑：`python -B analysis/check_v131_type3_workspace.py <V1.31-carrier.bin>`。工具固定 carrier SHA-256，核對 8 個轉移目標、倒序讀寫指令和返回狀態指令；一般及 `-O` 均通過。未連接設備或修改原始 BIN。
