# 任務 ID 7：配置失敗與派送入口

以 128 份初始化後 RAM 的 ID=7、task count=8 為輸入，從 V1.31 候選 resident 的 0x4e2ee 起算；建立獨立的呼叫框架，沒有假裝從初始化連續執行到訊息事件。沿用非空來源參數（呼叫端 SP+8）。每份 RAM 各跑三個分支。

|配置器回傳|派送時的 task count|執行至|
|---|---:|---|
|NULL|8|0x4e30e 分支到 0x4e358，還原堆疊與暫存器，帶著 a0=0 返回 0x4dffe。既沒有呼叫派送端，也沒有讀取 task count。|
|非空 M|8|要求把 24 bytes 複製到 M+8；假設複製正常返回，0x4e348 尾跳 0x43208(7,M)。0x43230 讀取當下的 count；7<8 且 7>2，抵達 0x4325a 的下一項檢查。|
|非空 M|7（對照）|同樣進入 0x43208，但 7>=7，在 0x43238 轉到 0x43242，沒有抵達 0x4325a。|

0x4e306/0x4e30a 的目標為 0x20000236，參數 32。配置結果為注入值，並未執行配置器；複製亦只核對三個參數並模擬正常返回，不檢驗內容。條件 Xwchc 解讀，成功存取及合成 MMIO，未接設備、不證排入佇列。兩種 Python 模式均得到 `PASS: 128 null returns without send; 128 (7,message) entries pass count 8; 128 count-7 controls stop at reject`。
