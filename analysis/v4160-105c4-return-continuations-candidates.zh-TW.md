# V4.1.60：0x105c4 三處正常返回後的選段候選

## 範圍與前提

本報告是靜態離線分析，不執行或模擬韌體。參考檔案
`firmware-downloads/legacy-options-2026-10-20/BINs/ID-2966-V4.1.60-decoded.bin`
長 76,800 bytes，SHA-256 為
`0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。
下文假設原始位址等於檔案 offset 加 `0x8000`，並假設表中起點為指令
邊界。雜湊識別所用 bytes，不證明原廠來源或實際載入方式。

既有六段選擇連結只比對 94 bytes，並非完整 CFG 或 ABI。若相應呼叫正常
返回到連結暫存器所指定的位置，`0x107d6`、`0x10846`、`0x10956` 分別
續接到 `0x107d8`、`0x10848`、`0x1095a`；這些續接均在原六段之外。實際
間接目標、可達性、callee 是否返回和所需暫存器／記憶體是否保持均未證明。
已有獨立的受限邊界重播見
`experiments/v4160-105c4-selected-return-boundaries/README.md`。

## 後繼的靜態判讀

- `0x107d8` 的 `05cd` 是以 `a0` 決定是否跳至 `0x10810`。零分支在
  `0x10810` 寫零至當時 `s0` 所指 byte，隨後跳至 `0x107ee` 的返回序列。
  非零分支讀取該 byte，加一並截為 8 位，再與 `12(sp)` 比較；分支另一側
  有 `0x820c` 呼叫及到 `0x1074c` 的尾跳。這些敘述均以各指令及存取成功
  執行為條件，並非宣稱呼叫或尾跳一定會發生。
- `0x10848` 的 `2a8411cd` 將返回值複製到 `s0`，再按 `a0` 分支至
  `0x10866` 或 `0x1084c`。非零側包含對 `0x820c` 和 `0x9124` 的呼叫；
  `0x10866` 將**當時的** `s0` 移回 `a0` 並恢復 frame。不能假設兩個
  外呼返回後 `s0` 或 stack 一定不變。
- `0x1095a` 的 `2dc1` 按 `a0` 分支至 `0x109bc` 或 `0x1095c`；後者在
  `0x10964` 依讀得的 byte 再分支。`0x1095c` 的 `97b7ff1f83c7c765`
  在假設的原址計算讀取地址 `0x2000bfb8`；相同指令移位後未必指向相同
  地址。此位址並非已證明的資料 owner 或實體記憶體配置。
