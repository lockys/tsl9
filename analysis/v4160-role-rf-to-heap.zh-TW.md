# 角色初始化：從第一次未知 RF 讀取接到配置返回

先前 `7e64ac2` 從快照另行呼叫配置器。本次沿 8 個繼承的 APP 初始化狀態，保留同一組暫存器及記憶體，從停點 `0x660e8` 重新執行該讀取，一直走到角色程式自己呼叫配置器；不預填空閒鏈，也不注入配置結果。

在 V1.31 參考映射、Xwchc 解讀、可返回的合成 RF/時鐘輸入下，經 `0x641b0 → 0x63eda → 0x6645c`，返回 `0x537b6`，再經 `0x53868` 與 `0x6dd1e`。從停點到進入配置器，沒有 CPU store 與游標 `0x20003190`、終點欄 `0x2000318c` 或兩個 8-byte 標頭 `0x200045ac` / `0x200048a4` 重疊；不只比較終態。第一個配置呼叫實參為 `300, 0x9001`，返回 `0x4ee10` 時 `a0=0x200048ac`。預期的 300-byte 範圍完全在 APP 池內且高於 `0x20003350..3351`；本段停止在返回點，尚未執行後續清零。

本機驗證 `check_v4160_role_rf_to_heap.py` 與 `check_v131_outer_count_rf.py` 的續跑模式，一般 Python 與 `-O` 各通過 8 個案例（兩組入口 SP/時鐘、兩種頁面比對、兩種排程結果）。只對指定的缺失 RF 暫存器及 RAM 樣本補入合成值，包括 `0x20002ec8` 的種子；不是從設備讀得。輪詢取可退出的值，不能據此認定每次都返回、每個 RF 分支皆不寫入這些位址，或設備安裝此版 ROM。
