# 模式寫入前：V1.31 候選 resident 的恢復條件

接續 [APP 的四個呼叫](v4160-mode-store-frontier.zh-TW.md)。候選 carrier SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`；只作離線參考，不推定裝置安裝此版。

- 表項 `0x4022c` 指向 `0x43932`。入口配置 32-byte frame，在 `sp+24` 保存入口 `s0`；`0x43992` 從返回當時的 `sp+24` 讀回。若各呼叫正常返回、SP 回到原框架且保存的四個 bytes 未變，讀回的是入口值。還需要後續指令完成及 `ra` 正確，才會返回 APP；恢復指令本身不是這些條件的證明。
- `0x43964` 依前一查找結果分支：零直接到 `0x4398c`，不執行 `0x6df1a`；非零才走算術分支。APP 在尾跳前令 `a2=1600`，候選入口以 `s1` 保留。**若中途 s1 仍是 1600**，令 `u` 為 `0x4396a` 讀出的無號半字，則 `0x43986` 呼叫前 `a1:a0 = 1600*u + 800`、`a3:a2 = 0:1600`。所有 65,536 種 `u` 下分子高字皆零，範圍 800..104856800。
- 這把 `0x6df1a` 的入口縮小至單一路徑前綴：`0x6df22` 的 a3 非零分支不取；`0x6df26` 的無號 a2<=a1 不取；`0x6df2c` 的 a2<65536 成立，下一段為 `0x6e0e2`。尚未以此證明 helper 最終回傳值、整條路徑不寫 stack 或實機執行。`0x4398a` 還有一次 word store，單從這段不能證其物件與框架的配置。

驗證：Python `-I -OB` 核對 carrier 雜湊、表項及七段機碼，窮舉半字範圍做參數算術檢查；另以 rasm2 靜態反組譯核對控制流。無設備連線或韌體修改。
