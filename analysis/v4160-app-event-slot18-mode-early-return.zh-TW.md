# v4.1.60：登記結果決定候選早退，不是模式值

接續[候選子呼叫](v4160-app-event-slot18-mode-resident-callees.zh-TW.md)。`0x10752` 把模式入參放入 `s0`，但 `0xb130` 的登記回傳值才是 `0xb148` 尾跳時的 `a0`：`0xb132` 將其低 byte 另存，續段沒有改寫 `a0`。候選 `0x43932` 把該值搬到 `s0`，再原樣傳入 `0x43728` 的第一個子呼叫。故模式值 1 本身不能決定候選早退。

在 WCH V1.31 綁定、Xwchc 解碼、正常返回與同一計數欄位未受其他寫入干擾的條件下，`0x43c4e` 的登記與 `0x43728` 的第一道比較都使用 `0x2000319d` 的計數。登記失敗時回傳 255，必通過「索引不小於計數」的早退條件；成功時回傳舊計數並將計數加一，因此不走第一道早退。這時若 `0x200031e0` 的指標為零，才走第二道早退；非零只代表越過檢查前綴，不代表一定執行回呼。

Python `-O` 重跑既有 byte/opcode 驗證，另核對五個指令窗、兩個 slot，並窮舉 131,072 組合成計數／容量／指標是否為零的組合：65,792 組走第一道早退、32,640 組走第二道、32,640 組越過前綴。組合數不是運行概率或實機可達性。下一步核對指標的候選初始化來源，再決定能否縮小仍未知的分支。未連接設備或修改原 BIN。
