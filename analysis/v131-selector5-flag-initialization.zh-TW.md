# Selector 5：0x20002f9c 是在初始化時清零，不是設為一

V1.31 參考段（VA 0x40000，SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`），不是裝置 ROM 證明。辨別寫入者時要同時解碼 SB 的來源暫存器與有效位址。

| PC | 原始 bytes | 效果 |
|---|---|---|
| 0x4da78 | b7370020 | a5 = 0x20003000 |
| 0x4da7c | 7971 | sp -= 48 |
| 0x4da7e | 0547 | a4 = 1 |
| 0x4da80 | 238e07f8 | U8[a5−100] = zero，即 0x20002f9c 清零 |
| 0x4da84 | b7370020 | a5 = 0x20003000 |
| 0x4da88 | 238ee730 | U8[a5+796] = a4，即 0x2000331c 設為一 |

重現：以 RISC-V 32 位、小端序反組譯參考檔 offset 0xda78 到 0xda8b（含），起始 PC 0x4da78。負向對照：只在記憶體副本把 0x4da80 的第三個 byte 從 07 改成 e7，位址不變而來源從 x0 變成 a4；這不是原始指令。

另對 APP、參考段及候選 RAM 複製前綴做有限掃描：從半字對齊的 `lui rd,0x20003` 起，追最多 24 條受支援的直線指令，檢查寫入寬度是否涵蓋目標 byte。三區命中數為 0 / 1 / 0；唯一命中為上述清零。一般與 Python -O 均通過。未追跨基本區塊、經資料表取得的指標或跨函式複製，故並非全體寫入者清單。

結論：若該初始化執行且之後沒有其他寫入，0x4d962 的 `flag == 1` 分支不成立。尚無任何事件把該旗標設為一的證據，也不能據此排除這種事件。
