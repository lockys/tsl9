# 三次註冊共用 0x8614，並非三份 PA 初始化函式

原 APP 以 0x8000 為基址。以三組 AUIPC/ADDI 實際計算入參：

|註冊呼叫 PC|回呼位址算式|回傳低 byte 寫入|
|---|---|---|
|0x8ed0|0x8ec8 − 4096 + 1868 = 0x8614|gp+157|
|0x8f8a|0x8f82 − 4096 + 1682 = 0x8614|gp+148|
|0x8fa0|0x8f98 − 4096 + 1660 = 0x8614|gp+152|

三者均透過 `[s0+128]` 呼叫；若 s0 維持 0x40000，對應參考 SDK 的 TMOS_ProcessEventRegister，不是當場執行回呼。後兩組另將半字 0xfffe 寫至 gp+150/+154（假設 s1 維持 -2）；這不是另外兩個回呼。

在回呼內，事件 0x8000 優先，其次是 8。其餘路徑才先比入參 task ID 與 gp+148，再比 gp+152，選 bank 0 或 1，兩者都不符則返回 0。事件 8 分支不做上述 ID 比對：0x8884 呼叫 `[0x401a4](taskID,0,0x19de0)`，參考 SDK 對應 GAPRole_PeripheralStartDevice；0x19de0 的前三個 word 為 0x8b90、0、0x85c8。這裡傳的是應用回呼表，而非 24-byte PA 描述元。

對 0x8614..0x888c（不含末址）按指令寬度線性核對：15 個間接呼叫，依 PC 遞增的表基址偏移（十進位）為 108,300,104,316,184,80,296,76,316,300,88,212,80,424,420；沒有 488（PA 表項 0x401e8）。其中 0x8864 的立即數 24 是 a2 的值，不是傳遞一塊 24-byte 物件的位址。結論只涵蓋這個 APP 函式本身且假定表基址保持；不包括被呼叫服務或之後執行的回呼，也不證任何註冊成功。
