# 原始複製來源資料視窗

[English](readme.en.md)

這輪核對原始 `0x12AD0..0x12B24` 呼叫端與完整軟體複製函式 `0x19BF0..0x19CA6`，合計 **82 條指令**，重建兩段唯讀 C/C++ 資料：

| 來源範圍（尾端不含） | 長度 | 複製呼叫 | 區域緩衝區 |
|---|---:|---|---|
| `0x19D08..0x19D66` | 94 bytes | `0x12AFC` | `SP+4..SP+98` |
| `0x19D68..0x19DD2` | 106 bytes | `0x12B1A` | `SP+4..SP+110` |

長度取自原始指令；沒有將相鄰位址當成資料長度，也沒有包含兩段之間的 2 bytes。呼叫端配置 128-byte 堆疊區，返回位址保存在 `SP+124`，兩個已選緩衝範圍均不與它重疊。這不是完整堆疊或中斷安全證明。

## 已驗證

- 重新執行 r2 靜態反組譯，82 條原始指令與既有證據及 BIN 位元組一致。
- 完整分類複製函式的 54 條指令，獨立核對 24 個記憶體操作與 10 個控制轉移；36-byte 區塊的最後一次讀取是來源遞增 36 後的 `-4`，即舊來源 `+32`。
- 在有效、不回繞的指標與可用堆疊等前提下，36-byte／4-byte／逐 byte 路徑的來源存取均受呼叫長度約束。此為靜態邊界推導，未執行韌體或模擬模型。
- C11、C++17 均產生 200-byte 唯讀資料，兩個實際 OBJECT；沒有函式、未解符號或重定位。兩種語言產物完全相同，且兩套 ELF 解析器的所有節區、位元組、符號及重定位記錄一致。
- 不與目前 5,721 個已整合 CODE/DATA owner 重疊，149 個既有 C/H 與 source manifest 均未變。
