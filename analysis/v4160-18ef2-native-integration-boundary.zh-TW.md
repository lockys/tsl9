# 0x18ef2 native 整合邊界（唯讀）

- **來源差異。** `experiments/v4160-18ef2-store-loop-evidence/README.md` 的正常入口靜態視窗先讀控制字，再對齊 A0；`src/native/nv/flash_native.c` 也將 `FN_READ` 放在 `FN_ALIGN0` 前。`experiments/v4160-18ef2-candidate/candidate.c` 則先做數值對齊，再透過 bus callback 讀取；它是事件模型，不是暫存器／fault prefix 重建。三者描述的正常事件流程包括 fresh 來源讀、目的寫及各次 polling；不能因此推定異常或非同步狀態相同。candidate README 限定 callback 正常返回、物件與函數指標有效；允許非資料競爭的重入改變後續 bus 取用。
- **具體 native 約束。** `src/native/nv/native_io.h` 的 `FN_FIXED_VALUE` 使用固定 `a0/a2/a3/a4/a5` register 變數與空的 `asm volatile`、`+r` 和 `memory` clobber；`FN_RET_PROGRAM` 的空 asm 以 `a1`–`a6` 為輸入、`a0` 為讀寫輸出。quarter 的 `FN_CALL_PROGRAM` 明寫 `jal ra, tsl9_flash_program_18ef2`，宣告 `a2`–`a6`、`ra` 與 memory clobber；quarter 另有 `csrc/csrs 0x800`。這些是編譯器介面，不是 C candidate 的內容，也不是逐指令等價保證。
- **ABI 與呼叫。** `src/native/nv/flash_native.h` 的 native program 接受 destination、source；host-test 模式另有 `fn_host *h`。candidate 的 `candidate_18ef2(const event_bus *bus, uint32_t a0, uint32_t a1)` 是另一個三參數 callback API，不能直接替代 native 符號或假設相同暫存器結果。`src/native/nv/nv_write_callback.c` 的 callback 入口有 destination、unused A1、source，使用一般 C 呼叫 program；`src/native/nv/nv_write_frame_contract.c` 則用固定 A2／A1 暫存器變數表示重讀值及呼叫參數，並以 inline asm 發出 JAL；這不單獨保證產出特定的搬移指令。`experiments/v4160-9c0a-tail-callee-evidence/README.md` 記錄另一 caller 在 `0x9c34` 前從 `12(sp)` 重讀 A1；靜態呼叫點不證明實際可達或入參。
- **owner 與 volatile。** `nv_write_callback.c` 直接 `#include "flash_native.c"`，而該檔本身定義多個外部函數；若又把 `flash_native.c` 作獨立編譯單元或保留原 carrier owner，須處理重複定義、區段及呼叫 relocation 的歸屬，不能只替換單一呼叫。`FN_ONLY` 條件只控制本次預處理所產生的定義（`flash_native.c`）；原 carrier 的別名與內部角色另見 `analysis/v4160-flash-entry-order-2026-10-22/ABI-review/README.md`。native 的 `FN_READ/FN_WRITE` 是 volatile 32-bit 存取，空 asm 的 memory clobber 是編譯器約束；它們不證明硬體成功、原子性、同步、位址有效或中斷等價。candidate callback 則不是直接 volatile MMIO 存取。
- **歷史證據的界線。** `analysis/v4160-flash-entry-order-2026-10-22/implementation/README.md` 記錄歷史 C 與 C++ 的 component ELF 同一 SHA-256 `aeccc19da9c5764a386333dd26898429c35bf0ff40efb08c8f8417b11820339d`：比較對象是兩個 component ELF，不是直接與 BIN 比對。該歷史 ABI 審查記錄 program 同為 100 bytes／38 指令，但首次 RMW 使用 A2 而非原始 A5，對齊指令邊界亦不同；不可由尺寸或兩個 ELF 的 hash 相同推論等於原 BIN。原 BIN 視窗的獨立 hash 與範圍另見 store-loop 證據 README，不能混作同一對象。
