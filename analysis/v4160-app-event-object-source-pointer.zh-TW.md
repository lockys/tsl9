# v4.1.60：事件物件更新的來源指標

接續[第 18 槽更新](v4160-app-event-object-length-source.zh-TW.md)與[重置初值](v4160-app-event-object-length-reset.zh-TW.md)，本輪分開核對入口保存、模式讀取及兩個區域之間的參數交接；不假定完整分派樹的所有路徑都保留相同狀態。

- `0x14d34` 把分派入口的 `a0` 存到 `s0`。下一個呼叫 `0x829e` 是讀取固定 RAM 位址 `0x2000bfb5` 的單位元組 getter；這三條指令不寫 `s0`，也不從 `s0` 指向的記錄取得長度。
- 第 18 槽更新分支 `0x152ba` 使用當時的 `s0` 作為來源指標，`0x152c4` 在間接複製正常返回後將當時的 `s0` 交給解碼器。兩個位置都不是現場配置來源，也沒有把固定的槽地址當成來源。如果中間路徑及提供者保留 `s0`，這個指標就是入口傳入的 `a0`；本輪不將該條件升格為全域 ABI 保證。
- 因此，重置初值、槽更新與入口記錄的形成是三件事：本輪核對前兩段的指標接法，未證入口記錄如何填入第三個位元組或其值域。

Python `-O` 通過原 APP SHA-256、44 bytes 指令、三組暫存器移動、三個靜態跳轉目標及模式位址計算。未執行設備。下一步從正常 APP 路徑找一條已知的記錄建立點，核對其欄位初始化，而非先假定所有來源共用同一格式。
