# 六次角色登記中的另一張表

接續[角色 ID 推導](v4160-role-registration-ledger.zh-TW.md)。在 V1.31 參考檔 `[0x6dd16,0x6dd86)` 的 112 bytes，前置呼叫是 `0x61b1c`；六次 `0x43c4e` 的返回值各自直接交給 `0x4da70 / 0x46570 / 0x4a7d6 / 0x50412 / 0x6c300 / 0x4d172`，最後尾跳 `0x6d572`。呼叫者本身沒有另一筆角色 ID 寫入。

第四段 `0x50412` 和第六段 `0x4d172` 都尾跳 `0x4efe2`，分別傳入 `0x4f516`、`0x4cff6`。此處是另一張固定表：從 `0x20003358` 起掃描 12 個 word，找到第一個零便寫入傳入值並返回 0；全滿不寫並返回 19。它不執行傳入函式，不呼叫 `0x43c4e`，也不碰角色計數 `0x2000319d` 或共用 ID `0x200035f5`。不要把存入函式指標算成新增一筆角色登記。

[有限指令檢查器](check_v131_registration_side_table.py) 接受 V1.31 carrier 路徑，固定 SHA-256，從該檔取指。兩個實際參數各跑 4096 種空位配置，逐例比對寫入位址、值和返回碼；一般及 `-O` 各通過 8192 例。非零表項用 1 代表，因分支只比較零；未模擬中斷、存取失敗或實機。第四段較早還呼叫 `0x50368 / 0x4d9ec`，第六段較早還呼叫 `0x493f2 / 0x4b35e / 0x4b33c`。這次排除的是兩段共用的尾函式，而非全部巢狀副作用；ID 11 仍為有條件推導。
