# 角色註冊返回後，到首次要求讀取記錄 2 之前

問題是：配置失敗回呼槽 `cfg+52` 的四個 bytes `[0x20003220,0x20003224)` 會不會在這兩段被改寫？在 V1.31 參考映像、名義基址暫存器、Xwchc 解碼、填值只寫指定範圍且各呼叫正常返回的條件下，**兩段內所列寫入均不重疊該槽**。

|區段|直接寫入目的（低 16 位；高 16 位均為 0x2000）|首次讀取呼叫|
|---|---|---|
|`0x6d5b6..0x6d636`，含 `0x4600e`|byte：35f5、35f4、35aa、35d0、35a9、3608、33ae；word：2ff0、35cc、2ff4。另有兩次 16-byte 清零，分別從 35d4、35e4 開始。|`0x6d636 → 0x440c2`|
|`0x6aeb6..0x6aeea`，含 `0x6ae4e`|byte：2fb0、35f4、3612、35ab、35f4（兩個位置寫同址）。其中 `0x6aeba` 按 Xwchc 解為 byte store。|`0x6aeea → 0x440c2`|

核對基準：參考段 SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`；一般及 `-O` 均通過 15 個 store 位置、2 個填值範圍及兩個讀取呼叫目標的檢查。表中是不同分支的聯集，不是單次執行紀錄。這只縮小[失敗回呼是否可能被叫用](v4160-pre774-read-alloc-callback.zh-TW.md)的未知區間；不涵蓋較早的註冊、非同步寫入或實機 ROM 身分，不足以斷定首次配置時該槽為零。
