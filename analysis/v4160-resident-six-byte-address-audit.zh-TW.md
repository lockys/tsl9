# v4.1.60：resident 六位元組欄位的地址交叉核對

接續[讀取點分析](v4160-resident-six-byte-readers.zh-TW.md)。沿用同一對 SHA-256 固定的 V1.30／V1.31 參考映像及 `0x40000` 映射，只分析已存在的離線樣本。

## 候選如何縮小

每兩個位元組取一個 32 位元解碼候選，找標準 load 或 ADDI，其有號 12 位元立即數若配上 `0x20003000`，會落入狀態 `+244..255`。這是過濾條件，不是以每個命中為有效指令；對所有命中再用相鄰指令確認來源。兩版各三個命中，六個都不是已證實的讀者：

| 參考版 | 兩個形成複製目的地址的 ADDI | 非目標位址的命中 |
|---|---|---|
| V1.30 | `0x67e74`、`0x67e94` → `0x2000335c`、`0x20003362` | `0x63b8a` 是 `(a1 << 7) + 0x364`，接著儲存該算術結果 |
| V1.31 | `0x67fda`、`0x67ffa` → `0x200034ac`、`0x200034b2` | `0x517f2` 使用 `lui a4,0x6e`，產生 `0x6e4b0` 的跳表基址 |

兩版均經 `AUIPC/JALR` 到 `0x20000332`，提供 `a0=目的地址, a1=s0, a2=6`。相鄰第三分支使用 `+256`，不在搜尋範圍。V1.31 原始位元組搜尋所碰到的 `b7 34 00 20` 也有明確非指標的例子：`0x59ef8` 是 `lui s1,0x20003`，不是指向 `0x200034b7` 的資料字。

## 整塊傳遞另外確認為填零邊界

V1.30 `0x534f2`、V1.31 `0x53650` 的呼叫傳遞同一結構基址及 `a1=0, a2=296` 至 `0x2000039c`。若候選 fill 例程成功執行，半開區間分別為 `[0x20003268,0x20003390)` 與 `[0x200033b8,0x200034e0)`，皆包含 `+244..255`。這不是從該欄位取值的證據，也不證明與其他寫入的實際執行順序。

Python `-O` 核對樣本雜湊、每版三個過濾命中、三個複製地址與呼叫參數、fill 參數與呼叫目標，兩版均通過；相鄰指令由靜態反組譯交叉確認。此結果不涵蓋以不同基址或偏移實作的讀取、壓縮／廠商指令、寬讀取從區間外起始，或間接取得的指標。未證實啟動比較器之外的讀者，未接設備或修改原 BIN／正式來源。
