# v4.1.60：追查 resident 產生的兩組六位元組由誰讀取

本輪以實際基址，而非 `+248` 或 `+252` 的位移相同來判定交叉參照。樣本為 WCH V1.30（SHA-256 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`）與 V1.31（`133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`），均按 `0x40000` 映射；不是裝置 resident 的身份證明。

- **已確認的內部讀取：** 啟動產生器的狀態基址是 V1.30 `0x20003268`、V1.31 `0x200033b8`。對應比較點 V1.30 `0x537da`、V1.31 `0x53938` 以 `lh` 讀 `s0+252` 和 `s0+254`，再與 `s0+234` 和 `s0+236` 的值分別遮罩、比較。這兩個讀取有前置分支條件，不是每次必經。
- **同位移不等於同欄位：** V1.30 `0x59d9e`、V1.31 `0x59efc` 把上述全域基址放在 `a4`，讀取全域 `+220/+216`，寫到另一個參數所指向的物件 `s0+252/+248`。V1.31 `0x59e78→0x59e7c` 顯示這個 `s0` 取自另一個呼叫的回傳值。後續在 `0x5c32a` / `0x5c436` 找到相同物件相對位移的讀取，但僅憑這些位移或指令不能把它們算成全域產生欄位的讀者，也未排除執行期別名。
- **另一個寫入邊界，不是讀者：** V1.31 `0x67fd2` / `0x67ff2` 的分支將 `a0` 分別設為 `0x200034ac` / `0x200034b2`，即全域 `+244/+250`，傳 `a1=s0, a2=6` 至 `0x20000332`；另一分支傳 `0x200034b8`，即 `+256`。依候選 copy 的參數方向，前兩者是目的地址，不能當成消費者。這裡只核對呼叫邊界，未執行 resident。

驗證：兩份樣本的 SHA-256 均通過；`rasm2` 反組譯與獨立 Python `-O` 欄位檢查核對兩版比較器的 `lh`、全域至物件的 `lw/sw`，及 V1.31 三個目的地址、共同呼叫目標和兩個物件讀取窗。本輪未證實啟動比較器以外的全域讀者；下一步以絕對地址及指標傳遞查找讀取，不能因未找到直接 load 就排除間接讀取。未連設備或修改原 BIN／正式來源。
