# v4.1.60：resident 設定六位元組的 APP 端來源

接續[比較欄位的來源](v4160-resident-six-byte-source.zh-TW.md)，以 SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667` 固定原 APP。`0x19aac` 設 `a0=sp+8`，`0x19ab4` 執行 JAL x1 至 `0x18f56`，link `0x19ab8`。兩個指令窗用 `rasm2` 靜態反組譯，並獨立驗證 load/store 欄位及 JAL 目標。

`0x18f5a` 從 `0x1ffff7e8` 讀取 32 位元字，依低至高位寫入目的 +0..3；之後 `0x18f78` 從 `0x1ffff7ec` 讀取另一個 32 位元字，只依序使用低兩個 bytes 寫入 +4、+5。第二次讀取發生在前四次寫入之後。假定兩次讀取及目的寫入成功、按原 link 返回，後續六次 byte copy 會將該暫存內容移到設定 +24..29。

Python `-O` 的檢查通過兩個指令窗、兩個來源位址、六次寫入與呼叫目標，另以三組合成輸入核對位元組順序（例如 `0x44332211` 和 `0x88776655` 產生 `11 22 33 44 55 66`）。這是 APP 資料流，不證明兩個位址的實機內容、讀取可用性或後續欄位的用途。未接設備、未變更原 BIN 或正式來源。resident 自行生成的 +244..255 欄位之外部讀者仍待獨立查證。
