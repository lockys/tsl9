# 原始更新狀態與控制器程式

[English](readme.en.md) · [C/C++](../../src/native/receive/ota_runtime.c) · [原始證據](evidence.json) · [驗證摘要](summary.json)

新增十個完整原始函式1052B／363指令，C11／C++17原址編碼相符。接上92BA、9C0A、13E0E三個舊入口，並展開六個真實回覆／回呼依賴，UND由74變77。完整14056分派仍未實作；本輪不輸出其驗證比對值，不改既有識別檢查。

| 範圍 | 已確認的靜態行為 |
| --- | --- |
| 92BA–9334 | 保留原始ROM讀取tuple與14-byte識別資料比較；沒有讀取或保存實體裝置值。 |
| 9C0A–9C4A | 32B frame，原始CSR0x800清除／設定0x88及控制器呼叫；不是先保存、再還原先前CSR狀態。 |
| 9C4A–9E5C | 完整48B frame，含第一個RET後的U/S/W/R/E分支、狀態／長度／識別檢查與讀回比對。 |
| 13E0E–13E98 | 0x2000C794起的原始記錄與0xFFFE空值處理；完整保留RET後路徑。 |
| 18E90–18F56 | 五個完整控制器函式，保留0x40022000基底、鎖定及所有輪詢／word寫入路徑。 |

W要求GP+169更新狀態非0、長度1026B；兩byte頁號後有1024B內容。原始位址為 `(0x20000+4+page)<<10`，並要求 `uint32(destination−0x08001000)<=0x6F00`。純靜態算術得到第一頁0x08001000、最後頁起點0x08007C00、寫入末端不含0x08008000。每頁四次256B操作後，逐word比較全部1024B；不符會走原始255回覆值路徑。

這個寫入範圍不能直接等同目前APP分析VMA0x8000；BOOT／APP角色、實體別名與bootloader接收端仍未證。本機沒有檔名明列BOOT的對照BIN，未據此宣稱映像相容。R要求16B，E要求15B且首byte為0，並保留14-byte識別檢查。S/U使用原始低8位長度運算，沒有改成較寬鬆或較嚴格條件。

E分支保留零長度、命令值69的回覆形態與排程參數200/400（單位未證）。字母E本身不能證明更新失敗或成功；重啟、版本、讀回與實體功能仍需獨立證據。所有程式均未執行，未對硬體發送封包、解鎖、寫入或讀取識別值。

主元件19708B code＋714B data，共20422B經原生原位址配置後逐byte等於官方ID2966 BIN。來源111個C/H檔、84個code單元；170項比較／340個物件通過，舊110檔與997筆產物記錄保持不變。1128直接轉移中1054有實作／74只具參照，另有3個僅以位址傳遞的提供者，故UND共77；不是完整CFG或實機證明。
