# 查找索引與序列來源追查

[English](readme.en.md)

本輪只做離線證據追查，沒有新增韌體程式或資料。覆蓋率維持 **88.09%**，未解參照仍為27個。

## 已確認的局部行為

- 核對目前21,938條指令、64,544 bytes已重建程式碼，並重新擷取17個視窗、174條原始指令。
- `GP+176` 有兩個已選程式範圍內的直接寫入者：`0xA0FA`、`0xA344`。其順序執行路徑都先加1，再AND3；這兩條局部路徑的寫入值為0～3，沒有已選直接轉移繞過遮罩進入寫入尾端。間接入口與非同步情況仍未證明。
- `0xA146..0xA158` 自記憶體讀取unsigned byte索引，乘2後從 `0x1AB48` 讀半字，讀取點本身沒有AND3。
- 原始GP設定與對齊word清零迴圈涵蓋此byte；在該啟動路徑執行完成後，索引為0。這仍未證明安裝中的啟動／ROM後續行為。
- `0xA37C..0xA38E` 把 `GP+172`、填充值0、長度5傳至槽位 `0x40048`；若該安裝槽位遵循快取官方SDK的預設 `tmos_memset` 契約，清除範圍會包含 `GP+176`。SDK版本與公式有來源雜湊，**尚未識別硬體實際安裝的ROM或ABI**。
- 另有5處把 `GP+128` 作為參數傳遞，後續不透明ROM呼叫的寫入範圍尚未閉合。185筆GP-relative ADDI的清單已保留；它們不全是寫入或外逸。

因此，目前不能把「已知兩個直接寫入者會產生四態」提升成「所有執行路徑的索引一定為0～3」。僅由unsigned byte推得的語法範圍是512 bytes，會超出本BIN尾端；這不代表實機發生越界。**本輪未將 `0x1AB48` 擅自宣告為四項資料表。**

## 校正序列消費者

`0xEFE0/0xEFE4` 與 `0xEE8C/0xEE90` 的回呼位址均為 **`0xEE30`**。`0xEF6C..0xEF76` 則只有三條指令，讀取並返回 `0x2000BF8C` 的一個byte。

`0xEE30` 從 `0x2000BF84` 讀取16-bit索引、從 `0x2000BF86` 讀取上限，只有索引小於上限才從 `0x2000BF88` 所存指標讀取半字。在指定來源與上限保持對應的前提下：

| 原始來源 | 設定上限 | 條件式讀取範圍（尾端不含） |
|---|---:|---|
| `0x1A430` |17 | `0x1A430..0x1A452`，34 bytes |
| `0x1A454` |17 | `0x1A454..0x1A476`，34 bytes |
| `0x1A478` |53 | `0x1A478..0x1A4E2`，106 bytes |

這些不是原始宣告長度，也沒有依相鄰位址猜成36／36／108 bytes。全部寫入者、指標與上限的非同步關係，以及實體功能名稱仍待確認，因此尚未提供這三段DATA。
