# 狀態寫入與回呼參數重建

[English](readme.en.md) · [C/C++](../../src/native/receive/state_output_dependencies.c) · [證據](evidence.json) · [驗證摘要](summary.json)

新增三個完整原始函式，80B／24 指令，C11／C++17 原碼相符。接通 `B6EA／D05C／10816`，未解析依賴由79降至76，沒有新增依賴。主元件15734B code＋674B data，經原生連結器配置後全部16408B逐 byte 與官方 ID2966 BIN 相符。

| 原始位址（結尾不含） | 已確認的靜態行為 |
| --- | --- |
| B6EA–B6F4 | 將 A0 低8位寫入 `0x2000BF0C`，返回。 |
| D05C–D07C | 依序寫入 `0x2000BF38..3B`：1、A0低8位、負A2低8位、A1低8位；保留32位無號減法。 |
| 10816–1083C | A0為0時改成1，A2取A0×1000低32位，將 `0x2000BFB8` 設1；A1/A3為0、A0為既有回呼 `1061C`，尾呼叫 `9124`。 |

既有 `1061C–10630` 清除同一個 `0x2000BFB8` byte，並尾呼叫 `90B0`；這是靜態連結，尚未觀察回呼執行。單位、欄位用途、RAM實體所有權與同步語意均未證，不推定為特定車輛功能。

原始碼共106個C/H檔，79個原生code單元；160項來源比較／320個物件，舊105檔與既有937筆產物記錄保持不變。完整驗證包含919個直接轉移、263個暫存器間接轉移、317個潛在返回位置；尚有76個真正未實作提供者。診斷ELF入口0、PT_LOAD=0，不是可燒錄BIN。

流程檢查初版 `verify-flow-v11.py` 複製時誤改一項壓縮JALR辨識常數，少計68個間接轉移／返回位置；該次輸出保留但不採用。正式證據使用修正的 `verify-flow-v12.py` 與 `state-output-dependencies-flow-v2`，辨識常數與原版一致。

值得新增的候選功能：離線列出狀態byte與回呼參數，明示未知單位，方便比較版本；目前僅提案，未加入硬體行為。下一步追查其餘回呼提供者與原機ROM／RAM契約。全程未執行韌體、未連硬體／網路、未燒錄。歷史隱私問題尚未清理，因此沒有commit／push。
