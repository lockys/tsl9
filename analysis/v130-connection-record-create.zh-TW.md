# V1.30 resident：建立連線紀錄時的編號指派

唯讀核對 V1.30 resident 參考映像（基址 `0x40000`、SHA-256 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`）。本文與[既有紀錄查找](v130-connection-record-lookup.zh-TW.md)交叉核對。

- `0x57804` 這條建立路徑在取得非空紀錄空間後，從 `0x20003000 + 616 + 156 = 0x20003304` 讀取串列頭，與查找函式使用相同的頭指標。
- 空串列分支在 `0x5786e` 選編號 `1`，於 `0x57870` 寫入新紀錄 `+8`，再更新頭及尾指標。
- 非空串列從 `1` 開始。`0x57846` 讀取各紀錄 `+8` 的無號半字；遇到相同編號，`0x578aa` 起將候選加一，並在候選低 16 位的符號位為零時從頭重掃。走到串列尾仍無重複時，`0x57850` 將候選寫入新紀錄 `+8`。重試到 `0x8000` 則轉入不插入新紀錄的路徑。

對一條可正常遍歷、搜尋期間不變的串列，這等同於選擇 `1` 至 `0x7fff` 中最小的未使用值。已重算映像雜湊、核對上述控制路徑的原始編碼，並依 Xwchc 欄位驗證一讀兩寫的寬度、暫存器和偏移。不代表每次 BOOT 都從空串列開始，也未確認實機 resident 版本或實際編號。
