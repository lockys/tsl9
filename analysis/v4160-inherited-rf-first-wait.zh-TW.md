# RF 初始化：第一個等待點不由狀態位元組決定

範圍：v4.1.60 APP 搭配 V1.31 參考映像，不連設備。從上一階段最後一組合成入口（SP 0x2000ffd0、clock 0x5555、頁面相等、變更 ID 的對照組）取七種遮罩路徑，各自沿用返回 0x641fc 的暫存器與 RAM，不重設 0x2000351b。

0x64246 呼叫 0x6645c。0x664c2 讀的是另一個 32 位字 0x20003588；此入口的四個位元組都沒有已知值。0x664d0 與 0x12345678 比較。相等時 0x67190 清除此字，跳到 0x665b0，略過第一個等待呼叫。不相等時 0x664f8/0x664fc 呼叫 0x20002df2。它先寫 6000 到計時暫存器，後續會重新讀它，不是固定執行 6000 次。

本次在後一分支選取第一次狀態讀值的 bit 26 為零。計時讀值 [0] 或 [1,1,0] 都返回 0x66500；[1,1,1] 在第三次仍回到 0x20002e0a，只證明這段前綴還沒有返回。七組遮罩各跑四種後續，得到 7 次相等跳轉、14 次等待返回、7 段仍在等待。一般 Python 與 -O 均通過。原有狀態 0 或 1 在這些前綴保持不變。

不推定裝置上的參考 ROM、標記值、周邊讀值或等待終止。尚未連到後續的 80-byte 配置請求。下一個比較點是 0x665b0：區分直接跳到這裡與經額外周邊操作才抵達的狀態。
