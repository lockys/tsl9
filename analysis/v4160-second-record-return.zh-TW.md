# 第二筆配置返回後，何時建立 255 筆記錄？

從第一筆區塊已經清零的狀態繼續。維持該次配置後的堆積、暫存器和記憶體；不另造 header，不注入第二次返回指標。八個狀態各用四個第一筆計數（1、3、4、255）以及兩個相鄰 byte 對照。這個 byte 並非實機讀值。

| 相鄰 byte | `0x4c05` 請求 | 實際執行參考指令後的結果 |
|---|---:|---|
| 251 | 0 bytes | 32 次返回空指標。`0x20002f98` 收到零；接著依序清 `0x20002fa0` 和 `0x20002fa1`，沒有記錄寫入。 |
| 250 | 4080 bytes | 32 次取得與第一區塊不重疊、標記為 `0x4c05` 的區塊。先存指標、逐 byte 清滿 4080 bytes，再將 255 筆 16-byte 記錄各自的偏移 +9 設為 `0xff`。 |

兩支都走到 `0x4efd8`，返回位址是 `0x4db88`。核對了配置返回之後所有讀寫的順序、地址和寬度，沒有把抵達下一函式當成它已成功返回。一般 Python 與 `-O` 均通過這 64 條離線路徑及既有回歸。模型依賴 V1.31 候選、Xwchc 和合成周邊；不是裝置執行證明。
