# v4.1.60 佇列 producer 的高位負向控制

針對 `0x12bc8` 的 C 候選，本機建立離線驗證包：呼叫者提供原始 BIN，先驗證 SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`，再用受限 RV32IMC 解譯器與 host C11/C++17 執行差分。原始影像只讀，不包含於驗證包。

此前負向控制只翻轉參數低位，且任何 callback 差異都可能被當成成功。現分別把候選傳給 provider 的完整長度、完整 tag 的 bit 16 翻轉；測試明確要求相應參數恰好改變該 bit，其他 callback 欄位及呼叫時佇列快照不變。C11 與 C++17 在普通和 `-O` 執行時均檢出兩個變造；各建置另有 4,752 筆正常差分案例通過。測試建置使用暫存目錄。

provider 仍是合成替身，不按傳入長度實際複製，未證真實 provider、實機、ABI、返回暫存器、併發或存取原子性。C 以兩個 byte 表示原版 halfword 寫入。驗證包從本機既有解譯器改編，不是第二套獨立 CPU；來源與散布權仍待釐清，因而此批只發布分析，不發布該驗證包。
