# Selector 5：保存的指標如何交給下一層

對象是 SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22` 的 V1.31 參考區段，不是裝置 ROM。以下採 Xwchc 解讀，假設合法且互不重疊的堆疊、訊息與標頭。

以解析成功、selector 5、非空保存指標 P 進入 `0x4e1c2`。外層長度不足 4 時走 `0x4e22c`，不讀 P。否則 `0x4debc` 依偏移 0、1、3、2 的順序讀四個 byte，將前兩個 byte 和一個小端 16 位元長度 n 分別寫到 sp+12、+13、+14。這不是整段 payload 複製。

驗證至第一個分歧點：n > 23 停在 `0x4e1f0`；n ≤ 23 但外層長度不等於 n+4 停在 `0x4e20c`。本檢查不判定這兩條分支的最終返回。長度相符時，`0x4e214` 重讀 sp+28；第三個參數是此次讀值加 4，而非先前暫存的 P。第一個 byte 的 bit 0 為 0 時呼叫 `0x4df54`，為 1 時呼叫 `0x4e084`；兩者的另兩個參數為識別值與 sp+12。

離線有限解碼測試：256 個首 byte × 7 個內長 × 5 個外長 = 8960 個案例，另在重讀前改變保存欄位的兩個對照均改變第三參數。一般 Python 與 `-O` 各通過。未執行被呼叫函式；不推出整個處理過程都不改旗標，也不保證實機可達。
