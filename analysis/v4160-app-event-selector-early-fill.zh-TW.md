# v4.1.60：登記事件回呼前的索引清零

接續[初始化順序](v4160-app-event-selector-init-order.zh-TW.md)和[清理呼叫鏈](v4160-app-event-selector-release.zh-TW.md)，本輪驗證第一個 `[0x40048]` 不僅收到清零參數：在 V1.31 參考映像的綁定與正常執行假設下，它確實會逐 byte 寫零，且不派發 handler。

- APP `0x17c0a` 呼叫 `[0x40048]`，入參 `(gp+376, 0, 3)`；`0x17c1c` 再次間接呼叫同一槽，入參 `(0x2000c8ac, 0, 115)`。沿正常續段，`0x17c2a` 才把 `0x176f8` 交給 `[0x40080]`。第二次呼叫是重新載入槽，不能只由第一次綁定推出第二次。
- V1.31 候選槽值為 `0x2000039c`，在既有候選 RAM 映射下取自 flash `0x4060c..0x4063a`。該函式在空指標或長度零時不執行目的區寫入；其他情況以 `sb a1,-1(a0)` 逐 byte 填入，執行到 `a0` 等於原指標加長度後返回。它有前後 MMIO 存取，沒有呼叫其他函式。
- 若第一次呼叫綁定此候選且正常完成，索引與其後兩個 byte 在呼叫返回時已清零。若兩次呼叫都遵循此候選且 GP 為 `0x20004000`，第二次填入 `[0x2000c8ac,0x2000c91f)` 與索引區 `[0x20004178,0x2000417b)` 不重疊。這只是正常初始化路徑，不證明實機已載入相同 ROM/RAM、沒有中斷或其他寫入。

驗證：Python `-O` 通過兩份映像 SHA-256、54 bytes APP 與 46 bytes 候選指令窗、slot、兩組 AUIPC/ADDI 位址及五組有界寫址投影（含正常兩個長度、空指標、零長度與模 2^32 跨界）。投影不執行 MMIO 或推論跨界存取能在實機成功。下一步核對 `0x176f8` 讀取索引前的長度與索引限制，將已證明的初始化值和後續讀取假設分開。
