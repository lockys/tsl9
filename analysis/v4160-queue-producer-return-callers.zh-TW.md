# v4.1.60 佇列 producer 的已識別呼叫點與返回值

離線檢查原始 BIN，SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`；映像位址為檔案偏移加 `0x8000`。對所有 halfword 對齊位置掃描直接 `jal`、`c.j`、`c.jal` 編碼，目標 `0x12bc8` 僅得到兩個 `jal ra`，附近反組譯確認如下：

- `0x12c4a` 呼叫後，`0x12c4e` 調整 stack，`0x12c50` 執行 `mret`；這段沒有比較返回的 `a0`。
- `0x16afa` 呼叫後，`0x16afe–0x16b08` 還原暫存器並返回，未覆寫 `a0`，因此將當時值傳給上一層，而不是在此使用它。

已見的兩個 `0x16a7c` 呼叫點 `0x16b2a`、`0x16b38` 的後續路徑不比較該值；前者先依保存的 `s0` 判斷是否再次呼叫，`0x16b40` 將 `s1` 放入 `a0`。這不排除其他呼叫者使用返回值。

`0x12bc8` 佇列滿時不呼叫 provider，`a0` 保持輸入 ID；找到空槽且 provider 正常返回時，後續沒有再設定 `a0`，所以當時值取決於 provider。不能把它直接命名為佇列成功狀態，也不能據此斷定原始 C 的返回型別。

掃描可能把資料或指令後半部當編碼；兩個命中已用周邊反組譯核對。此範圍不涵蓋較複雜的間接呼叫、其他映像、執行期位址或可達性；未連接設備，實際 provider 與中斷行為未知。
