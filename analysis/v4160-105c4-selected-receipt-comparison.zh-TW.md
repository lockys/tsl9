# 105c4 選定收據與 BIN 比對：歷史紀錄

**結論：選定範圍的紀錄檢查通過；原實驗仍為 INCOMPLETE / FAIL CLOSED。** 本文為去識別的歷史摘要，不附原始收據、資料或韌體位元組，讀者無法僅憑本文獨立重現或驗證比對。

## 證據與假設

- 兩份保留下來的收據分別記錄一般與 Python 最佳化模式的探測。每份各有 C、C++ 與 original、split 組合的四列；每列 11 個選定區段、合計 122 bytes。收據記載各列與參考 BIN 相符，original 與 split 亦相符。
- 獨立驗證器直接讀取現存 BIN，將兩份收據四列所記載的選定 bytes 與 BIN 對照，並核對列的副本、符號中繼資料、選定重定位及命令與負面結果紀錄。這是對**現存 BIN 和收據內容**的檢查；不是對已刪除 ELF 的獨立檢視。收據所稱的輸入區段標頭亦無法由收據本身證實。
- 所有位址對照均假設 `PC = 0x8000 + BIN 檔案偏移`；BIN 雜湊不證明載入基底。獨立的有限解碼只涵蓋少數壓縮指令，其靜態分支解讀不證明可達或執行。
- 操作者記載的編譯、連結、負面檢查與狀態是歷史執行的陳述，不是本次重跑或經認證的執行證據。每份收據記載 18 個命令：16 次成功、兩次預期的缺少 leaf 連結失敗。當時探測即使選定檢查通過仍刻意以失敗狀態結束。

## 驗證與限制

本次以 Python `-B` 在一般及 `-O` 模式各執行一次獨立驗證器及測試，四個命令均成功；每次測試各通過四個測試方法。驗證器確認現存七項輸入的固定雜湊，並分別確認現存編譯器、連結器與標頭雜湊通過。現存工具檢查不證明歷史執行使用同一工具；工具缺失會回報不可用，存在但雜湊不符則失敗。

測試包含兩份真實收據的正向檢查、記憶體內收據副本與 BIN 的變異，以及有限解碼器正反例；變異涉及 bytes、位址、符號、命令、負面紀錄、重定位與結構。先前獨立審查亦記錄三項曾誤接受的變異已遭拒絕。這些有限測試不能涵蓋所有畸形輸入，也不能重驗已刪除的歷史變異產物或證明歷史命令曾如實執行。

已連結 ELF、其實際區段標頭與原始連結輸出不再保留；較早的探索性收據曾被覆寫，且過大的工具輸出曾存至預期目錄之外，該外部日誌的位置及後續處置未留紀錄。這些缺口未被本次檢查修復。

因此，本結果不證明 ABI 等價、邊界閉合、可達性、執行期行為或完整 BIN 正確性，也不認證歷史建置。本次驗證沒有安裝軟體，也沒有執行、模擬或燒錄目標。
