# 位址查找 0x6b50c：事件欄位是比較輸入，不是寫入目的地

承接 [連線前處理](v4160-link-preprocess-stores.zh-TW.md) 的類型 0、1 路徑。V1.31 參考 carrier 的 SHA-256 為 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`，以下不代表實機 ROM。

`[0x6b50c,0x6b55e)` 將 `M+4` 保存在 s2。索引從 0 起，每輪重讀 `U8[0x20002fc1]`，若索引已達界限就返回剛讀到的界限，否則重讀 `U32[0x20002fbc]` 作為表基址。唯一呼叫位置 `0x6b54c/550` 的參數為 `(表基址 + 16*索引, M+4, 6)`。結果非零即返回索引，零才遞增再查。本體只有五個保存暫存器的 stack word store。

這個呼叫直接算出 `0x20000442`，不是透過 slot。按參考 startup 的複製對應，其 72 bytes 來自 `[0x406b2,0x406fa)`。若採 Xwchc，`0x20000478` 是 `qk.c.lbu a3,0(a3)`，與前一條 LBU 分別取兩個輸入的 byte。兩指標非零時首次不等就返回 0，六個 byte 都相同才返回 1。任一指標為零則不比較、直接返回 1；因此非零結果並非無條件證明六個 byte 相等。每列對事件欄位讀 0 至 6 bytes，多列可重讀同一範圍。

比較器沒有向任一輸入指標寫入，但不是無副作用：進入時讀 `0x4002420c` 並寫零，在兩個返回分支之一寫回先前讀值。假設堆疊與事件分離、事件在普通 RAM、指令與載入成功且無外部干擾，此查找不改 `M+4..M+9`。不據此推論整個前處理都不寫事件。

檢查：重算呼叫目標，核對五個 frame store、三個 MMIO store 的操作數和 vendor halfword；`python -B analysis/wch-resident-candidate-2026-10-21/instruction-reference/check-profile.py --check` 通過 2,048 種操作數及 16 個單 bit 負向控制。此檢查驗證條件解碼，不是設備執行記錄。
