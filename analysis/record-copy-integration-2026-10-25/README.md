# 複製來源資料整合

[English](readme.en.md)

已將原始 `0x19D08..0x19D66`（94 bytes）與 `0x19D68..0x19DD2`（106 bytes）的唯讀資料納入 [src/](../../src/native/receive/record_copy_windows.c)。範圍由 [82 條原始指令與完整複製函式](../record-copy-windows-2026-10-25/README.md) 推導；沒有包含中間的 2-byte 缺口，也沒有推測實體功能名稱。

## 結果

| 項目 | 驗證結果 |
|---|---|
| C/H 與來源單元 |150 檔；121 個程式單元＋3 個獨立資料單元 |
| C11／C++17 原始與整理版比對 |248 組、496 個物件；舊242組與1453筆產物記錄不變 |
| 新增資料 |200 bytes、2 個真正 OBJECT；沒有新程式碼或新外部相依 |
| 原始位址逐 byte 比對 |67,655／76,800 bytes＝**88.09%**；程式64,544B＋資料3,111B |
| 未解參照 |29→27；2 個排除的直接入口＋25 個資料位址參照 |
| 控制流程 |21,938 指令、4,245 直接轉移、4,861 重定位；普通順序執行位置缺口0 |

兩個複製來源現在均由真正的唯讀資料物件提供。已核對原始 HI/LO 參照、呼叫目的地與所有來源位元組；既有程式碼與舊資料保留。雙語言原位址 ELF 相同；它沒有載入區段、入口為0，是診斷產物。

## 限制與可新增的檢查

邊界推導依賴有效且不回繞的指標、可用堆疊及無非同步破壞等前提；沒有證明完整堆疊、原始資料宣告範圍或實際硬體效果。MCU、安裝中的 ROM、RAM、IRQ 與 BLE OTA 相容性仍未證明。沒有產生新 BIN，也未執行韌體、HOST 模型、ISA 模擬、硬體或後端呼叫。

已增加 [兩個來源提供者的靜態完整性檢查](feature-candidates.json)，可作為後續更新檔建置的預檢基礎；尚不是通用 OTA 相容性檢查或已啟用的硬體新功能。
