# 任務表基址：短直線指令序列只找到初始化寫入

目標是保存任務表基址的四個 bytes `[0x200031c4,0x200031c8)`，不是表項。為檢查[兩個登記呼叫](v4160-pre774-registration-to-read.zh-TW.md)之前有沒有另一個明確設定基址的位置，從每個半字對齊的 `lui r,0x20003` 起，向前檢視最多 16 條指令。只追同一個未改寫的基底暫存器；遇控制轉移或白名單以外的指令停止。只計算標準 SB/SH/SW 的寫入區間是否與目標相交。

|輸入|命中|
|---|---|
|v4.1.60 原 APP|0|
|V1.31 參考 ROM|1：`0x43be8` 建立 s1，`0x43bf2` 寫入整個 word|
|由同一參考 ROM 推得的 RAM 映射|0（不是獨立樣本）|

因此在**這種定址形式**中，唯一命中就是已知的 `T=P+576` 初始化，沒有找到第二個 setter。不能反推基址一路保持不變：清零、複製、間接指標、壓縮 store 或較長序列都可能不在掃描範圍，且編碼命中不等於實際執行。較早的 `0x44022` 仍應依[各條返回路徑](v4160-handler-base-survival.zh-TW.md)判斷，而非依零命中排除。

重現：`python analysis/check_v131_task_base_stores.py <decoded APP> <V1.31 主段>`。一般與 `-O` 均核對輸入 SHA-256、三組命中結果；另在已知寫入前分別換入改寫 s1 與 branch，兩者皆不再穿越該處計入寫入。
