# 時鐘回呼的固定寫址是否包含 `0x20003350`？

接續[註冊路徑](v4160-role-nested-clock-registration.zh-TW.md)。在所述 V1.31 參考映射下，答案是**不包含**；這不是執行後計數仍為零的全域證明。

- APP `0x191c6..0x1921f` 只有讀取、比較與暫存器運算，沒有 store；讀值不穩定可重試。
- `0x43d62` 有七筆 frame 保存。若第一次算出的值與舊值相等，跳過固定寫入；否則 `0x43dce` 以 `sw s1,24(s3)` 寫 `[0x200031b4,0x200031b8)`。`0x43520` 有兩筆 frame 保存；非零回呼正常返回後 `0x4353e` 寫 `[0x200031b0,0x200031b4)`，再讀回。假設 callee 保持相關基址，兩個 word 都不含計數。
- `0x43d94` 和選用的 `0x43dc6` 都把 `1600 * uint32` 的高低字傳給 `0x6df1a`，除數為配置 `+8` 的半字。若沿用 APP 的 `0x03e83e80`，半字為 16000；分子高字至多 1599，故 `0x6df22/26` 均不跳，`0x6df2c` 跳至 `0x6e0e2`。查表後可能走商修正分支 `0x6e2a0`；涵蓋的指令視窗均無 store。這採用 WCH 對 `0x6df48` 的 byte-load 解釋，不外推至其他除數、指令集或未驗證 ROM。

重現：`python analysis/check_v4160_clock_write_sets.py <decoded-APP> <V1.31-carrier>`。固定兩份輸入的 SHA-256，依指令寬度走讀指定區段並核對 store 清單。此檢查不模擬 CPU 或外設；9 筆 stack 保存的實際地址取決於呼叫時 SP，不能算作已排除。未改 BIN 或正式來源。
