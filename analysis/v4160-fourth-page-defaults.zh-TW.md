# v4.1.60：第四設定頁的十二個預設 word

原 APP SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`，載入基址 0x8000。0x13268 請求複製 256 bytes，自 0x08077700 至 D=0x2000c594。D+255 等於 0x5a 就跳到 0x13298；否則呼叫 0x12f7a，請求填零 256 bytes。以下是填充返回後的直接寫入，不是從 Flash 讀出的欄位值。

|D+ (十進位)|常數 (hex)|保留遮罩 (hex)|
|---:|---:|---:|
|0|ff000000|200|
|4|99800300|0|
|8|0000ff04|2|
|12|049aa023|02000000|
|16|030000ff|0|
|20|ff089b00|00020000|
|24|a0230000|0|
|28|00ff089c|200|
|32|9f000300|0|
|36|ff00ff0c|2|
|40|0c9e9803|02000000|
|44|03ff00ff|0|

七個有遮罩的 word 寫為 `常數 | (該次讀值 & 遮罩)`；其餘五個不讀原 word。先寫單 byte D+255=0x5a；D+48=0 的單 byte 寫在讀 D+40 後、寫 D+40 前。若填零成功且沒有其他寫入，十二個 word 即表中常數，並非保留原持久頁的七個位元。0x1304e 尾跳 0x12f48，請求把 D 的 256 bytes 複製到棧，再呼叫 0x9c0a(0x08077700,sp)。不證明裝置寫入或欄位用途。

本機以 rasm2 逐條解出 [0x12f98,0x1304a)，核對取指位址及原 bytes，於獨立的 256-byte 緩衝區比較解碼指令與表格。覆蓋 128 種保留位元組合及全零、全 FF 對照；逐一核對結果、7 次頁內讀取和 14 次頁內寫入順序。一般與 -O 均通過。假設 s0 仍指向 D，棧與頁分離，記憶體存取成功；並非完整 CPU 或 Flash 模擬。
