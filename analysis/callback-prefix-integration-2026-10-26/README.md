# 固定長度回呼資料正式整合

[English](readme.en.md)

[14 個 C/C++ 資料提供者](../../src/native/receive/callback_prefix_data.c) 已納入正式來源，共 109 bytes；每個原位址與 HI/LO 參照均通過核對。

| 項目 | 結果 |
|---|---|
| 來源 | 153 個 C/H 檔；121 個程式單元＋6 個獨立資料單元 |
| C11／C++17 比對 | 254 組／508 個物件；舊 242 組結果及 1,453 筆產物紀錄不變 |
| 原位址逐 byte 相同 | **68,374／76,800 bytes＝89.03%**；程式 64,544B＋資料 3,830B |
| 新增資料 | 14 個實際正長度物件、109 bytes；六個既有零配置 DATA 標籤完整保留 |
| 編譯器未解參照 | 22→8；2 個直接入口＋6 個資料位址參照 |
| 流程 | 21,938 指令、4,245 個直接轉移、4,861 筆重定位；普通順序位置缺口 0 |

資料範圍來自原始 A0 指標與 A2 長度參數，沒有補 NUL 或猜原始宣告大小。原始呼叫與分支保留；封存 SDK 的 `tmos_memcmp` 候選使用 BOOL／TRUE 相同契約，並未代換成標準 C `memcmp` 語義。原機 ROM／ABI 與實際讀取契約仍未證明。

**編譯器計數不涵蓋全部執行期缺口。** 兩個尚未提供的候選回呼表另指向未覆蓋的 `0x10C36`／`0x10D2E`／`0x10D30`／`0x11544`；目前只知道原始指標值與 CODE 覆蓋狀態，尚未完整重建這些回呼，也未提供假函式。

拆分器僅排除三個無重定位參照、位於非 ALLOC `.comment` 的本機編譯器標記（兩個 `$d.1`、一個 `$d.14`）；其餘實際符號角色與重定位均核對保留。

這是位元組覆蓋率，不是功能完成率或可刷入比例。診斷 ELF 入口為 0、沒有 PT_LOAD。沒有產生 BIN、執行韌體／HOST 模型／ISA、操作硬體或呼叫後端；MCU／ROM／RAM／IRQ／BLE OTA 相容性仍未證明。
