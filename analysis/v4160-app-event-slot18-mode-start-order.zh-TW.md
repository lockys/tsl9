# v4.1.60：時鐘設定呼叫與主迴圈的程式順序

接續 [APP 設定首字](v4160-app-event-slot18-mode-clock-app.zh-TW.md)。本輪以原 APP BIN 核對呼叫鏈，不將候選 resident 的內容視為已安裝的 ROM。

- `0x900c` 呼叫 `0x9250`。該初始化路徑在 `0x9268` 呼叫 `0x8e88`，後者在 `0x8eac` 呼叫 `0x19b16`；`0x19b38` 再呼叫 `0x19b56`。設定 slot 的間接呼叫 `0x19bcc` 位於這個子程序內。
- 若上述呼叫依原控制流正常繼續並返回，`0x900e` 才呼叫 `0x8180` 進入主迴圈。迴圈先於 `0x819c` 進行間接呼叫，然後 `0x81a2` 呼叫 `0x12c58`；其中 `0x12d8c` 在相應分支呼叫 `0x14d2e`。因此，對這條正常啟動後的佇列路徑，設定**呼叫**先於迴圈的佇列處理。
- 這個順序不證明 `[0x40074]` 成功保存設定，也不排除初始化中的其他呼叫、回呼或中斷先觸及模式寫入；沒有證明所有到 `0x1074c` 的路徑都經過佇列。

Python `-O` 驗證原 APP SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`、7 個直接呼叫目標及 2 條間接呼叫的 opcode。下一步從 `0x14d2e` 核對進入 `0x10b60` 的條件，區分已證主線與尚未確認的入口。未連設備，未修改原 BIN 或正式來源。
