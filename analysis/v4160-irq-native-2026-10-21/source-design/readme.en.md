# Branch-local lifetime proposal

The original 30-byte helper branches on the full A1 flag before materializing its base or reading the MMIO word. Enabled: base in A4, fresh old word in A5, A0 updated in place. Disabled: base in A5, fresh old word in A4, A0 complemented and updated in place. This bounds the algorithm's working values to A0/A4/A5 while keeping A1 exact and leaving A2/A3/RA/SP untouched. It does not prove the compiler can reproduce that allocation.

The frozen readable C instead hoists the read, computes OR and AND_NOT, selects the result and stores it before branching only to the commitments. Its optimized IR explicitly retains `%3` before, `%5` OR, `%7` AND and `%8` select. The input-only commitment and later return add another selected-value lifetime. The previous value-returning commitment diagnostic removes the last issue, but still has the same load/two-expressions/select/store structure. Actual native compilation fails all five functions under both strict three-register and four-register profiles. The exact error is `Stack pointer required, but has been reserved.` These are recorded compiler outcomes; the lifetime explanation is a supported hypothesis, not a complete allocator proof.

`proposal.c.txt` proposes one concrete body change: branch-local fresh reads, calculations, stores and direct value-returning A0 commitments; change `address` to `offset`. Add branch-specific opaque bases fixed to A4 or A5. The parent's refined output-only `lui` primitive makes each base a separate SSA output and a control-dependent barrier, preventing the two volatile reads from merging via the same constant address. Unlike an empty identity with a constant input, this creates no shared constant input SSA. Each base physically starts at `0x40021000`; do not commit the full register address as the base residue. A dynamic mask identity fixed to A0 shortens helper mask lifetimes. Main's per-use immediate `li` output-A0 primitive avoids holding repeated C mask literals across operations. Its immediate constraint must require an actual compile-time constant. Hosted identities add no I/O events. These are low-level data-materialization primitives; the branch, arithmetic and memory effects remain typed C.

The commitment must return its bound A0 output, and the C body must return that value directly. It retains exact A1 bits, with A4/A5 in source-specific order. A standalone boolean conversion of A1 would break the contract. The main initializer retains all six fresh RMWs, its six trailing stores and clear/set CSR operations in their proven order. Its final value-return bridge commits A0=result, A1=0, A4=128, A5=`0xE000E000`. Do not keep the pre-bridge result alive for a second return. No proposal permits allocation in A2/A3 or use of RA/SP.

A separate worker's single SP-enabled diagnostic reports helper spills of old word, both branch candidates and selected result; main caches repeated mask literals. It also found machine outlining through T0 despite the fixed-register profile. That diagnostic is not a candidate. This review did not run it independently. The parent should bind its final receipt separately. Explicitly disabling that observed outliner is a justified single correction if the supplied compiler documents the flag; retain emitted-symbol/call/T0 checks regardless. The parent's four-register A0/A1/A4/A5 allocation requires proof of exact A1 restoration on every helper path; a destination-set check alone cannot establish this. The proposal is intentionally uncompiled here; no optimization/profile search or model edit occurred.

Before acceptance, require hosted C/C++ exact trace/residue tests and compiled negative controls; then inspect actual C/C++ native IR and every emitted function, including outlined functions, calls and return continuations. Check one fresh read and correctly addressed store per helper; the branch-specific output pair; A1 bit preservation; all instruction destinations; no SP/frame/RA/T0 or hidden calls; A2/A3 preserved; main 20 ordered effects and correct final outputs. Different opaque base values in IR require a narrowly justified identity model, not generic invented address equality. If the compiler still spills or outlines, record failure rather than accepting a relaxed boundary. Code size must be measured anew. Normal returns do not establish identical transient registers, stack traffic or asynchronous IRQ behavior, nor original placement, ROM, OTA or hardware compatibility.

Evidence and exact input hashes are in `verification.json`. The source-design script inspects existing files only; no compilation, execution, network, device operation or BIN generation occurs.
