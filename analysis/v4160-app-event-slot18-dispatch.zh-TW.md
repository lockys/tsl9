# v4.1.60：第 18 槽更新的模式 1 路徑

接續[第 18 槽更新來源](v4160-app-event-object-length-source.zh-TW.md)與[佇列寫入重播](v4160-app-event-queue-insert-replay.zh-TW.md)。本輪核對分派條件，不推論實機收到何種記錄。

- `0x14d40/0x14d44` 形成模式表基址 `0x1a6b8`。表的第 1 項（從零開始）指向 `0x14d5e`，由此以 `lhu a5,0(s0)` 讀取記錄識別值。
- 識別值 `0x0679`（1657）依序通過 `>819`、`>991`、`>1025`、`>1267` 的無號分支，到 `0x15036` 通過相等檢查並轉移至 `0x152ba`。這條路徑比較記錄首半字，沒有另檢查記錄 `+2`。這不代表其他入口或呼叫者沒有檢查，也不證明某個佇列生產者會提供該識別值。

Python `-O` 通過原 APP SHA-256、七個模式表目標、一處半字讀取、五個比較常數、九個分支目標與全部 65,536 個半字值的條件投影；只有 `0x0679` 符合這條已核對路徑。未執行設備。下一步只比對已知正常佇列來源是否有此識別值的靜態證據；不足則保留未知。
