# v4.1.60：事件記錄如何傳到下游物件

接續[回呼欄位用途](v4160-app-event-record-field-use.zh-TW.md)，分開記錄來源、暫存區與目的物件。位元組編號從 0 開始。

- `0xc776` 不直接把七個位元組寫入目的物件；它向 `[0x4004c]` 請求 `(gp+220, 原記錄指標, 7)`。正常返回後，它以 `0x2000c290` 為物件指標轉到 `0xc6a8`。這只建立參數關係，不證明裝置上的間接函式確實執行複製。
- 若合成提供者照此複製、GP 與區域不變且彼此不重疊，暫存記錄的 `b1` bit 1 控制 `0xc6a8` 是否處理。當該位元已設且 `b1 >> 2` 非零，`b2/b3/b4` 依序寫到目的物件 `+4/+5/+6`；因此上游類別 2 的表項改寫可傳到這三個目的欄位。`b5/b6` 仍隨七位元組送到暫存區，但在這段已檢查的解碼中不決定上述三筆寫入。物件 `+7/+8` 有各自的條件更新，不是記錄的等長覆寫。
- 範圍截至 `0xc6a8` 返回或尾轉移；不推論實機間接函式、副作用、別名或完整控制流。

Python `-O` 使用固定原 BIN 與既有兩段有限解碼器，通過 28 組合成串接案例：七筆原表項 × 兩種解碼開關 × 兩種目的物件狀態，檢查複製參數、三筆有序欄位寫入、停止位置和原記錄不變。關閉案例由合成提供者清除暫存開關，只測解碼守衛，不代表真實提供者會改旗標。下一步追查物件 `+7/+8` 與後續 dispatcher 的資料依賴。
