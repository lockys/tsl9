# 接收零值與佇列入口的條件關係

原始 v4.1.60 BIN SHA-256：`0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。離線反組譯 `0x16a7c` 的結果：兩次前置傳輸之後，迴圈把另外 13 次 `0x16896` 的返回低 byte 依序存到 `sp+16..28`。若這 13 次均正常返回零且中途無干擾，`0x16acc` 的旗標檢查通過，但 `0x16ae6` 的長度檢查以無號比較拒絕零，跳到 `0x16afe`，不從這次呼叫執行 `0x16afa` 對 `0x12bc8` 的佇列插入呼叫。

更窄地說，即使其他 byte 任意，只要第五筆存入的長度 byte 低四位為零，這次呼叫不會到插入點：旗標不符可能先拒絕，否則長度檢查拒絕。零返回可能來自逾時或成功收到零；不能因此推論是哪一種，也不能斷言佇列全域為空或其他路徑未插入。

本機 `analysis/check_v4160_ingress_zero_length.py` 固定 BIN 與 guard 指令位元組，以手寫算術檢查 65,536 組旗標和長度；普通及 Python `-O` 通過。這不是逐指令模擬或實機紀錄，且假設此前呼叫返回、暫存器與堆疊資料不受干擾。驗證腳本目前只在本機。
