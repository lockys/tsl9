# v4.1.60：分派模式寫入函式的直接引用

接續[模式的清零與直接寫入](v4160-app-event-slot18-mode-writer.zh-TW.md)。掃描固定 SHA-256 的原 APP 映像，從每個仍有 4 bytes 的半字邊界解碼標準 RV32 `JAL`，以 `0x1074c` 為目的位址。38,399 個起點中有四筆命中；另對照各引用的原指令與既有來源。

| 引用指令 | 形式 | 到達轉移指令時的 `a0` |
|---|---|---|
| `0x107c2` | 尾跳 | `0`，由 `0x107c0` 設定 |
| `0x1080c` | 尾跳 | `0x10806` 取當時的 `s1`；此前的呼叫已返回，`0x10808` 才還原保存的 `s1` |
| `0x147be` | 呼叫 | `0`，由 `0x147bc` 設定 |
| `0x154a2` | 尾跳 | `0`，由 `0x1549e` 設定（其後只調整 `sp`） |

`0x107d4` 曾把 `a2` 存至 `s1`，但在 `0x10806` 之前有間接和直接呼叫，尚不能把當時 `s1` 等同於入口 `a2`。同理，上表記的是抵達寫入函式時的入參，不是 `0x10776` 實際寫入值的全域證明。掃描不包含間接或其他形式的控制轉移，也不證明各路徑可達或已執行。

離線 Python `-O` 通過原 APP 雜湊、四筆 JAL 的位址與目的暫存器、五個參數來源指令窗；反組譯結果與既有來源一致。下一步只針對非固定零的引用核對上游入參及暫存器保存邊界。未連接設備或修改原 BIN／正式來源。
