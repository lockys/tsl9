# 到期節點的事件投給任務 3，而非任務 7

接續 `v4160-id7-timer-service.zh-TW.md`。只看該批有節點的 128 個狀態，以節點期限作為無副作用的時鐘返回值，保留進入投遞時的暫存器與 RAM。`0x20000588` 呼叫 `0x4354a` 時 `(a0,a1,ra)=(3,0x2000,0x2000058c)`。以下停止點是投遞返回，不是整個計時器服務返回。

* 承接的任務數 8：登記表內 ID 3 有效。`0x43578` 寫入事件表基址加 6 的半字（0x2000486e），0 → 0x2000，返回 0。
* 只把該半字預設為 0x42：得到 0x2042，而非覆蓋為 0x2000。
* 只把任務數改為 3：ID 3 不滿足嚴格小於條件，跳過事件表寫入，返回 3。

每組 128 例，其中任務 7 的事件原為 0、0x47 各 64 例，三組均保持原值。另核對投遞內的完整寫入序列：先清控制字 0x4002420c，成功時才寫事件半字，最後還原取樣控制字。一般 Python 與 -O 各通過 384 條路徑。本機驅動 `analysis/check_v4160_role_rf_to_heap.py`；條件 V1.31/Xwchc、合成記憶體與周邊，非裝置 ROM 或任務 3 已執行的證據。
