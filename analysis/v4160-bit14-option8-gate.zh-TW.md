# 登記成功不等於固定選項 8 會執行

接續[收件 ID 的來源](v4160-bit14-option8-id.zh-TW.md)。`0x200035ab` 是控制是否走固定選項 8 的 byte，不是收件 ID。本輪把兩次讀取分開：第一次決定是否繼續初始化，第二次才決定是否設定目的 ID。

1. **先有清零路徑。** 第一個角色初始化在 `0x6dd3a` 呼叫 `0x46570`，其中 `0x46582` 呼叫 `0x6d682`，`0x6d6ce` 將 `0x200035ab` 寫為零。這是明確的後續清零指令，不只依賴啟動時的 BSS 初值。
2. **後一次登記走成功分支時，角色組合決定是否設為 1。** `0x6aeba` 先保存這次登記的 ID；未走 255 失敗分支時，`0x6aeca` 把共用選項寫 8，`0x6aece` 呼叫 `0x6ae4e`。它讀的是**另一個**共用角色 ID `0x200035f5`。若該 ID 不是 255，依序將 gate 寫 1、共用選項 `0x200035f4` 改寫為 12；若是 255，兩筆都不寫，不是強制清 gate。
3. **兩次分支。** 返回後 `0x6aed6` 讀 gate，非零便跳 `0x6ae96` 結束這段初始化。另一次 APP 經槽 `0x401b0` 進入候選 `0x6ad8e` 時，`0x6adb4` 重新讀 gate；非零跳 `0x6adec` 返回零，根本不讀收件 ID，也不呼叫設定函式。只有這次讀到零才繼續，從 `0x20002fb0` 讀 ID 並以**常數**選項 8 尾跳 `0x49b92`（不讀共用選項 12）。

因此在上述路徑上，共用角色已登記且 gate 後續未被改寫時，固定選項 8 會被略過。相反地，共用 ID 為 255 時要看原 gate，不能僅憑 255 判定分支。兩次讀取之間並非無條件直線執行；尤其 APP 此呼叫傳入非零 `a1` 時，`0x6ada0` 先呼叫 `0x6c0f0` 再讀 gate。本輪未證全部中間副作用、間接寫入或裝置實際 ROM。

[固定雜湊及指令檢查](check_v131_option8_gate.py)：以 V1.31 carrier 路徑為唯一參數，核對兩個固定 writer、兩個非零跳轉與零值尾跳；一般及 `python -O` 均可執行。不需要設備。
