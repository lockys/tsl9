# V1.30 resident：缺失來源字的兩種結果

依據[原始載體覆蓋](v130-resident-sparse-copy-coverage.zh-TW.md)，本機 `experiments/v130-resident-copy-gap-next/test_gap.py` 以稀疏來源模擬第二次 copy 及 zero helper。假定前段已成功，保存的返回位址有效，其他存取成功；這不是 RV32 指令執行、例外處理或實機模型。

- 最後一字讀取不可用：保留前 34 次讀寫，在 `0x6e9b0` 停止，沒有最後一次寫入、不清零，也不走到 MRET。模型停止不等於硬體會停在該處。
- 假設讀取成功：測三種合成值，全都先寫至 `0x20002da8`，才在後續清零覆寫，並到達 `0x6dd44` 的 MRET 邊界。三個案例的最終合成記憶體相同，但有序讀寫記錄不同。沒有將合成值填入 HEX 或當成原始資料。

一般 Python 與 `-O` 各兩項通過，使用獨立合成資料及重新核對完整 SHA-256 的 WCH 原始 HEX，並驗證更早的缺字不會被最後一字的假設值掩蓋。此結果不證明真正的 resident 身分、最後一字可讀或實機返回。原 BIN 及正式來源未變。本提交只發布報告。
