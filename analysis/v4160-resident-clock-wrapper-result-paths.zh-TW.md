# Resident 參考碼：雙回傳值的端點、封裝與重試

接續[兩個相鄰 wrapper 呼叫](v4160-resident-clock-wrapper-pair.zh-TW.md)。以固定雜湊的 V1.30 原始 HEX／主段及 V1.31 主段逐條核對 `0x53746..0x5381e` 與 `0x538a4..0x5397c`。以下假定呼叫正常返回、保存相關暫存器且記憶體成功存取；不證明實機可達。

第一階段以第一個回傳的低 14 位與第二個完整 32 位判斷兩個端點：兩者皆零，或分別為 `0x3fff`、`0xffffffff`。端點不寫這階段的輸出，而是再執行一輪相同引數的兩個 wrapper，回到判斷（V1.30 `0x53808→0x5374c`，V1.31 `0x53966→0x538aa`）。普通路徑將第二個回傳寫到基址 +244..247，第一個回傳的低 byte 到 +248，次低 byte OR `0xc0` 到 +249。兩版基址依序為 `0x20003268`、`0x200033b8`。

第二階段再次取得兩個值，重試入口為 `0x53784`／`0x538e2`。這裡的第一個端點判斷直接使用第一個 wrapper 的 16 位元回傳，不先做 14 位遮罩：兩者皆零，或第一個等於 `0x3fff` 且第二個全 1，則不寫並重試。其他結果以「第二個回傳的四個小端 bytes，接第一個回傳的低 14 位」寫入 +250..255。這六個 bytes 若等於 +232..237，則重試（比較發生在寫入之後）；否則走本地 epilogue 返回。未證明實際會重試幾次，亦未替六個 bytes 命名。

Python `-O` 的有限投影通過第一階段六項、第二階段五項合成向量，涵蓋端點、第一階段遮罩、普通封裝及第二階段寫後重試。模型不是 ISA 或實機執行。原 BIN 與正式來源未改。本輪只發布報告；下一步先查 +244..255 的讀者與 +232..237 的寫入者，再評估這兩組六位元組的用途。
