# v4.1.60：物件 +7/+8 更新與分派決策

接續[事件記錄的下游流向](v4160-app-event-record-downstream.zh-TW.md)。本輪分開檢查解碼器的欄位更新、尾轉移條件，以及分派器交給下一個函式的資料。

- `0xc6a8` 的 `+7` 更新以暫存記錄的 `b5 & 31` 為參數；非零時調整既有 `+7` 的低七位，保留最高位。在固定、互不重疊的合成記憶體中，走過這個更新分支可令解碼器進入後續檢查，但寫入的數值本身並非分派條件。
- 解碼器要求本次走過更新分支，且物件 `+2` 非零，才把 `(b5 >> 5) & 3` 寫到 `+8` 的低兩位、保留其餘六位並尾轉移至 `0x12a08`。`+8` 的新值不是本次轉移的判斷輸入。
- `0x12a08..0x12a50` 的直接物件讀取使用 `+0`、`+2`、`+11`，未把 `+7/+8` 作為直接分支輸入。走到 `0x12a4e` 時，`a0=sp+23`、`a1=物件+3`、`a2=零延伸的物件 +2 byte`（`0x12a32` 的 LBU）；**不是固定長度**。若提供者遵循候選 byte-copy 語意，`+7/+8` 是從來源起算的偏移 4/5，分別要長度至少 5/6 才會隨資料傳遞。`+11` 非零的另一分支不在此旁證內；實機別名、副作用及後續讀取未驗證。

Python `-O` 核對通過固定原 BIN、72-byte 分派前段和 2,560 組有界解碼投影，涵蓋 32 個調整碼、四種低位值、十種既有 `+7` 值及兩種 `+2` 狀態；未執行實機或間接函式。下一步用既有複製／寫入模型核對長度條件及後續載入。
