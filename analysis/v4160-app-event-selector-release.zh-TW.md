# v4.1.60：候選 `[0x40068]` 的清理分支不呼叫 handler

接續[寫零前的 APP 回呼表清理](v4160-app-event-selector-prezero-callback.zh-TW.md)與[候選事件清除](v4160-app-event-selector-stop-task.zh-TW.md)。本輪只檢查 `0x90b0` 命中、且槽 `+8` 非零時的另一個間接呼叫。

- 原 APP 在 `0x90d4` 讀槽 `+8` 到 `a0`，零值跳過；非零時 `0x90de` 呼叫 `[0x40068]`，不呼叫槽 `+4` 的回呼。V1.31 候選 slot word 為 `0x431ba`。
- 候選 `0x431ba..0x43208` 的唯一非返回呼叫位於 `0x431fc`，由 AUIPC/JALR 計算出 RAM `0x20000110`。在候選複製映射下，helper 的 212 bytes 來自 flash `0x40380..0x40454`。核對所有 14 條局部分支／跳轉皆留在 helper 內，唯一以暫存器轉移的是 `0x20000126` 返回；沒有呼叫 handler。原範圍外的裝置程式碼和 MMIO 效果並未驗證。
- 合併上一輪結果：若兩個 slot 及 RAM helper 確與 V1.31 候選一致、指令解碼及正常存取成立，`0x90b0` 的同步呼叫鏈不派發 `0x176f8`。這不等於證明分配生命週期正確，也不排除中斷、其他上下文或實機不同綁定。

Python `-O` 通過兩份映像雜湊、原 APP 呼叫窗、slot 與 helper 綁定、兩段共 290 bytes 的指令掃描，以及 18 個局部控制目標。未連設備或修改原 BIN／正式來源。下一步檢查 `0x17bf6` 的較早 `[0x40048]` 呼叫：核對 V1.31 候選是否確實在回呼登記前清除索引 byte，而不只接受清零參數。
