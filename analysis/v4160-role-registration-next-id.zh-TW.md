# 回呼註冊返回後，下一個任務 ID 的來源

範圍：沿用第三筆配置清零後的 64 個合成狀態，每個狀態分成原本空表及另設 12 格全滿的對照。從 0x4dbc2 執行回呼註冊，保留各分支實際改寫的暫存器與 RAM，從 0x6dd2e 接到 0x45220 入口。不是僅替換一個返回碼。

- 空表分支在首格存入 0x4d916，返回 0；全滿對照不寫回呼表，返回 19。呼叫者不依這兩個值分支，而改用 0x465b4 呼叫任務註冊 0x43c4e。
- 兩邊沿用的任務計數為 7、容量為 29。0x43c6a 更新計數為 8，0x43c72 將 0x465b4 寫入任務表第 7 格（從 0 起算），下一個 ID 都是 7。0x46574 將該值以 word 存在入口 SP−20，再以該 ID 進入 0x45220。
- 每對從 0x6dd2e 開始的 PC 序列和有序寫入皆相同，但兩份回呼表仍不同，不能推斷兩分支全狀態相同。沒有執行已註冊的回呼，也沒有對任務表滿的裝置作預測。

本機重播：一般 Python 與 -O 均得到 `64 paired caller continuations`，觀測三元組 `(entry count, capacity, saved ID) = (7, 29, 7)`；既有 25 組合成計數與容量的對照亦通過。限 V1.31 候選 resident、條件指令解讀、分離的合成記憶體及正常存取，不是 v4.1.60 裝置的執行紀錄。
