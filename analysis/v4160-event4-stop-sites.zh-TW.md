# 事件 4：停止計時器與清待辦事件的 APP 呼叫點

掃描原 APP 全部半字對齊位置，限 RV32 `LW` / `C.LW` 位移 84、92（表基址為 `0x40000` 時分別對應 clear、stop）。這不是對所有間接呼叫的證明。

- **Clear**：唯一命中 `0xe014` 是從 `0xe012` 開始的 JAL 後半，不是在該指令流中載入表項。
- **Stop**：12 個編碼命中有 4 個同樣落在 JAL 後半；另 6 個呼叫位置的事件參數分別是 16、16、1、2、1、2，不是 4。
- `0x9106` 的事件是 `low16(1 << index)`；正常索引 0..14 中只有 2 產生 4。任務 ID 取自 `gp+166`。
- `0x1688c` 的停止分支取 `gp+363` 作任務 ID。對初始化的三個 stack 半字，索引 0、1、2 得 0、2、4；選 2 且輸入 a1 為零時才走這個停止分支。未將這三個索引視為呼叫端已驗證的範圍。

因此，有停止同名事件的程式，但這兩處都不是直接讀周邊連線記錄的 `gp+148/+152` 任務 ID。不同儲存位置不代表值必定不同；尚須核對註冊結果、其他寫入與呼叫時序。未涵蓋等價的地址運算、預載函式指標、resident 或非同步行為。重現：用 `check_v4160_event4_stop_sites.py` 加原 decoded BIN 路徑；一般與 `-O` 均通過。
