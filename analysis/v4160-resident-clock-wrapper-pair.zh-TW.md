# Resident 參考碼：相鄰的兩次 clock wrapper 呼叫

接續[三組包裝函式](v4160-resident-clock-wrapper-boundaries.zh-TW.md)。固定 V1.30 原始 Intel HEX 與兩版連續主段的 SHA-256，以原始欄位核對四個 JAL 的目的、兩組引數設定及回傳值的局部使用。參考碼不代表實機 resident。

| 參考 | 第一個呼叫（a0=0、a1=0x3fff） | 第二個呼叫（a0=0、a1=0xffffffff） |
| --- | --- | --- |
| V1.30 | `0x53738 → 0x43d3e` | `0x53742 → 0x43d62` |
| V1.31 | `0x53896 → 0x43e8e` | `0x538a0 → 0x43eb2` |

前一個 AUIPC/JALR 呼叫指向 `0x20000332`。假定它按 link 返回並保存 s1，第一組引數源於 `lui s1,0x4` 後的 `addi a1,s1,-1`；第二組由立即數載入，並非傳遞第一個結果。第一個呼叫若返回到下一條並正常執行，至第二個 JAL 之間沒有分支：先將第一個回傳存入 s0，再準備第二組引數。第二個呼叫若正常返回且保存 s0，第一個結果取低 14 位後，與第二個回傳值做 OR；V1.31 靜態反組譯另外顯示全零，以及第二個回傳全 1 且第一個低 14 位全 1，均跳往 `0x53966`。不能假定兩次各自取得的 reader 回傳值相同。

Python `-O` 的兩版局部指令比對與前置呼叫目的核對均通過。尚未執行韌體、不證前置 helper 正常返回、不證實機可達。下一步確認 OR 後的兩個端點分支及普通路徑分別如何使用結果，再判斷用途。原 APP BIN 與正式來源未改。
