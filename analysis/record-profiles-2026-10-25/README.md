# 記錄參數處理：離線重建

已將 `0x18232..0x18604` 的四個完整函式重建為 C，並以 C11 與 C++17 分別編譯。978 bytes、310 條原始指令、43 個直接轉移及 3 組程式位址參照均通過物件比較。這是保留暫存器與私有架構操作的重建，並非可直接移植的完整原始碼。

| 入口 | 觀察到的行為 |
|---|---|
| `0x18232` | 索引大於 9 時返回；分成 0..4 與 5..9 兩路，從記錄拷入 8 bytes，檢查標記 `0x5A`，從資料通道 16／17 取欄位並比較門檻。 |
| `0x18430` | 按輸入 bit 0／1 與既有旗標清除對應狀態，再通知既有處理函式。 |
| `0x184AA` | 拆出四欄位，分別限制到 10..250、30..470、5..75、10..50；建構含 `0x5A` 標記的記錄，拷貝 8 bytes 並呼叫既有設定寫入函式。第八 byte 未在此函式明確初始化，原樣保留。 |
| `0x185D8` | 僅在輸入 byte 2 為 3 或 4 時更新模式；依另一狀態 word 決定是否轉移至既有處理函式。 |

實體單位、車輛功能歸屬、私有 ABI 與硬體／OTA 相容性尚未證明。沒有執行目標、主機模型、ISA 模擬或硬體操作，沒有新增 BIN。完整來源證明已通過 210 組比較／420 個物件；接上兩個舊依賴且沒有新增依賴，尚缺 141 個。43,223 個選用的原始位址 bytes 與官方 BIN 相同。靜態控制流程涵蓋 2,357 個直接轉移，一般延續位置無缺口；間接轉移的實際目標尚未驗證。
