# RF 初始化：兩次保存的是同一位址的兩次讀值

依據 V1.31 參考 carrier（SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`），以 RV32、基址 `0x40000` 靜態核對。以下不是 v4.1.60 裝置的 ROM 或 MMIO 觀測。

| 位置 | 指令所做的事 |
|---|---|
| `641ea / 641ee` | 外層讀 `0x4002420c` 到 `s4`，再寫零。`641f8` 呼叫 `63eda(13)`。 |
| `63ee8 / 63eec` | 內層從同一位址重新讀到 `s2`，再寫零；不可把這個新樣本當成外層樣本，也不可僅憑前次寫零就斷言它是零。 |
| `63ef8..63f00` | 讀 `p = word[0x2000353c]`，取 `word[p] & 3`。為零就跳到 `63f56`；這條路不檢查參數 13，也不呼叫回呼。非零則進入 `63f02`，不適用短路結論。 |
| `63f56..63f68` | 寫回 `s2` 到 `0x4002420c`，還原 `s1/s2` 和堆疊，返回 `641fc`。此時恢復的是內層樣本。 |
| `64246..64252` | 外層依次呼叫 `6645c`、`67198`、`662da`、`6636e`，不是在 `641fc` 立刻寫回。 |
| `6427e / 64282` | 先清 `byte[s0+7]`，再寫 `s4` 到 `word[s1+524]`。若四個呼叫均返回且保留所需暫存器，後一筆才把外層樣本寫回原位址。 |

核對方式：對上述 carrier 的 `[641d6,641fc)`、`[63eda,63f02)`、`[63f56,63f6a)`、`[641fc,64298)` 取出 `VA-0x40000` 的檔案位元組，以 `rasm2 -a riscv -b 32 -s <VA> -D <hex>` 解碼。內層短路只用標準整數指令及 `fence.i`，不需用 Xwchc 重解浮點助記符。進入外層之前的狀態檢查仍沿用先前的條件解讀。以上僅描述成功讀寫和有效返回堆疊下的 CPU 行為；不保證外設接受寫值或最後一筆一定執行。
