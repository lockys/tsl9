# 0x960e 所寫七個半字的讀者

把 [producer](v4160-settings-callback-960e.zh-TW.md) 與 [既有 IRQ 原位重建](timer3-irq-2026-10-24/README.md) 接起來：`0x97ba` 建立狀態基址 `0x2000bebc`，其 +16 是 producer 寫入的指標。假設該指標、資料與保存暫存器穩定、`0x93aa` 已清 phase/index，且後續有符合條件的 IRQ，這七個半字表達兩筆 6-byte 記錄及下一筆的終止欄位。

|索引|phase 0: +0 → 週期暫存器值|phase 0: +2 → 期限增量|phase 1: +4 → 期限增量|
|---|---|---|---|
|0|1165 → 857|130|0|
|1|1465 → 681|150|0|

* `0x981a` 讀 +0；對這兩個正值，半字寫入 `0x4000042c` 的值為 `low16(1000000 / value - 1)`（整數商）。比較輸出另由旗標／設定及外設讀回值決定，不直接取自這七個半字。
* `0x987e`、`0x98ae` 分別在再次取得時間後取 +2、+4，加到當次時間並寫入期限。phase 1 先將比較暫存器清零。增量 0 不代表同一個 IRQ 直接跑完下一階段；共同尾端更新 phase 後退出。
* phase 2 將 byte 索引加一，再讀新列 +0 (`0x98ea`)。第一次讀偏移 6 得 1465，走 `0x9930` 清 phase；第二次讀偏移 12 得 0，進入結束處理，不取偏移 14 或 16。零終止不代表硬體必在同一個 IRQ 停止；`0x9902` 尚會查另一個半字狀態。

一般／`-O` 檢查以原 BIN 的建表指令、讀取欄位與指定機碼做有限組合，不是連續 CPU 或裝置驗證。每次進入仍須外設狀態 bit 0 及時間比較通過；沒有據此命名物理負載或時間單位。
