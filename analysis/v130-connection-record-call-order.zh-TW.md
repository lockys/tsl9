# V1.30 resident：串列清除之後與建立紀錄的呼叫點

唯讀核對 V1.30 參考 BIN（基址 `0x40000`；SHA-256 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`）。接續[串列初始化](v130-connection-record-init.zh-TW.md)及[編號指派](v130-connection-record-create.zh-TW.md)。

- 假設清除函式正常返回至 `0x5365c`，下一個直接呼叫為 `0x635a6`。這一小段將 `0x2000332c` 的 word 和 `0x20003328` 的 byte 清零後返回；兩者均在原串列清除範圍 `[0x20003304, 0x20003320)` 之外。
- `0x53660` 起還原現有 frame，`0x5366a` 尾跳 `0x5e5fa`。後者清除 `0x20003330` 的 byte 和 `0x20003334` 的 word，再於 `0x5e60a` 尾跳 `0x5370a`。在這兩段短續程中未見再次寫入串列頭、尾或計數；此結論止於 `0x5370a` 入口。
- 另確認兩組直接建立／查找呼叫：`0x59d12 → 0x57804` 與 `0x60748 → 0x57804`。兩處均將回傳的 `a0` 複製到 `s3`，若 `a0` 為零則跳過查找；若非零，下一個 JAL 分別由 `0x59d1a` 或 `0x60750` 呼叫 `0x576ec`，把同一個 `a0` 作為查找鍵。

重算映像 SHA-256、獨立解碼 8 個 JAL 與 2 個零值分支，並核對 3 段續程原始位元組，全部通過。這證實初始化後的短續程及兩個建立呼叫點，尚未把它們連成一條同次開機的可達路徑，也未排除其他建立呼叫者或中途寫入。不能確認實機 resident 身分，也不能斷定 BOOT 第一筆連線編號為 `1`。
