# V1.30 參考 resident：0x6dc92 的資料邊界與返回條件

延續[v4.1.60 APP 與 V1.30 的交接對照](v4160-resident-handoff-v130-reference.zh-TW.md)。以下只描述本機 V1.30 參考快照（基址 `0x40000`，SHA-256 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`），不識別設備上的 resident。以 `rasm2` 靜態反組譯 `0x6dc92..0x6dd04` 與 `[0x40280,0x402b0)` 的兩個 RAM helper 原始 bytes，並以獨立欄位解碼核對三個 JALR、copy 引數與迴圈比較。比較以 raw 欄位為準：copy 的 `0x00b67363` 為 `bgeu a2,a1`；zero 的 `0x00f77363` 為 `bgeu a4,a5`，都是包含終點的無號比較。

| 轉移位置 | 目的 | 成功存取條件下的資料範圍 |
| --- | --- | --- |
| `0x6dcd4`，JALR x1 | `0x20000010` | 2,873 個字，`[0x402b0,0x42f94)` → `[0x20000040,0x20002d24)` |
| `0x6dcf4`，JALR x1 | `0x20000010` | 35 個字，`[0x6e928,0x6e9b4)` → `[0x20002d20,0x20002dac)` |
| `0x6dd00`，JALR x0 | `0x20000022` | 清零 `[0x20002da8,0x200034c8)` |

快照在 `0x6e8ea` 結束（上界不含）：第二次 copy 的 140 個來源 bytes 全部不在這份快照，不代表硬體未映射，也不代表其他參考載體沒有。第二次 copy 首字覆寫第一次 copy 末字；其末字會被後續清零覆寫，但仍須先讀取來源，不能用清零代替未證的讀取。

`0x6dc92` 區段保存進入時的 `ra`，`0x6dcf8` 還原後以無 link 跳入 zero helper。假定記憶體存取成功、已複製 helper 可執行且保存的返回位址未遭干擾，zero helper 的 `ret` 使用外層連結值 `0x6dd44`，該處為 `MRET`。本次掃描的外層、初始化與兩個 helper 沒有顯式改寫 `mepc` 的指令；不排除例外或中斷改變 CSR，也未執行任何韌體。下一步先核對 V1.30 原始載體是否覆蓋 `0x6e928..0x6e9b4`，不要填造缺失資料。
