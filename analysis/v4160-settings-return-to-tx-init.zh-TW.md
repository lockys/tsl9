# 六區設定檢查返回後，先請求清零兩個 TX bank

原 APP SHA-256：`0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。以下以各次必要的呼叫正常返回、保存的棧內容未被改寫為前提。

- `0x9264` 的四位元組 JAL 呼叫 `0x131c2`，返回位址為 `0x9268`。設定檢查建立 16-byte frame，保存 ra。末區標記等於 `0x5a` 時，`0x13304..0x13308` 還原 ra/sp 並返回。
- 標記不等時，`0x132f4` 先還原同一個 ra/sp，再以不寫 ra 的跳躍轉至 `0x13108`。修復函式另存、還原 ra，尾跳 `0x130d6`；後者在 272-byte frame 保存這個 ra，呼叫頁面寫入後還原。因此正常完成後也直接回 `0x9268`，不是回到標記檢查。
- `0x9268` 的兩位元組 RV32 C.JAL 呼叫 `0x8e88`，新返回位址為 `0x926a`。此處不檢查先前 a0。`0x8ea6` 以 `(0x2000b18c,0,2124)` 呼叫槽 `0x40048` 內的目標。此範圍 `[0x2000b18c,0x2000b9d8)` 恰為先前辨識的兩個相鄰、各 1062-byte 的 TX bank。是清零請求，不是觀測到實機 RAM 已清零。下一個直接呼叫是 `0x8ea8 → 0x199e2`。

離線檢查：對兩個合成棧位置各跑 256 種標記，2 次直接返回、510 次經修復返回，核對 JAL/C.JAL、棧恢復指令及清零呼叫參數；一般與 Python `-O` 通過。跳過先前各區的內部執行，對填充、複製與頁寫入注入正常返回，不是從開機起連續執行的證據。
