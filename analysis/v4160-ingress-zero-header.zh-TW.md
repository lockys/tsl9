# 接收標頭零值的條件性影響

原始 BIN SHA-256：`0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。`0x16acc..0x16afa` 在旗標及長度通過後，將 `(byte0 << 3) | (byte1 >> 5)` 傳給 `0x12bc8`。如果第五筆返回 1，而第二筆返回零，即使零是逾時產生，旗標檢查也會通過；這與第五筆為零時必拒絕不同。

合成對照：若其他條件相同，byte0 為 `0x28`，byte1 原本設想為 `0xa0` 時 ID 是 325；將第二筆改成零後，ID 是 320，兩者皆通過這兩個 guard。此例只是反事實輸入，不證明任何真實資料遺失或佇列成功寫入。另一種零替換使 byte0 為零時 ID 僅剩 byte1 的高三位；結果為零還涉及空槽標記，不能把呼叫插入等同有效項目。

本機 `analysis/check_v4160_ingress_zero_id.py` 固定原始 guard bytes，在長度低四位為 1 下枚舉 16,384 個通過旗標的標頭：將 byte0 替零使 16,320 個 ID 改變；將 byte1 替零使 14,336 個 ID 改變。普通與 `-O` 均通過。這是手寫算術投影，假設呼叫正常返回、記憶體無干擾，不是 CPU、實機或通訊追蹤；腳本目前只在本機。
