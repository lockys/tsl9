# 查找表資料池正式整合

[English](readme.en.md)

[432-byte C/C++ 資料池](../../src/native/receive/grid_read_windows.c) 已納入正式來源，兩個真實內部 DATA 標籤通過原位址及 HI/LO 參照驗證。

| 項目 | 結果 |
|---|---|
| 來源 | 152 個 C/H 檔；121 個程式單元＋5 個獨立資料單元 |
| C11／C++17 原始與整理版比對 | 252 組、504 個物件；舊 242 組結果及 1,453 筆產物紀錄不變 |
| 原位址逐 byte 相同 | **68,265／76,800 bytes＝88.89%**；程式 64,544B＋資料 3,721B |
| DATA 標籤 | 4 個舊標籤完整保留，新增 2 個，共 6 個，均有實際資料支撐 |
| 未解參照 | 24→22；2 個直接入口＋20 個資料位址參照 |
| 流程 | 21,938 指令、4,245 個直接轉移、4,861 筆重定位；普通順序位置缺口 0 |

資料池範圍為 `0x19ED8..0x1A088`，兩個零配置標籤偏移為 0／320。432 bytes 是兩條選定讀取路徑之保守視窗聯集，沒有假定 nibble 只會是 0–9，也不是原始陣列宣告大小或全域執行界限。第三張 `0x1A078` 表仍未提供相依；其 `AND 7` 修改 A3，而實際查表索引仍使用 A4。

拆分器只排除兩個無重定位參照、位於非 ALLOC `.comment` 的本機 `$d.1` 編譯器標記；其餘實際符號角色與重定位均核對保留。舊流程 v2 收據保留於本機；修正摘要硬編碼後，以新 v3 收據為準。

這是位元組覆蓋率，不是功能完成率或可刷入比例。診斷 ELF 的入口為 0、沒有 PT_LOAD；沒有產生 BIN、執行韌體／HOST 模型／ISA、操作硬體或呼叫後端。原機 MCU／ROM／RAM／IRQ／BLE OTA 與私有 ABI 相容性仍未證明。
