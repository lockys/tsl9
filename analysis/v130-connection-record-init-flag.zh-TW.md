# V1.30 resident：初始化旗標的寫入來源

唯讀核對 V1.30 參考 BIN（基址 `0x40000`，SHA-256 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`）。接續[初始化上游](v130-connection-record-init-caller.zh-TW.md)。

- 已核對三個直接呼叫 `0x606f8` 的位置：`0x59eaa`、`0x6a17a`、`0x6dac0`。單憑呼叫點不能排序，也不能排除其他呼叫方式。
- 在旗標為零的分支中，`0x6070e` 呼叫 `0x43afe`，返回後立刻從 `0x60712` 呼叫 `0x534d0`，中間沒有重設 `a0`。`0x43afe` 的返回段 `0x43b24` 將 `a5` 移到 `a0`；另一分支 `0x43b28` 明確先將 `a5` 設為 `255`，再跳到共用返回段。這不是將呼叫前的輸入指標原樣傳給 `0x534d0`。
- `0x534e4` 把入口 `a0` 存到 `s0`。若中途呼叫正常返回、`s0` 保持不變，`0x5350a` 把其低 byte 寫入門檻讀取的同一位址 `0x2000304f`。這是**首次讀到零之後**可發生的寫入，不是首次讀取前旗標為零的證據；若回傳低 byte 為零，此寫入也不會把旗標變成非零。
- 在旗標寫入之前，`0x534f2`/`0x534f6` 已以 `(0x20003268, 0, 296)` 呼叫 `0x2000039c`。若候選填值函式已載入且正常完成，清除區間為 `[0x20003268, 0x20003390)`，已包含串列的頭、尾和計數，但不包含 `0x2000304f`。因此 `0x53658` 所在的窄範圍清除不是此分支中唯一可能清空串列的位置。

重算映像雜湊並解碼 7 個 JAL、旗標寫入與前置填值參數，均通過。尚未證明任一呼叫是實機 BOOT 的第一次呼叫、該旗標的最早來源，或清除必然早於第一筆連線建立。
