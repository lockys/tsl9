# v4.1.60：候選排程回呼來自設定區首個 word

接續[指標寫入點](v4160-app-event-slot18-mode-clock-init.zh-TW.md)。固定的 WCH V1.31 參考映像中，`[0x40074]=0x43f46`。在這個入口的成功路徑，傳給 `0x43f9a` 複製呼叫的 `a1`，來自入口 `a0` 所指的設定區，而非可選前置回呼的返回值：

- `0x43f56` 將入口 `a0` 搬到 `a1`；若 `[0x2000321c]` 為零，直接進入 `0x43f64`。若非零，`0x43f5e` 先保存入口指標，`0x43f60` 呼叫該前置回呼，`0x43f62` 再從保存槽載入 `a1`。後者以回呼正常返回且保存槽及堆疊基址未變為前提；記憶體內容本身仍可能經回呼改變。
- 續段檢查指標與設定欄位。若通過檢查、候選 copy 如預期複製 16 bytes 且正常返回，`0x43faa` 寫入 `0x200031e0` 的值便是複製當時設定區的首個 word。不能由此判斷 APP 實際傳了哪個設定區，或實機的指標值。

Python `-O` 核對候選映像 SHA-256、來源轉移與保存槽運算元、四個分支目標、複製目標及 `0x40074` 的候選對應。下一步回到 APP，核對 `[0x40074]` 的呼叫位置及設定區首個 word 的來源。未連接設備或修改原 BIN。
