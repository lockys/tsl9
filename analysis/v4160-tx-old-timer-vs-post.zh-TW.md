# 新 TX 的設位不會替舊重試計時器改期

以下區分同一任務 `i` 的兩份狀態：pending 表中的事件半字，以及計時串列中鍵為 `(i,2)` 的節點。前提是登記與 bank 綁定穩定、表和節點不重疊、正常返回且無其他寫入。APP 是 v4.1.60 原 BIN；服務語意是 V1.31 參考，不是裝置觀測。

|時點|指令證據|對未到期舊節點的意義|
|---|---|---|
|新 TX 已接納並完成組框|`0x8b32/36` 寫總長、清游標；`0x8b46..50` 尾跳 `[0x40050](i,1)`|設位服務只對合法 ID 的 pending 半字做 OR，沒有計時串列查找。這個動作不取消、不改期。|
|事件 1 成功準備片段|`0x8732..3c` 重設重試數並經同一槽立即設位 2|即使舊節點仍在，也不靠它設位；兩者可以同時存在。|
|後續重試要求|`0x87f2..f8` 經 `[0x40058](i,2,2)`；參考 `0x43808` 呼叫按任務與事件查找的 helper|若通過前置檢查並命中尚在的同鍵節點，`0x43812` 改寫其 `+8` 期限；未命中才嘗試配置。名義設定因子 16000 不變時，新期限相對本次時鐘取樣加 20 個計數，不是從舊期限加 20。|

若舊節點先到期、成功設位且正常摘除，設位時 bit 2 已存在便合併，不會累計；若先前的 bit 2 已交付且槽已清，舊節點可再次設位。之後是否同輪派送還取決於返回遮罩與取消遮罩。**新 TX 不是取消；失敗後再排程才可能改期。** 這不代表實機一定有舊節點或一定重送。

複核：[APP 片段準備](v4160-tx-bit0-to-copy.zh-TW.md)、[設位服務完整 64 bytes](v4160-dequeue-tx-event-leaf.zh-TW.md)、[排程命中及未命中分支](v4160-first-schedule-request.zh-TW.md)、[到期、設位與一次性摘除](v4160-first-timer-due-post.zh-TW.md)。排程報告中的 192000 是另一呼叫點的延遲，本處代入 2，不沿用其期限。
