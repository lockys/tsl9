# 任務 7 第一次取出的訊息是否就是新入列的那一筆？

以已入列、已設 0x8000 的合成 RAM 進入排程掃描，再從選中任務的狀態分析候選 V1.31 resident。0x465d8 檢查事件 bit 15；成立時不是直接沿用 a0，而是 0x465e0 重讀 U8[0x200033ac]，在 0x465ec/465f0 呼叫 0x2000028c。此處繼承值為 7。

從 [0x20003198] 讀佇列首指標，與各訊息前兩個位元組處的目的 ID（單一 byte，即 M−2）比較，循 M−8 的 word 鏈結前進。找到第一個符合的指標後仍繼續找第二個；0x4319c 解下第一個，將其 link 清零、目的欄設為 255。若有第二個符合者，走重設待處理事件的呼叫，否則走清除呼叫；假設兩者正常返回。0x200002fa 回傳第一個符合者，未找到則為零。

128 份原空佇列的新增訊息均被選回；128 份原有一節點的 fixture 只提供舊節點鏈結，沒有其目的 byte，故不能直接判定。分別指定舊目的為 6 或 7：前者取新、留下舊首；後者取舊、留下新首。另將接收 ID 改為 5 而兩目的為 6、7，均返回零且不改鏈結。一般及 -O 各驗證以上 128+256+128 個確定結果。這是核對原指令窗的離線投影，不是硬體或已安裝 ROM 的執行紀錄，亦未驗證後續訊息內容處理。
