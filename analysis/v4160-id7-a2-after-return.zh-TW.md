# A2：返回 1 的下一步

前文：`v4160-id7-a2-key-route.zh-TW.md`。此段是 WCH V1.31 候選常駐程式，非 v4.1.60 APP 內獨立存在的函式。以下依候選 RAM 映射、正常存取、堆疊與保存寄存器不變及必要呼叫返回，非實機證據。

- `0x46648` 呼叫 `0x4572c`；返回到 `0x4664c` 後直接跳到 `0x467a4`。這裡判斷完整 a0 是否非零，不是只看低 byte 或對照常數 1。非零跳 `0x4666e`，把 s0 中原訊息指標 M 當作唯一參數呼叫 `0x431ba`。
- 結果為零才檢查先前採樣的 s4（不是重讀 RAM）。s4=255 也走 `0x431ba(M)`；其他值呼叫 `0x43208(s4,M)` 要求轉送，返回後直接跳 `0x46674`，不在這裡再呼叫 `0x431ba`。
- `0x431ba` 在暫存、清零外設字和 fence.i 後檢查 M。空指標返回 5；非空但 M−2 的 byte 不等於 255 返回 4；等於 255 時 `0x431f8/431fc` 呼叫 `0x20000110(M)`，不是 M−8。若正常返回則設定結果 0 並恢復外設字。到此只能證明發出釋放呼叫，尚未驗證該次堆積修改。
- 兩條路都匯入 `0x46674`：重新從 sp+24 載入基址，再從基址+940 取任務 ID（覆寫 a0），呼叫 `0x2000028c` 取下一筆。非空回 `0x46632`；空則返回原 s2 事件遮罩 XOR 0x8000。不能由第一次的返回 1 推斷下一次一定有訊息。
- 驗證：一般 Python 和 `-O` 各跑 6144 個路徑組合，含非零高位、所有 s4 byte、四個訊息旗標，另有空指標對照。在沿用上輪 RAM 的 128 個 A2 案例，結果 1 與 M−2=255 共同導向 `0x20000110(M)`。測試是以固定映像查核位元組的有限分支模型，不是全系統模擬。此提交僅發布報告。
