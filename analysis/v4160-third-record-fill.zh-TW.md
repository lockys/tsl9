# 第三筆記錄區：配置地址與清零範圍

目的：沿用 v4.1.60 APP 與 V1.31 參考程式的合成執行狀態，不在第三次配置入口重建堆積或注入返回值。

第二筆標記 0x4c05 的請求為 0 或 4080 bytes；兩者均接第三筆 60 bytes、標記 0x4c06。在 64 條本機路徑中第三筆均非空。按第二筆結果分組，第三筆資料首址集合：

- 第二筆返回空：0x200049e0、0x20004a28、0x200059d8。
- 第二筆配置 4080：0x200059d8、0x20005a20、0x200069d0。

固定其他輸入，第二組相對第一組增加 4088（4080 資料與 8-byte header）；不同第一筆大小可以得到相同的第三筆地址，所以單憑地址不能反推第二筆結果。

從第三次配置返回 0x4dba0 到 0x4dbc2：0x4dba4 存 P 至 0x20003318，非空分支再讀 0x200033b4（5），執行 fill(P,0,60)。填寫函式先讀取並清除 0x4002420c，順序對 P 到 P+59 各做一次 byte 零寫入，再寫回先前的暫存器樣本。與已配置的前兩筆資料無重疊。此區段的有序讀寫與範圍在一般 Python 和 -O 的本機重播中均通過。

界限：依賴候選 ROM、Xwchc 解讀、合成堆積與外設樣本、成功存取；不保證真機地址、外設效果或配置必成功。未改動原始 BIN。
