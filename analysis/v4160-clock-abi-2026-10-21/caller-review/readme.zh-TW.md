# 原始時脈函式的呼叫端要求

**只保留原函式未修改的暫存器，仍不足以證明 query 可直接替換原入口。** 原始 query 依路徑產生的 A3 會穿過已知初始化流程，進入尚未確認的間接 callback。不能僅因標準 C 呼叫慣例或公開介面為 `void`，就以入口 A3 取代這個原始輸出。

本審查讀取原始 ID2966 runtime SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`，重用已封存的 214 位元組／69 條時脈指令及 9A42/helper ABI 證據。新增呼叫端來源共 **298 位元組、98 條指令**，分為 main `0x9008..0x901A`、init `0x9250..0x9290`、中間 `0x9A42..0x9AD2`、後續 `0x9F4C..0x9F74`、下一個 callee 前綴 `0x131C2..0x131E2`。`verification.json` 保存原始位元組、位址、指令列、直接跳轉候選與來源 seal；`caller-contract.json` 整理要求及限制。

## 精確的正常呼叫鏈

| 呼叫位址 | 目標 | 返回 link |
|---|---|---|
| `0x900C` | init `0x9250` | `0x900E` |
| `0x9254` | query `0x18834` | `0x9258` |
| `0x9258` | 中間函式 `0x9A42` | `0x925C` |
| `0x925C` | 派生欄位 `0x1973C` | `0x9260` |
| `0x9260` | `0x9F4C` | `0x9264` |
| `0x9264` | `0x131C2` | `0x9268` |

Init 在這些呼叫之間沒有本地參數暫存器準備。原始兩個時脈函式不寫 RA、SP；在控制流程未被改變的正常路徑，以呼叫端剛設定的 link 返回。Init 自己將 SP 減 16，RA 存於 SP+12，稍後重新載入、SP 加 16，再 tail jump 到 `0x17BF6`。新增原生函式的堆疊寫入與最終 SP 還原是另一個要求，僅比對最終暫存器不足以證明新堆疊存取符合實機記憶體與中斷環境。

## 具體暫存器存活情形

原始 query 只寫 A2–A5。A2 在預設與內部路徑保持原值，外部倍率路徑設為 `0x00C00000`。A3 在 selector 4 為 4；selector 0、12 為 8；內部倍率路徑為 17；外部遮罩相等路徑為 `0x40021000`；外部 fallback 則為新 config 左移 14 後的低 32 位元。A4 最後是零擴展的 live table byte，A5 是新 scalar word 右移後的結果。

原始派生函式只寫 A4、A5：A4 最後是 1000，A5 保留完整的 `(((uint32 scalar / 8000000) & 255) * 1000)`，雖然記憶體 halfword store 只寫低 16 位元。此函式不改變 A0/A1/A2/A3。

在已審查且正常完成的同步前綴中，query 入口 A0/A1 與輸出 A4/A5 在 `0x9A42` 先被覆寫，才可能被讀取。派生函式的 A4/A5 在 `0x9F4C` 被覆寫後才使用。下一個 `0x131C2` 在首次 callback 前，分別於 `0x131CA` 覆寫 A1、`0x131CE` 覆寫 A2、`0x131D8` 覆寫 A0。這些只是限定同步路徑的本地 deadness，並非全程式或非同步證明。

**A3 中途沒有新的定義。** 實際 9A42 與 helper 保留 A3，派生函式保留 A3，9F4C 只改 A4/A5。下一個 callee 在 `0x131C6` 從 `0x4004C` 讀取 function pointer，`0x131E0` 透過這個新 pointer 執行 JALR，將 query 產生的 A3 帶到未知目標。其實作與 prototype 未獲證明，因此不能斷言 A3 被使用，也不能斷言被忽略。這是具體尚待處理的呼叫端要求，不是已找到第四個 C 參數或還原原始 prototype。

## 邊界與待補證據

中間函式在 `0x9A50` 清除 CSR `0x800` 的 `0x88` 遮罩，於 `0x9AC2` 設回同一遮罩，沒有保存、還原舊 CSR。這無法證明兩個時脈呼叫期間不會發生中斷，也無法證明所有 handler 都保存所需暫存器。本審查不假設非同步 handler 或實機 ROM callback 的行為。

有限掃描涵蓋該映像 **38,400 個 halfword 對齊位置**，解碼 JAL 與 RV32 C.JAL/C.J 目的立即值；對 `0x9250`、`0x18834`、`0x1973C` 只找到三個已具來源證據的呼叫 `0x900C`、`0x9254`、`0x925C`。這是 raw-format 候選掃描，未證明 code/data 分區、排除特殊入口邊界、分析計算式 JALR 目標、還原 pointer callers，也未證明不存在其他呼叫端。

若要宣稱一般性直接替換，仍需證明原函式完整且相關的輸出暫存器契約、返回／堆疊相容、連結位置及其他呼叫端，加上實機中斷／ROM／硬體環境。派生 A4/A5 在這一段前綴未存活，並不代表全域無關。本審查不執行 firmware 或 ISA emulator，不進行網路或硬體 I/O。可用 `audit.py --image <原始 BIN> --r2 <radare2 路徑>` 重現唯讀來源核對。
