# 時脈暫存器保留與編譯可行性

實際 Clang 18 建置已建立暫存器配置更受限的 C／C++ 候選。最終查詢函式為 **196 位元組、64 條指令**，原始為 174 位元組；欄位函式為 **38 位元組、10 條指令**，原始為 40 位元組。查詢函式仍超出原範圍 22 位元組，本階段尚不能直接替換原映像。

兩個單元分開編譯。查詢只允許配置器使用 X13–X15，欄位函式只允許 X14–X15，其餘以 `-ffixed-xN` 保留。查詢的 X12 只經明確的外部遮罩基元設定。每條實際指令的目的暫存器位元欄位都會與反組譯文字及原始寫入白名單交叉核對。輸出元件的兩個函式保留 A0／A1，沒有 SP／GP／RA 寫入、堆疊存取、隱藏呼叫、未定義符號、可寫資料或冒充原始符號的別名。

欄位函式實際使用無符號 `DIVU`，保留 GP+382 的 byte 寫入及 GP+380 的 halfword 寫入，並符合完整直線指令模式，可支持一般返回時 A4=1000、A5=(新讀 GP+108 值 DIVU 8000000 & 255)*1000。byte 寫入使用未遮罩商的暫存器，其低八位與遮罩後的商相同。中間暫存器指派順序仍不同，不能宣稱逐點暫存器或非同步 IRQ 等效。

查詢 C 程式保留各分支的 A3 公式，僅在外部 PLL 路徑設定 A2。編譯證明涵蓋全部 196 位元組、獨立檢查每條指令的目的欄位，並檢查完整、內部、無循環的 CFG，包含中途 RET 與其後的備援分支區塊。它不執行分支條件，也不證明查詢機器碼的完整語意。獨立 hosted 測試驗證共用 C 計算、記憶體效果與暫存器承諾。僅限制可寫暫存器並不足夠：來源 A3 會經後續呼叫保留，進入下游未知 callback。

C11 與 C++17 都實際編譯並連結出 `COMPONENT-ONLY-NOT-FIRMWARE.elf`。每種模式均將三個控制版本實際編譯、連結後拒絕：寫入 A0、寫入 SP，以及錯誤的最終 A4。每種模式另有十四個反組譯控制，拒絕遺失／截斷指令、竄改位元組、只改文字目的暫存器，以及無法解析的行。驗證器逐位元組與目的欄位比對，確認 RV32IMAC／RVC／soft-float 屬性，拒絕跳出範圍、CFG 循環、隱藏輔助程式或不支援的指令形式。

## 有限實驗與未採用方案

一般時脈 C 會破壞 A0／A1；只保留這兩個暫存器仍可能寫入 A6。把較舊的記憶體效果版查詢限制在原始可寫子集內，可產生 174 位元組，但未保留必要的 A3 殘值。舊欄位 C 需要第三個暫存器，在 SP 及 A4／A5 之外全數保留時會編譯失敗。一般常數除法產生 magic multiplication；`-Oz` 或明確的 DIVU 基元雖可縮小，但複製 GP 值仍留下 42 位元組。

以空 volatile asm 的輸出綁定實體 GP，省去不必要的 GP 複製，且不產生 GP 指派；GP 保留仍依實際反組譯確認，不能只靠來源宣告。要讓欄位函式的最終 A4／A5 正確，還須在乘法前加入空的 A4 read/write barrier；只有最終 input 承諾會產生 42 或 46 位元組。採用不透明的 A2 外部遮罩後，查詢可避免配置器失敗。另一次 A3 比較常數重用實驗仍要求 SP，已拒絕；此後未再擴大搜尋。

早期一份 GP 探索腳本誤將反組譯字串當成下一個最佳化版本的 C 來源。其錯誤來源失敗產物留存本機，但不作為工具支援與否的結論；已用修正後的六個設定重做。新產品標頭曾缺少 native macro，也已修正，之後凍結四個 C／標頭並獨立重建。`results.json` 記錄最終收據與相關探索報告。

## 重新原生建置

需要 Python 3.10 以上及支援 RV32IMAC 的本機 LLVM。在發布的專案目錄執行：

```sh
python3 analysis/v4160-clock-abi-2026-10-21/compiler-review/verify_compiler.py \
  --project-root . --tool-dir /path/to/llvm/bin --language both
```

也可用 `--clang`、`--linker`、`--objdump` 分別指定工具。分析工作區前綴為 `apk-analysis/tsl9-v4160-clock-abi-2026-10-21/`；發布版本為 `analysis/v4160-clock-abi-2026-10-21/`。新建置只需目前四個 C／標頭、本地 `elf32.py` 與 LLVM，不需要舊有被忽略的原映像建置封存。已驗證工具為 Android NDK 27.1.12297006、Clang 18.0.2，使用 RV32IMAC／ILP32、`-Os`、freestanding／no-relax，以及各單元的保留旗標。不同編譯器若超出此證明器支援形式，會明確失敗。

`check_compiler.py --project-root . --require-local-builds` 可唯讀重播保留的原生與 hosted 收據。省略最後旗標時會明確列出缺少的封存，只驗證中繼資料及目前來源，不代表重新編譯。`probe_*.py` 是使用固定本機工具路徑的 Windows 有限探索紀錄；跨平台新建置入口為 `verify_compiler.py`。物件、ELF、日誌及一次性候選只保留本機。

完整原始 ABI、逐點暫存器行為、IRQ、原始佈局、實機 ROM、硬體及藍牙 OTA 仍未證明。舊原生映像檢查保持不變。沒有產生韌體 BIN、沒有執行 RV32 或模擬 ISA，也沒有硬體 I/O 或網路操作。
