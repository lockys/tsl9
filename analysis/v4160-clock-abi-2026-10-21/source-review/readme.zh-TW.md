# 時脈函式：原始暫存器輸出與原生檢查限制

本輪沿用已封存的 ID 2966 V4.1.60 證據，SHA-256 為 `ebf0521f52c5142d1dc7969aaca17bb1c7567065165eba4c88fd4523e30b6a51`。查詢 `0x18834..0x188E2` 與衍生欄位 `0x1973C..0x19764` 合計 214 位元組、69 條指令；原始映像 SHA-256 為 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。

以下正常返回結果以原始程式、每次記憶體操作正常完成、沒有額外的外部暫存器修改或陷阱效果為前提；各次外部記憶體讀取仍可得到不同數值。這是靜態資料流結論，沒有執行原始程式，也未證明實體中斷模型。

## 精確的整數暫存器寫入集合

| 原始函式 | 可能明確寫入的暫存器 | 命名寫入目的地的指令數 | 本體未寫入的整數暫存器 |
|---|---|---:|---|
| 查詢 0x18834 | x12/A2、x13/A3、x14/A4、x15/A5 | 44 | x1..x11、x16..x31 |
| 衍生欄位 0x1973C | x14/A4、x15/A5 | 8 | x1..x13、x16..x31 |

這是完整範圍內的靜態指令數，包含互斥分支，不是實際執行次數。寫入值也可能恰好等於舊值。x0 維持架構定義的零；兩個函式都是葉函式，沒有呼叫、SP 調整或明確寫入 A0、A1、GP、RA。返回指令原始位元組都是 `8280`，即 `jalr x0,ra,0`，跳往當時 RA 並清除最低位元，不改寫 RA。

本輪檢查直接讀取原始指令目的地欄位，不解析助記符，也不執行指令。僅辨識舊封存中實際出現的指令類別；完整位元組、運算元與 50 個負向案例仍由原始證據檢查負責。

## 查詢函式的最終殘值

第一個 RCC 取樣的 `sample & 12` 決定選擇分支；0x18864 是最後一次無號表格 READ8，0x1886C 是最後一次新的純量 READ32。

| 分支 | 最終 A2 | 最終 A3 |
|---|---|---|
| 選擇值 4，使用 32000000 | 進入時的 A2 | 4，最後寫於 0x1883A |
| 選擇值 0 或 12，使用 8000000 | 進入時的 A2 | 8，最後寫於 0x18842 |
| 選擇值 8，獨立取樣的來源位元 16 未設定 | 進入時的 A2 | 17，最後寫於 0x18890 |
| 選擇值 8，來源位元 16 設定，下一次取樣位元 22、23 均設定 | 0x00C00000，寫於 0x188B6 | 0x40021000，最後寫於 0x188B0 |
| 選擇值 8，來源位元 16 設定，下一次取樣位元 22、23 非均設定 | 0x00C00000 | 隨後再一次新的 RCC 取樣左移 14 位，保留低 32 位，最後寫於 0x188D0 |

0x18896 將倍率 17 改成 18 時，改的是 A5，**不是 A3**；內部來源分支最後 A3 仍是 17。外部 fallback 的 A3 保留完整的移位值，不只是正負號或分支判斷位元。各條件必須使用各自的獨立取樣，不能合併成一個快取 RCC 值。

所有正常返回分支的最終 A4 都是 0x18864 無號讀入並零擴展的表格位元組；最終 A5 是 0x1886C 新讀取的純量邏輯右移 `(A4 & 31)`。最後 WRITE32 不改動這兩個暫存器。A0、A1 保留輸入值，A2 只在上述非外部分支保留；GP、SP、RA 由本體保持不變，但仍受外部效果前提限制。

## 衍生欄位的最終殘值

令 `q8 = (uint32(新讀取的 GP+108 純量) / 8000000) & 255`。最終 A4 是 0x19756 寫入的 1000；最終 A5 是 0x1975A 產生的完整 32 位元 `q8*1000`，範圍為 0..255000。0x1975E 的 WRITE16 只把低十六位寫入記憶體，不會把 A5 本身截斷。0x19752 的 WRITE8 也不會重讀或替換保留的商。

例如純量為 528000000 時，q8=66、最終 A5=66000，但寫入的半字為 464。讓 A5=464 返回雖可符合記憶體結果，仍違反原始暫存器輸出。第二個函式沒有改寫 A2、A3；它們可能保留更早呼叫的殘值，不能自行填入猜測常數。

## 原生寫入檢查能證明什麼

在範圍明確、完整且正確解碼、沒有未分析呼叫或轉移的前提下，靜態掃描可以證明所有明確整數寫入目的地都在 allowlist 內。遇到未知編碼必須拒絕，不能跳過。隱含效果、CSR、浮點／向量狀態及系統指令需要另外檢查；只看一般 rd 欄位不足。

allowlist 本身不能證明允許寫入的暫存器最終值、返回位址、SP 暫時或最終狀態、記憶體順序、寬度與新取樣。把 A2..A5 全部恢復成輸入值，雖然保存了所有未動暫存器，仍可能違反查詢函式的輸出。衍生欄位若讓 A4 任意或把 A5 截成十六位，也可能通過 x14/x15 allowlist，卻不符合原始語意。「沒寫某個允許寫入暫存器」不必然代表成功。

檢查 C 最終二進位是否保存 A0、A1，比只依賴 `void` 宣告更有力，但仍不能證明 A2..A5 輸出或所有架構效果。組合語言 adapter 若只保存並恢復全部暫存暫存器，仍需另外設定原始輸出，否則是另一種可觀察契約。一般 C ABI 的假設不是原始二進位 ABI 的證據。

## 省略輸出要求前所需的呼叫端證據

須先確定所有實際呼叫與入口，包括適用的間接或 resident／ROM 呼叫。對每一個不同的輸出暫存器，證明它在任何讀取、分支、寫入記憶體、傳遞參數、轉送回傳值或不透明函式使用之前，都會先被覆寫；並涵蓋其他延續路徑及適用的中斷／陷阱進出。單看下一條指令、單一合成呼叫端或 caller-saved 慣例，不能證明整個二進位中的 deadness。未知的呼叫端或中斷行為，仍是未解決要求。

還需確認 adapter 的輸入／返回暫存器、GP 相對位址、堆疊對齊與儲存、RA 返回方式。實體 MCU、resident ABI 與 OTA 相容性則是其他未通過的關卡。本輪不宣稱原位替換相容或可燒錄。
