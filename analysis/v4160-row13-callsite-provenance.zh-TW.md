# v4.1.60：第 13 列重播的呼叫來源

離線對照原 BIN SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`，APP 位址基底 `0x8000`。以下為靜態局部路徑，不表示執行時可達、呼叫一定返回或硬體行為。

令 S 為 byte[gp+240]、F 為 byte[gp+237]、M 為 byte[word[gp+84]+9]&0xc0，S、F 和 M 以下均指相應位置當時讀到的值。

| 到 `0xfda6` 的直接轉移 | a0 | 條件與順序 |
|---|---:|---|
| `0xd5a2` JAL | `0xd578` 入口 a0 原值 | 零擴展 S 不等於完整入口 a0；先將其低 byte 寫入 S，M=0x40。此路徑在呼叫前無其他函式呼叫。 |
| `0xd5d4` JAL | 1 | 後續讀得 F=0、S非零、入口 a1 非零；先寫 F=1，再讀得 M=0x80。 |
| `0xd624` JAL | 0 | 後續讀得 F非零、S=0；先寫 F=0，再讀得 M=0x80。返回後仍可能走至 `0xd602`。 |
| `0xd602` tail jump | 0 | 共用路徑中 `0xfda0` 返回 1 且 `0x10402` 返回無號值不大於 8；先恢復堆疊再跳。 |

`0xd5a2` 前的 `sb` 不改變 a0。合成例子：入口 a0=0x100、S=0，記憶體寫入仍為 0，但傳給 `0xfda6` 的完整 a0 非零。這不是可達性證明。經過 `0xd5a2` 或略過該呼叫後會呼叫 `0xd53c`，故後續 F、S 必須以重新讀取為準，不能假定保持先前值。

兩個已識別的直接上游轉移 `0xd646`、`0xd65e` 分別來自 `0xd632`、`0xd64a`：前者 a0=(halfword[record+6]>>6)&1，a1=(byte[record+8]>=38)；後者 a0=(halfword[record+4]>>9)&1，a1=(byte[record+6]>=81)。這兩處均 tail jump 至 `0xd578`，其 a0 確實只為 0 或 1；不能因此排除其他入口或間接呼叫。分支達到 `0xfda6` 也不保證該函式會讀取或處理記錄。

本機 `analysis/check_v4160_fda6_callsite_provenance.py` 固定 BIN 雜湊及選定指令窗、解碼六個 JAL 目標和 rd，窮舉 131072 個半字位元抽取與 512 個閾值例子，一般及 Python `-O` 均通過；數學枚舉不是獨立 CPU 執行。未修改 BIN、正式來源或既有 staged 工作，未連接設備。
