# 選擇值 5 的記錄：誰讀取任務 ID 255？

對象是 v4.1.60 APP 搭配的 V1.31 **候選** resident（SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`）。以下是靜態路徑，不代表已安裝或已執行。

- 在 `0x4dfd8` 呼叫正常返回 0 的路徑，`0x4dfe0..0x4dfea` 取表基址 `0x20003320`，讀 `+12` 的半字；測的是**非零**，不是與 5 比較。這正是初始化曾寫入 5 的位置。零值支線不讀 ID。
- 非零支線 `0x4dff4` 從 `+14`（`0x2000332e`）讀無號 byte 到 a0；`0x4dffc` 呼叫 `0x4e2ee`，沒有把 255 轉成別的 ID。兩個壓縮讀取 `5e25` / `6825` 按候選 Xwchc 解碼，不採通用反組譯器的浮點解讀。
- `0x4e2f2` 以 s1 保存 ID，申請 32 bytes；若取得非空指標，後續複製或填充正常返回且遵守保存暫存器慣例，`0x4e33c..0x4e348` 以 `(ID, message)` 尾跳 `0x43208`。
- 非空 message 路徑 `0x43230` 重讀 `U8[0x2000319d]`（task count）；`0x43238` 是無號 `ID >= count`，成立就去 `0x43242` 呼叫 `0x431ba`，若正常返回則恢復周邊字並回傳 3。窮舉 byte ID/count：32,896 / 65,536 對走此分支，其中 ID=255 為 256 / 256。這是範圍檢查，不是 `ID == 255`；低於 count 仍有後續檢查，不能反推訊息一定成功。

已核對來源 hash、兩個 Xwchc 讀取的暫存器及位移，以及 `0x43238` 原碼的 unsigned funct3、暫存器與目的位址。本次沒有做跨配置器與複製函式的連續執行，也不是所有消費者的普查。
