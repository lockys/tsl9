# v4.1.60：候選排程回呼指標的兩個直接寫入點

接續[候選早退條件](v4160-app-event-slot18-mode-early-return.zh-TW.md)，本輪追查第二道檢查所讀的 `0x200031e0`。在固定 WCH V1.31 參考映像中：

- `0x43b56` 建立基址 `0x20003000`，`0x43b62` 把 `0x200031e0` 清為零。
- `0x43f96/0x43f9a` 呼叫候選 `0x20000332`，入口 `a0=0x20003234`、`a2=16`。若正常返回至續段，`0x43fa2` 從 `0x20003234` 重讀首個 word，`0x43faa` 將該值寫入 `0x200031e0`。這個指標不是在此處載入固定函式位址。尚未確認 copy 來源、這兩個寫入點在模式 1 路徑前的實際順序，或其間是否另有寫入。

Python `-O` 核對映像 SHA-256，掃描 95,538 個半字起點內具有 `+0x1e0` 或 `-0x220` 位移的 32-bit `SW`，並驗證兩個命中的基址／來源欄位與前置呼叫目標。這個篩選不涵蓋其他基址、壓縮 store、間接 copy 或別名，不能當完整 writer 清單。下一步追 `0x43f9a` 的 `a1`，判斷哪個輸入欄位供應初始指標。未接設備，未修改原 BIN 或正式來源。
