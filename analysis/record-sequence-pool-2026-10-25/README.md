# 序列資料池 C/C++ 實驗

[English](readme.en.md)

本輪新增 [C/C++ 唯讀資料池](../../experiments/tsl9-record-sequence-pool/src/record_sequence_pool.v1.c)，並以真實內部標籤接上三個原始資料參照。這是**獨立編譯與實驗連結**，尚未納入 `src/` manifest 或正式原位址元件。

## 資料範圍與標籤

原始來源常數為 `0x1A430`、`0x1A454`、`0x1A478`，局部設定的非零上限為17或53。將三個來源與兩個上限獨立配對，可得到六個條件式讀取窗口；其聯集為 `0x1A430..0x1A4E2`（尾端不含），共 **178 bytes**。

這個範圍保留已知來源與已知上限交錯時的相對位置，不依賴三個理想設定一直維持配對。它不是任意RAM值的全域讀取界限，也不是原始陣列宣告長度。

| 符號角色 | 原始位址 | 池內偏移 | 配置 bytes |
|---|---|---:|---:|
| 唯一實際資料 owner | `0x1A430` |0 |178 |
| 原始來源標籤1 | `0x1A430` |0 |0 |
| 原始來源標籤2 | `0x1A454` |36 |0 |
| 原始來源標籤3 | `0x1A478` |72 |0 |

三個標籤都有真正的 readonly section backing；沒有用ABS位址冒充資料，亦未重複配置同一批 bytes。

## 驗證與新發現

- 重新擷取245條原始指令，核對來源選擇、RAM欄位、上限常數、回呼與停止路徑。
- `0xEEBE` 的32-bit零寫入同時清除索引與上限，然後才呼叫 `0x90B0`。這不證明回呼已完全停止或不可重入。
- `0xF0B0..0xF0C6` 向ROM槽位 `0x40048` 傳入從 `0x2000BF84` 開始的12-byte零填參數；若安裝中的槽位遵循快取SDK的memset契約，範圍會包含來源指標。安裝中的ROM與ABI尚未確認。
- C11／C++17 的資料物件與實驗元件分別完全相同；雙ELF解析器的節區、bytes、符號與重定位全部一致。
- 實驗元件保留64,544B程式與原3,111B資料，加上178B資料池；三個參照以真正標籤解決，未解參照 **27→24**，4,861個重定位角色保留。
