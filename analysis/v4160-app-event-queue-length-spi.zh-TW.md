# v4.1.60：SPI 接收分支如何填入佇列長度

接續[佇列暫存來源](v4160-app-event-object-queue-source.zh-TW.md)與[過濾器的長度處理](v4160-app-event-queue-length-filter.zh-TW.md)。本輪只核對一般 SPI 接收分支與佇列寫入點，不推論其他來源或第 18 槽分支一定會執行。

- `0x16ad6..0x16ae6` 取 `sp+20` 的低四位，並以 `((length-1)&255) <= 7` 篩選。通過此處檢查的值為 1–8；`0x16afa` 呼叫 `0x12bc8` 時以 `a2` 傳入該值。這是單一呼叫點的條件，不是全佇列或下游分派器的上限。
- 寫入函式由 `0x12bd2/0x12bd6` 建立與消費端相同的數值基址 `0x2000c038`，使用 12-byte 槽步距。找到空槽後，`0x12bfa` 以 `sb a2,2(s0)` 明確寫入長度。正常的 SPI 長度 1–8 下，從 `+3` 開始的資料複製區與 `+2` 長度、`+11` 標籤不重疊；這仍假設間接函式遵循按參數複製的語意。
- 由此可分開描述長度初始來源、佇列暫存及後續消費；目前尚未證明哪個來源實際供應第 18 槽更新分支。

Python `-O` 核對原 APP SHA-256、兩段指令窗、SPI 呼叫目標及佇列基址，並通過 256 個原始長度值與 256 組槽／長度組合的離線投影。未執行韌體或設備。下一步對照既有 C 重建的寫入順序與欄位寬度。
