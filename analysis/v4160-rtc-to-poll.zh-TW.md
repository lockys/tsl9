# RTC 原始樣本如何變成輪詢值？

銜接 [APP 成對讀取](v4160-rtc-sampler-pairs.zh-TW.md)與[參考累計時鐘](v131-poll-clock-join.zh-TW.md)。這次不再注入除法商：先依序供應合成的高低半字讀值，在 APP `0x191c6` 指令取得 x，再從 V1.31 參考 carrier 取出 `0x6df1a` 函式與查表資料，依候選 Xwchc 解碼執行。依 `0x43d80..0x43d94` 的輸入配置傳入 64 位乘積 `1600*x` 與零擴展的非零 16 位除數 d；檢查兩個返回字合起來是否等於整數商。累計使用的只是商的低 32 位。

848 組（106 個樣本 × 兩條取樣路徑 × 四個除數）全部相符，含乘積超出 32 位與高半字邊界。以 d=16000、初始 last=acc=0、單調讀值 x=0..100 為例，x=49 時商=4、APP 輪詢值=2；x=50 時商=5、輪詢值=3，首次越過以 0 為基準的 `>2` 判斷。50 是此例的 RTC 數值，不是毫秒或保證的等待次數。

重播：`python analysis/check_v4160_rtc_to_poll.py`，亦測 `-O`。需要兩個指定 hash 的本地映像及 `analysis/slot-40058-offline/rv32_helper.py` 與其 import 依賴；本提交沒有散布映像或該舊解碼器，不宣稱只 clone main 就能執行。這是分段串接，不是連續 CPU 或實機紀錄；未測零除數，也未由此證明任何裝置安裝 V1.31。
