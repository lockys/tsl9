# 模式寫入：從 0x1074c 入口到 0x10776

原 APP 在 0x10752 將入口 a0 存入 s0。到寫入之前依次有四個直接呼叫：0xd272、0xb0fc、0x820c、0x10032。最後兩個 byte store 是不同目的地：0x1076e 清除 0x2000bfb4，0x10776 把當時 s0 的低八位寫至 0x2000bfb5；不是把最後一次呼叫的回傳值寫入。兩個 store 之間沒有呼叫。

| APP 子函式 | 與 s0 及外部程式的關係 |
|---|---|
| 0xd272 | APP 包裝本身不寫 s0，從 0x40048 取目標並尾跳；是否正常返回並保留 s0 取決於實際目標。 |
| 0xb0fc | 將 s0 存於本地框架，再用 s0 指向 gp+192。依次間接呼叫，名義 slot 為 0x40048、0x40080；0xb136 從當時 sp+8 恢復 s0 後，再經名義 slot 0x4022c 尾跳。這次恢復在最後外部呼叫之前，且依賴框架與保存值未被破壞。slot 計算假設基址暫存器保持。 |
| 0x820c | 此處呼叫前 a0=0，本地分支寫零到當時 gp+193，不寫 s0。若 gp 一致、0xb118 的 s0 仍是 gp+192，則兩處寫的是同一 byte；不是模式目的地。 |
| 0x10032 | 再經 0x40048 尾跳；這是取 s0 低八位之前最後一個外部返回條件。 |

隨附 Python 檢查器用原 BIN 比對整圖 SHA-256、四個 JAL、七個操作數視窗與兩個 PC-relative store；一般與 -O 均通過。它檢查指定機碼，不執行呼叫，不驗證裝置 resident、堆疊或實際模式。下一步可把同版本候選 resident 的返回路徑與本表逐項核對，而非將 ABI 慣例當證明。
