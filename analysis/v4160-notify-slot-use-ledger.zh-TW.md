# 三個通知表指標槽：12 處 ADDI 的用途

對 v4.1.60 decoded APP 固定 SHA-256 的離線結果。槽指的是 `gp+96/100/104` 本身，表指標則是從該址讀到的 32 位元值。兩者不是同一個參數。

| ADDI 位址 | 後續讀取／用途 |
|---|---|
| `1367e` | `13682` 取表指標；`1368a` 寫入描述項 +4，不是寫回槽。 |
| `1376c`, `13772` | `a1!=0` 選 +104，否則 +100；匯合於 `13776` 讀指標後寫描述項 +4。 |
| `14b08`, `14be4`, `14c10` | 各由 +96/+104/+100 取指標至 a0，長度 256，再呼叫 `[0x4004c]`。顯式目的參數是表指標；但這三處的 a4 **仍持有槽位址**，不能據此排除被呼叫者使用 a4。 |
| `167ba`, `167e2`, `167e6` | 迴圈由 s3/s4 指向槽；`167c2`, `167ee`, `16814` 重新讀表指標，再加索引取資料，不是把表指標固定在迴圈外。 |
| `1778a` | `1778e` 讀 +104，索引後作為 7-byte 來源；條件分支 `177ba` 再讀同一槽，這次不加索引。 |
| `1799e` | `179a2` 讀 +100，a1 是表指標加 7 倍索引；a0 是 sp+8，a2 是 7。此路徑要求先過索引檢查且輸入 a0 為零。 |
| `17a00` | `17a04` 讀 +100，再取表首記錄 byte 1 的 bit 1；若走對應分支，`17b28` 或 `17b70` 重新取 `[s2]` 到 a1 作為 7-byte 來源。跨呼叫的槽身分以 s2 未變為前提。 |

重播：`python -B analysis/check_v4160_notify_slot_loads.py <decoded-bin>`。以既有 census 核對 12 個產生點，獨立解碼上表 14 個不同 LW/C.LW 的基址、位移和目的暫存器，另以 store 和非零位移變體作負向對照。正常及 `-O` 均通過。這是所列指令的查核，不是全程資料流模擬；未證明任意間接呼叫、其他別名、或非同步寫入不會改槽。沒有接設備。
