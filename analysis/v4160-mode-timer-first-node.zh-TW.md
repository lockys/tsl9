# 16-byte 節點：剛初始化時的第一次配置

接續[游標初始化](v4160-mode-timer-arena-init.zh-TW.md)。本例只問：若設定、啟動複製及 V1.31 Xwchc 解碼前提成立，且尚無其他配置或干擾，一個合法的 16-byte 請求會拿到哪一段？不假定 APP 的計時器是第一個呼叫者。

`0x4314c..0x43157` 在初始游標 `H=0x200043ac` 的標頭寫入後繼 `0x200045ac`、容量 504、標記 0；三個欄位分別在 `+0/+4/+6`。配置器 `0x200000ae` 先讀標記，再讀容量，故初始標頭就符合條件。剩餘 488 大於 8，進入分割分支。

| 位置 | 第一次成功配置後的含義 |
|---|---|
| `0x200043ac` | 原標頭，容量改為 16，標記改為請求的非零標記，後繼改指向新標頭 |
| `[0x200043b4,0x200043c4)` | 16-byte payload。`0x200000f4` 令 `a0=H+8`，成功尾段返回這個位址 |
| `0x200043c4` | 剩餘區塊的 8-byte 標頭；後繼沿用 `0x200045ac`，容量 480，標記為 0 |

容量守恆：504 = 16 + 8 + 480。若恰是此次取得的物件，`node+4` 的四個 bytes 落在上述 payload 內。這不給出任意時刻查找到的節點位址，也未量測堆疊。若後續需回答實際選中哪個節點，應先查 APP 正常初始化順序中該次請求之前是否已有其他配置，不應一直沿用第一個節點位址。

離線檢查：隨附腳本核對候選 carrier SHA-256、6 段機碼及 6 條 Xwchc 載入／儲存的操作數，檢查分割與區間算術。另重跑兩個呼叫端的 16-byte 請求檢查；正常與 `-O` 均通過。非完整指令模擬，不連接設備。
