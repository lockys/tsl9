The actual ID2966 V4.1.60 range `0x1892E..0x18986` independently yields 88 B / 37 rows. Original instructions write only A3/A4/A5 and preserve A0/A1/SP/RA throughout. This is source evidence, not installed hardware identity. `source-ledger.json` comes from the actual firmware and a previously sealed raw decoder, independently of the producer algorithm.

The fourteen ordered effects are: read base+4; read config+24,+0,+28,+4; write base+4; freshly read base+8; read config+12,+16,+8; write base+8; freshly read base+44; read byte config+20; write base+44. Address arithmetic wraps as u32. Original LUI/ADDI fields give masks `E0F0FEFF`, `FFF1F7FD`, `FF0FFFFF`. Seven config fields are full 32-bit words without high-bit truncation. Config+4 shifts by8 and config+8 by1. Byte20 decrements, masks255, then shifts20. Aliasing and callback mutations require sequential fresh reads, not a config snapshot.

The independent HOST harness runs the genuine C/C++ core and synthetic typed I/O through 74 cases / 2904 checks per language. Coverage includes high bits, byte0/1/255, wrapped addresses, config=base/base-8/base-12 aliasing, dynamic changes to later registers/config, all fourteen stop sites with three stop flows, and budgets0..13. A stopped effect is attempted only: a stopped write is not committed and no later effect or cleanup occurs. Three compiled semantic controls per language (mask bit, truncated config word, missing byte decrement) fail assertions. This is not CPU or register execution modeling.

Each HOST TU retains compiler sourceDependencies, actual resource-header hashes, compiler/linker hashes and source hashes. Every launch reparses the local executable machine/width/format before and after execution. Only this synthetic harness runs. An early deeply nested mutant tree hit the Windows include-path limit; that failed archive is retained. The new entry preserves A0/A1 but additionally writes original-preserved A2/A6/A7 and changes normal scratch residues.
