# v4.1.60 佇列 producer 的呼叫邊界

離線檢查原始 BIN（SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`）的 `0x12bc8`。在找到第一個 ID 為零的 12-byte 槽後，`0x12bf6` 寫入 ID 低 16 位、`0x12bfa` 寫入長度低 8 位；`0x12bfe–0x12c0c` 讀取 `0x4004c` 的函式指標並間接呼叫。

呼叫邊界的 `a0` 是槽位加 3，`a1` 保持來源指標，`a2` 保持傳入的完整 32 位長度，`a3` 也保持傳入的完整 tag。`0x12c06` 先將 `a3` 保存到 `s1`；呼叫正常返回後，`0x12c0e` 才將保存值的低 8 位寫入槽位 `+11`。因此把第四參數替換成獨立 context 的 C 投影，對可能觀察 `a3` 的未知 provider 並不等價。這是針對原指令的靜態結論，並不表示實際 provider 一定會讀取 `a3`。

若 32 槽皆非零，這段路徑不呼叫 provider，返回時 `a0` 仍是輸入 ID；若呼叫正常返回，這段後續指令不再賦值 `a0`，故返回的暫存器值取決於 provider。尚未確定呼叫者是否使用這個值，也未證明原始函式的 C 返回型別。未驗證實際 provider、副作用、併發、例外或硬體執行。候選 C 與差分測試仍在本機修正，尚未宣稱正式整合。
