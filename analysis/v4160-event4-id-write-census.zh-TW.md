# 四個事件任務 ID：註冊以外的寫入檢查

在固定 SHA 的 76,800-byte APP 逐半字掃描，檢查以 gp 為基底的 `SB/SH/SW`，以寫入的整個 byte 區間判定是否碰到 +148、+152、+166、+363。僅找到三筆，各為註冊結果的一個 byte。也檢查 `ADDI rd,gp,任意有號位移` 後緊接 `SB/SH/SW/C.SW` 且同一基底的組合；命中零筆。這不是所有地址表示法。

恰好產生四個目標地址的 `ADDI` 有六筆：

- `0x85f0 / 0x86a8 / 0x8b3a`：選記錄後分別讀 ID、handle、ID；這些讀取不是寫入。未據此排除後續外部服務的副作用。
- `0x8be8 / 0x8c5e`：連線與斷線分別在 `0x8bf2 / 0x8c68` 寫半字到記錄 +2。索引 0 或 1 時，寫 gp+150..151 或 +154..155，不碰任一 ID。
- `0x17066`：建立 s2=gp+363，註冊返回後寫入；同函式末段 `0x171a6` 是從 0(s2) **讀** ID 送事件 1，不是覆寫（假設中間呼叫保留 s2）。

因此已分類的這些操作沒有顯示註冊後把兩個 ID 改成相同值。仍不能排除其他基址、跨指令地址推導、區塊複製／清零或外部服務。重現：`python -B analysis/check_v4160_event4_id_writes.py <decoded.bin>`，也可用 `-O`。這是靜態盤點，不是實機監測。
