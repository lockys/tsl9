# V1.30 resident：連線串列初始化呼叫

對 V1.30 參考 BIN（基址 `0x40000`，SHA-256 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`）做唯讀核對。本文補充[編號指派](v130-connection-record-create.zh-TW.md)與[紀錄查找](v130-connection-record-lookup.zh-TW.md)。

- `0x53654`、`0x53658`、`0x5365c` 三條相鄰的 `jal ra` 分別指向 `0x6413a`、`0x57966`、`0x635a6`。這是原始指令中的呼叫順序，不是 BOOT 動態紀錄。
- `0x57966` 起設定 `a0=0x20003304`、`a1=0`、`a2=28`，再透過 `auipc t1` / `jalr x0` 尾跳 `0x2000039c`。同一參考映像 `0x40048` 的 32-bit 表項也等於這個目標。
- 若該 RAM 位置已載入對應的填值函式，且填值正常完成，傳入參數會清除 `[0x20003304, 0x20003320)`。範圍涵蓋建立路徑使用的串列頭 `0x20003304`、尾 `0x20003308` 和半字計數 `0x2000331c`。

驗證：重算完整參考映像 SHA-256，對照反組譯並獨立取原位指令欄位計算三個 JAL 目標、尾跳目標、參數與三個欄位的包含關係，均通過。未確認實際裝置使用此 resident 版本、RAM provider 身分，或此清除必定發生於 BOOT 第一筆連線建立之前；不能據此斷定該筆編號一定為 `1`。
