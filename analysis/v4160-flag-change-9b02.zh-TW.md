# 設定位元變更與延遲回呼的取消請求

`0x142fc` 取 P=`U32[gp+84]`，比較 `U8[P+3]` 與 `U8[s0+27]` 的 bit 4。相同就跳過 `0x9b02`；不同才由 `0x14316` 呼叫，a0 是後者的 bit 4（已正規化為 0/1）。不表示這個分支在裝置上已執行。

`0x9b02` 保存傳入值，先呼叫 `0x90b0(0x9ad2)`。這個表查找只處理第一筆 +4 與回呼相等的記錄；若舊 +8 非零，先交給槽 0x40068。匹配時清 +4/+8，再用該筆遮罩與當下 `U8[gp+166]` 尾跳槽 0x4005c；無匹配直接返回 1。不等於所有匹配或已派發事件均被取消。

在查找及必要的外部呼叫正常返回並保存 s0 時，`0x9b16` 不檢查返回狀態，即將保存值低 byte 寫 `gp+168`。對這個具體呼叫者：傳 1 隨即向 0x40010814 寫 word 2；傳 0 尾跳 0x9af0，重新讀旗標，仍是零才向 0x40010810 寫 word 2。此後 0x9b36 亦依當下旗標決定是否進行外設存取。不要將一般入口的完整 s0 零判斷誤作低 byte 判斷；本呼叫點確實只有 0/1。

檢查器固定原 APP、核對分支與寫入位置，從機碼擷取遮罩和位移，對 65536 組 byte 對照 bit 4 判定：32768 跳過、16384 傳 0、16384 傳 1。一般及 -O 通過。這是離線資料流證據，不是排程器、裝置或外設觀測。
