# 任務 7：入列後設置事件，不等於已派送

承接前次 128 份初始化後的合成 RAM，各跑空佇列與一個既有尾節點。成功入列後從同一份暫存器與記憶體執行參考函式 0x4354a(7,0x8000)，直到返回 0x43292。使用 V1.31 候選 resident 與條件 Xwchc 半字載入/儲存，不代表裝置 ROM。

- 函式重新讀取 0x2000319d 的任務數。7 < 8 時，從 0x200031e4 載入待處理事件表指標，再以 2*7 索引。256 份分支的欄位均為 0x20004876，原值 0；0x43578 寫入 0x8000，函式返回 0。讀寫帳本也核對了進入時保存、清零及離開時還原的外設字；未模擬真實硬體效應。
- 256 個獨立對照把原半字預設為 0xa135，結果仍為 0xa135，表明不是以 0x8000 覆寫其他事件。另 256 個對照只將任務數改為 7；函式返回 3，未讀事件表指標、未寫事件半字。這是入列後的測試分支，不是自發的任務數變動。
- 一般及 -O 各回報：`PASS: 256 inherited posts, 256 pre-set masks, 256 count rejects: [('0x20004876', '0x0', '0x8000')]`。這一步只證明上述狀態下事件已標記，沒有執行排程器或任務處理器。
