# 可讀的原生時脈元件

新的 `native_clock.c` 已實際編譯為 freestanding RV32 C11 與 C++17，並連結為 `COMPONENT-ONLY-NOT-FIRMWARE.elf`。兩種模式輸出相同函式位元組：時脈查詢為 **170 位元組、59 條指令**，原始範圍為 174 位元組、58 條指令；衍生欄位函式為 **44 位元組、14 條指令**，原始範圍為 40 位元組、11 條指令。此編譯設定下，欄位函式超出原範圍四位元組。兩者均尚未配置至原韌體位址。

原生物件與連結元件沒有未定義符號、函式庫呼叫、可寫資料，或冒充原始位址的別名；只包含兩個使用新名稱的重建函式。檢查涵蓋 ELF 類型、處理器、RVC／soft-float ABI 旗標，以及 RV32IMAC 整數 ISA 屬性。在診斷位址 `0x1000` 連結後，兩個函式的機器碼保持一致。

每個函式的全部 ELF 位元組都與反組譯原始位元組比對，要求位址連續、指令邊界完整。無法解析的指令形式、內部／尾端行、內部標籤、缺漏與截斷均會拒絕。所有直接分支只能指向同函式內真正的指令邊界，所有順序落下路徑均保持在函式範圍內。兩個函式分別保留四次與三次明確的 GP 讀取，且不寫入 GP。存取寬度白名單拒絕不支援的 load／store；CSR 操作、陷阱、外部呼叫與隱藏輔助函式也會拒絕。

LLVM IR 另外檢查即時 GP 讀取與記憶體 clobber，獨立的 GP 相對位址 `+108`、`+64+index`、`+382`、`+380`，六個 RCC 靜態讀取位置、一個 EXTEN 讀取位置、無符號表格 byte 讀取、兩個 32 位元輸出寫入、遮罩後的無符號位移、除以 8,000,000 的無符號除法，以及乘以 1,000 前的 byte 截斷。靜態存取位置數量包含互斥分支，不代表每次執行具有相同的固定效果清單。

每種語言均實際編譯並拒絕五個錯誤版本：固定 GP、錯誤全域位移、錯誤表格讀取寬度、遺失商的截斷，以及有符號除法。每種語言另有十二項反組譯控制，分別測試兩個函式遺失首筆／內部／尾端指令、竄改位元組，以及無法解析的內部／尾端行。`results.json` 記錄真實收據、來源／工具識別，以及獨立的主流程 hosted 語意測試證據。

## 從發布專案重新編譯

需要 Python 3.10 以上及支援 RV32IMAC 的本機 LLVM 工具：

```sh
python3 analysis/v4160-native-clock-2026-10-21/native-review/verify_native.py \
  --project-root . \
  --clang /path/to/clang \
  --linker /path/to/ld.lld \
  --objdump /path/to/llvm-objdump \
  --language both
```

也可用 `--tool-dir /path/to/llvm/bin`。分析工作區前綴是 `apk-analysis/tsl9-v4160-native-clock-2026-10-21/`；發布版本是 `analysis/v4160-native-clock-2026-10-21/`。新建置只需要新 C／標頭、已發布的 Python 檔及本機 LLVM，不需要舊有被忽略的原生映像封存。本次工具鏈為 Android NDK 27.1.12297006、Clang 18.0.2，主要旗標為 `--target=riscv32-unknown-elf -march=rv32imac -mabi=ilp32 -Os -ffreestanding -mno-relax`。每份收據記錄完整旗標及執行檔雜湊。不同編譯器若輸出超出靜態證明器支援形式，會明確失敗。

唯讀重播本機原驗證產物可使用 `check_native.py --project-root . --require-local-builds`。省略最後旗標時會明確列出缺少的封存；只驗證封存中繼資料不代表重新編譯。產生的物件、ELF、IR 與日誌只保留本機，不隨來源碼發布。

## 證據限制與整合工作

這些是原生結構、I/O 基元與部分無符號 IR 屬性的證明。時脈查詢具有分支；機器碼驗證器不執行分支、不模擬暫存器／記憶體，也不證明完整原生分支路徑語意等效。主流程的 hosted 測試透過明確的合成 I/O 驗證共用 C 計算，屬於獨立證據，不是 RV32 執行或實體硬體驗證。

一般 C 介面會改變原始 A0／A1 與其他 caller-saved 暫存器殘值。保留 GP 不代表完整原始 C／IRQ ABI 已證明。仍需釐清真實呼叫鏈、非同步中斷、欄位函式多出的四位元組、固定佈局、未知 ROM／駐留實作、實際板型／MCU、周邊副作用及藍牙 OTA 相容性。舊原生映像檢查保持不變。沒有產生韌體 BIN、沒有執行原始／重建 RV32 程式，也沒有裝置 I/O 或網路存取。此元件尚不可燒錄。
