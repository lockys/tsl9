# 原生 C 時脈重建：原始契約

本輪直接沿用 ID 2966 V4.1.60 的唯讀原始證據，範圍為 `0x18834..0x188E2` 與 `0x1973C..0x19764`，封存 SHA-256 是 `ebf0521f52c5142d1dc7969aaca17bb1c7567065165eba4c88fd4523e30b6a51`。原檢查涵蓋 214 位元組、69 條指令，拒絕 50 個原始運算元變異，並另列重設表格來源。本輪沒有複製或另造解碼器。

## 0x18834 的查詢

第一次 READ32 `0x40021004` 只供選擇位元 2、3。遮罩結果為 4 時選 32000000，為 8 時進 PLL 分支；0 與 12 都選 8000000。

PLL 分支在 0x18882 與 0x18884 分別讀取倍率與來源位元 16，不能合併為一次取樣。倍率是 `((sample >> 18) & 15) + 2`，其中 17 改為 18。來源位元 16 為零時，另讀 `0x40023800` 的位元 4：有設定位元選 8000000，否則選 4000000。來源位元非零時，再讀 `0x40021004` 的位元 22、23；兩者均設定時選 16000000，否則還要再讀一次，再以該次位元 17 判斷：設定選 4000000，未設定選 8000000。原指令把最後一次取樣左移 14 位後作有號正負判斷；C 可以直接檢查同次取樣的位元 17，但不能改成無號「大於等於零」，也不能觸發有號左移的未定義行為。乘法保留 32 位元低位結果。

各分支合流後依序執行：

1. 0x18850 先 WRITE32 暫定結果至當時 `GP+108`。
2. 0x18858 再 READ32 `0x40021004`，取得 `(sample >> 4) & 15`。
3. 以當時 `GP+64` 為表格基址，0x18864 對基址加索引作無號 READ8。
4. 重新形成當時 `GP+108`，0x1886C 讀取新 READ32，不能用先前的暫定區域變數代替。
5. 對新讀取的值作無號右移，位移量必須是 `table_byte & 31`，避免 C 在表格值超過 31 時產生未定義行為。
6. 0x18872 WRITE32 結果至當時 `GP+108`。

重設複製若正常完成且內容未再改動，表格十六個位元組才會是 `00 00 00 00 00 00 00 00 01 02 03 04 06 07 08 09`。這不是實體 RAM 擷取，也不能據此省略原來的 READ8。

## 0x1973C 的衍生欄位

0x19740 重新 READ32 當時 `GP+108`，作無號 32 位元除以 8000000，再於 0x1974E 保留商的低八位。0x19752 WRITE8 該值至當時 `GP+382`；0x1975A 將仍保留的低八位商乘以 1000，不重讀剛寫入的位元組；0x1975E WRITE16 乘積低十六位至當時 `GP+380`。必須先截斷商再乘法，不能只在最後截斷。寫入寬度必須保留，避免改動相鄰資料。

原呼叫順序是查詢函式、`0x9A42`、衍生欄位函式，因此最後一次讀取不能改為使用查詢函式的快取回傳值。其他來源對 0x9A42 的研究也不能取代這個新讀取，或證明實際中斷行為。

## C 介面與原始 ABI 的差異

兩個原始函式均為葉函式，沒有呼叫或 SP 操作，也沒有明確改寫 GP、RA、A0、A1；均透過當時 RA 並清除最低位元返回。A2、A3、A4、A5 依原始運算而改變。這些是指令本體的事實，不能反推完整 C 函式簽章。

一般 C 的 context／GP 參數通常會使用 A0，可能也會用 A1；回傳值也會使用 A0。即使宣告 `void`，編譯器仍無須保存 A0、A1，亦可能建立堆疊框架。因此原生 C 可以重建資料及周邊效果，但在原呼叫位址替換之前仍需要獨立證明 ABI 轉接，不能宣稱原位相容、IRQ 安全或可直接燒錄。

原指令會分別形成每個 GP 相對位址。若 C 介面在單次呼叫固定一個 GP，必須明列此假設：原始本體雖未改 GP，但非同步或外部注入的 GP 變動不在該 C 介面範圍內。Host MMIO 回呼改動外部記憶體，不能當成已證明任意機器暫存器變動。
