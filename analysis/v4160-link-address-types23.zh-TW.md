# 連線位址類型 2、3：查表輸入和輸出位置

承接[類型 0、1](v4160-link-address-lookup.zh-TW.md)。此處沿 v4.1.60 APP 對應的 V1.31 候選路徑分析 `0x6be3c`；事件位址 `A=M+4` 存於 s3，輸出指標 O 存於 s2。在此呼叫者，O 是 `0x6c194` 的堆疊緩衝區，不是 A。以下假定相應 RAM helper 已正常複製、Xwchc 解碼成立、保存暫存器及堆疊有效。

- **類型 2** 從索引 i=0 掃描，每輪重讀 `U8[0x20002fc1]`。`0x6beac` 比較 `(U32[0x20002fbc]+16*i+6, A, 6)`，用的是 `0x20000442`；不同於類型 0、1 比較列首。比較返回非零才跳至共用輸出段。此處沒有把 A 當目的地，也不能把比較非零無條件當成六 byte 相同（見前文的空指標例外）。
- **類型 3** 在 `0x6beea` 以 `(515+6*i,16,SP)` 呼叫 `0x440c2`。正常返回零且後續對這 16 bytes 的檢查也返回零，才在 `0x6bf06` 傳 `(SP,A)` 到 `0x46018`，它直接跳 `0x50040`。非空路徑先將 `A+3..A+5` 三個 byte 複製到本層 `SP+8..10`；再將末 byte 改為 `(舊值 & 63) | 64`。`0x50060/70` 的 Xwchc 指令都是對 `SP+10` 操作，並未修改 `A+5`。`0x51f78` 的三個明示參數是上層的 16-byte 暫存區、本層 `SP+8`、本層 `SP+12`；若它返回零，才比較 `(SP+12,A,3)`。這段明示的 copy、修改與比較不以 A 為目的；未驗證 `0x51f78` 或資料讀取服務的全部副作用。
- **共用輸出**：到達 `0x6bf0c` 仍須重讀界限；若 i 仍有效且 O 非零，才呼叫 `0x6b730(i,O)`。後者再次檢查，並向 `0x440c2` 提出 `(512+6*i,16,自己的 SP)`；成功返回零才要求 `0x20000332(O,自己的 SP,6)`。呼叫者隨後用 i 返回，不使用輸出 helper 的狀態。查到索引不保證六個輸出 byte 已填妥。

核對固定 V1.31 carrier（SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`）上的 5 組 AUIPC/JALR、6 個 JAL 目標與連結暫存器，以及兩個 Xwchc 堆疊指令的暫存器和位移。這不是已安裝 ROM、實際事件或整條路徑無寫入的證明。
