# v4.1.60：模式寫入上游的三個入參常數

接續[模式寫入函式的直接引用](v4160-app-event-slot18-mode-callers.zh-TW.md)。本輪只核對 `0x107c6` 的直接轉移與入參，不主張啟動條件或實機狀態。

在原 APP 的 38,399 個半字起點篩查標準 32-bit `JAL`，目的為 `0x107c6` 的有兩處：`0x10bbe` 是尾跳，`0x10bda` 是呼叫。前者有兩段局部前導：`0x10ba4` 設 `a2=5` 後跳至共同尾跳；`0x10bb6` 則設 `a2=1` 後順行至同一尾跳。後者的 `0x10bd0` 設 `a2=2`。這些是原指令中的常數，不是觀測到的 RAM 值。

`0x107d4` 保存入口 `a2` 至 `s1`，`0x10806` 使用的是經中間呼叫之後仍在 `s1` 的值。已找到靜態模式 1 入參，但寫入證據仍需分兩段檢查：`0x107c6` 路徑上的 `s1` 能否保持、以及 `0x1074c` 從入口到直接寫入前的 `s0` 是否保持。兩個檢查均未完成；掃描也不涵蓋間接轉移或證明上游執行可達性。

Python `-O` 驗證原 APP SHA-256、兩個 JAL 引用、三個入參常數和三個固定指令窗；另用反組譯交叉核對前導。未連接設備，也未修改原 BIN 或正式來源。
