# 表第 0 項到 0xe66c：三個選擇值的共同條件

承接 [0xcfdc 的輸入篩選](v4160-e220-cfdc-cancel-consumer.zh-TW.md)。原 APP 的 `0x1a13c` 第 0 項為相對位移，入口是 `0xe246`。以 s1=1、s0=64/65/66 進入時，若 `0xb664` 回非零，第二張表 `0x1a150` 的索引 21、22、23 都指向 `0xe288`；回零則直接到同處。`0xb6a8` 的零／非零選擇不同支路，但這三值最後都匯入 `0xe2bc`。並非兩個 helper 都得回非零才能取消。

|s0|匯合後、檢查取消旗標之前的差異|
|---|---|
|64|呼叫 `0xd052` 並把結果低 byte 存到 gp+267；設 gp+263=1，呼叫 `0xbd00(1)`、`0xda36(1)`，再呼叫 `0x167a6(111)`。|
|65|同樣取 `0xd052`；若讀到 gp+263 非零，清零並呼叫 `0xbd00(0)`；接著 `0xda36(0)`、`0x167a6(112)`。|
|66|跳過 `0xd052`；gp+263 的處理同 65，再呼叫 `0xda36(0)`、`0x167a6(113)`。|

三者都在最後一次呼叫返回後才重新載入 `[gp+84]`，讀其所指的首 byte。**此刻 bit 4 為 1** 才以 a0=0 走到 `0xe66c`；為 0 則跳至 `0xe568`，本次不呼叫取消。不能用進入函式前的旗標替代最後一次讀值。

`python analysis/check_v4160_selector0_cancel.py <decoded-bin>`：固定原 BIN SHA-256，在有限指令解譯器走該段；helper 均注入正常返回、保留 s0/s1/gp，不模擬其副作用。兩個 helper 各取零／一、gp+263 取 0/1/255、旗標窮舉 256 值，共 9216 案，4608 案抵達呼叫點。這是條件分流的驗證，不是實機頻率，也沒有執行取消服務。
