# v4.1.60：分派器入口的佇列記錄來源

接續[來源指標交接](v4160-app-event-object-source-pointer.zh-TW.md)。本輪確認一個 APP 呼叫點如何建立傳給 `0x14d2e` 的暫存記錄；這不等於證明該次呼叫一定選到第 18 槽更新分支。

- `0x12c6e/0x12c72` 建立佇列基址 `0x2000c038`；`0x12c76` 設定步距 12。`0x12c86` 起以目前索引計算槽址，槽首半字非零時，`0x12ca4` 要求透過 `[0x4004c]` 把槽內 12 bytes 複製至 `sp+8`。若提供者按參數複製，暫存記錄的第三個位元組初值來自槽內 `+2`，不是在複製時另行產生。
- `0x12cb0` 先把同一個堆疊偏移的指標交給 `0x82d2`。正常續段在其返回零、記錄首半字不同於 `s4`、通過 `0x12d78` 的旗標檢查且 `0x81aa` 返回非零時，`0x12d8c` 以當時的 `sp+8` 呼叫 `0x14d2e`。這條分支不經過 `0x12cbe` 的等於 4 檢查；該檢查在首半字等於 `s4` 的另一邊。
- 因此，建立暫存記錄的固定複製大小，不等於其長度欄位的值。兩處 `sp+8` 要指向同一區域，必須有相同的實際堆疊基準；本輪也不假定 `0x82d2` 保留記錄內容。下一步核對 `0x82d2` 在一般處理路徑上是否改寫暫存記錄的 `+2`，再決定能否把槽內值一路追到入口。

Python `-O` 通過原 APP SHA-256、106 bytes 指令窗、佇列基址計算、三個 JAL 目標與一個條件分支目標。僅靜態核對，未執行提供者或設備。
