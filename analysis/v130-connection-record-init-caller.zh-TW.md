# V1.30 resident：串列初始化的上游分支與回呼槽

唯讀核對 V1.30 參考 BIN（基址 `0x40000`；SHA-256 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`）。接續[串列清除與建立呼叫點](v130-connection-record-call-order.zh-TW.md)。

- `0x606f8` 入口從 `0x2000304f` 讀一個 byte。`0x60704` 若讀到非零，跳到 `0x60716`，略過 `0x6070e → 0x43afe` 和 `0x60712 → 0x534d0`；零值分支則依序呼叫兩者，前提是第一個呼叫正常返回。`0x534d0` 的後段含先前確認的 `0x53658 → 0x57966` 清除呼叫。
- 若回到共同續程，`0x60734` 會將 `0x603b8` 寫到 `0x200033a8`。因此，僅憑這個槽已被寫入，不能反推該次執行走過清除分支。
- `0x5e7de` 和 `0x601a8` 各從同一槽讀取 word 至 `a0`。前者另設 `a1=3` 後呼叫 `0x439d8`；後者用 AUIPC/JALR 呼叫 `0x2000078a`。此處證明的是把槽值當參數傳遞，不是已證實由這兩處直接執行 `0x603b8`，也尚未連到任一建立呼叫點。

完整映像雜湊、分支條件、直接及 PC-relative 呼叫目標、槽位寫入值與兩次載入均經原位欄位重算。尚未確定 BOOT 首次通過此入口時 flag 的來源與值、排程器如何處理該參數，也未確認實機 resident 版本。
