# 第三張查找表的狀態寫入者

[English](readme.en.md)

新擷取 **275 條原始指令／11 個視窗**，並核對全部已選取 CODE（64,544 bytes／21,938 指令）。找到查表列索引 `0x2000BF39` 的以下來源。

| 路徑 | 已確認的程式行為 |
|---|---|
| `0xD05C` 設定函式 | `0xD06E` 將 A0 的低 byte 寫入索引，本身沒有遮罩；五個選定直接呼叫者提供 1／3／5 |
| `0xD0C8` word 寫入 | 三條常數路徑的索引 byte 分別為 5／4／2；均保留原始分支與寫入角色 |
| 啟動清零程式 | 編碼的清零區間包含此索引；不是已安裝啟動或 ROM 的實機證明 |
| `0xD0EE` 重設 | 以 16-byte 範圍包含索引；若原機 `0x40048` 槽位符合已封存 SDK 的 memset 契約，才可推論清零 |
| `0xCEAA` 相鄰重設 | 20-byte 範圍結束於 `0x2000BF38`，不包含索引 |
| `0xC91E → 0xEBAC` | 相鄰紀錄的直接寫入範圍為 8 bytes、結束於 `0x2000BF38`，不包含索引；被呼叫函式的副作用未閉合 |

五個選定直接呼叫位址為 `0xA224`／`0xAC6C`／`0xD528`／`0xE1EA`／`0xE6E8`。已重建元件對設定函式只有這五筆直接參照，沒有其他已選取的取址參照；這不能排除未選取資料、間接入口或其他指標別名。

在這些設定與相符的清零條件下，索引集合為 **0–5**，第三表的保守讀取視窗為 `0x1A078..0x1A0D8`（96 bytes）。其中 16 bytes 已在目前資料池內，候選增量為 80 bytes；三張表的保守聯集會是 512 bytes。這不是原始宣告大小，也不是全域執行界限。

**目前沒有新增資料提供者、沒有擴大覆蓋率。** 任意 record 指標別名、非相鄰位址推導、ROM／callee 副作用、間接入口與非同步影響仍未完整排除。正式狀態維持 **88.89%／22 個未解參照**。

沒有產生 BIN、執行韌體／HOST 模型／ISA、操作硬體或呼叫後端；實機與 OTA 相容性仍未證明。
