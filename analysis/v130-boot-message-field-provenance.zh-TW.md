# V1.30 BOOT 訊息欄位來源

本次以 Flash 基址 `0x40000` 反組譯 V1.30 resident 候選映像。映像 SHA-256 為 `8fd279d4bc08bea74625e0ef3b8ca873746a84bf430c46a7565482effd96a04c`。

## 訊息類型

原始指令核對顯示，下列三個組包位置都以 `addi a5, zero, -48`（指令字 `0xfd000793`）搭配 WCH 壓縮位元組寫入，將訊息首位元組設為 `0xd0`。

| 載入常數 | 首位元組寫入 | 額外欄位 |
|---|---|---|
| `0x4573e` | `0x45742` | `0x45752` 將入口 `a1` 的低 16 位寫入 `+4`。 |
| `0x45824` | `0x45828` | `0x45832` 將入口 `a1` 的低 16 位寫入 `+4`。 |
| `0x45b76` | `0x45b7a` | `0x45b90` 將子碼 `5` 寫入 `+3`，`0x45b94` 起將六位元組複製到 `+4`。 |

先前將前兩個組包位置歸入 `0x91` 訊息的判讀需更正。實際移除分支在 `0x46500` 比較首位元組是否為 `0x91`，在 `0x4650c` 比較子碼是否為 `5`，兩項均命中才呼叫 `0x45620`。該函式由 `0x45626` 與 `0x4564a` 讀取原訊息 `+4` 的半字。產生這則 `0x91/5` 訊息的函式及實機連線編號仍待確認。

## 已核對的參數

`0x4f382` 的 WCH 壓縮半字載入 `0x2192` 將附屬結構 `+0` 讀入 `a2`。該值經 `0x45ec4` 與尾跳 `0x4604e` 成為 `0x456c0` 的 `a1`。另一條路徑在 `0x4fbc8` 以 `0x204a` 讀取輸入訊息 `+4`，經 `0x4f446` 與 `0x4f528` 傳入 `0x457e2` 的 `a1`。
