# OTA 結束依賴：記錄檢查與模組狀態

[English](readme.en.md) · [C/C++](../../src/native/receive/ota_finalizers.c) · [原始指令](evidence.json) · [驗證摘要](summary.json)

新增兩個完整函式182B／69指令、22個私有區塊與14個控制重定位。所有下游已具實作，未解析提供者由73降為71，沒有新增依賴。C11／C++17與原始位址配置均通過。

| 範圍 | 已確認的靜態行為 |
| --- | --- |
| 9EA6–9EE0 | 32B frame，取得9E84傳回的兩word／8B記錄，比較偏移4的byte與完整32-bit輸入；不符則寫入輸入低8位後呼叫9E5C。最多五次寫入；先讀到相同值才返回0，第五次寫完直接返回1，不再讀回。 |
| 16E0C–16E88 | 輸入bit0／1控制0x40010814的16／1寫值，呼叫16896(192)，再寫17至0x40010810。輪詢16994(input,14)&0xE0是否為0x80；unsigned tick差>2返回1，符合狀態返回0。tick單位與實體狀態用途仍未證。 |

原9EE0流程以1呼叫9EA6，未依返回值分支，隨即以0尾跳99E8。因此旗標寫入沒有最終讀回證據時，原流程仍可繼續進入重啟請求。這不證明實體寫入失敗，但也不能用E或進入重啟流程證明持久化成功。

更正上一輪報告：8E66直接跳到8E4A的JR T1，跳過8E48的SP+=16。先前把跳過的指令算入路徑，所述堆疊不平衡沒有證據。原始指令與重建C/C++不變，已更正上一輪三份公開報告，舊報告保留本機，先前最終收據視為歷史快照。此更正不等於已證實完整呼叫端／ROM ABI。

目前113個C/H檔、86個code單元，含獨立指標資料共174項比較／348個物件；舊112個來源與1021筆產物記錄不變。主元件20224B code＋714B data，共20938B在原生原址配置後逐byte等於官方ID2966 BIN；71個真實缺漏仍明列，未用stub或ABS函式取代。

靜態流程含7033指令、1160直接轉移（1089已重建／71僅參照）、6487個一般下一位置且無缺口、431個可能呼叫返回位置；363個暫存器間接轉移、10個MRET與1個EBREAK仍非完整CFG或硬體證明。診斷ELF入口0、PT_LOAD=0，不可燒錄。

下一步處理主初始化131C2／12D92與ROM／BOOT／APP映射。值得新增的功能是OTA完成階段證據顯示，分開回覆、分頁讀回、旗標讀回、重啟與功能確認；目前僅提案，不修改原安全檢查。未執行目標、HOST模型或ISA模擬，未操作硬體／網路；歷史隱私問題未清理，未commit／push。
