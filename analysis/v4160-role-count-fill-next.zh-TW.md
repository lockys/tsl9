# 分開第一個區塊的清零長度與下一筆請求

承接 `v4160-role-count-alloc-neighbor.zh-TW.md` 的非空返回；保留原來的 P、堆積和暫存器。在 `0x4db2a` 的讀取才為缺少的 `0x20003351` 提供測試值 B。每個測試使用獨立記憶體覆層。

- `0x20002fa3` 收到重讀的 N，`0x20002fa1` 收到 B。驗證完整有序寫入：除了欄位及外設暫存／還原，填充迴圈恰好逐 byte 清 `[P,P+16*N)`，長度不取決於 B。
- 填充返回後讀 `0x200033b4`（八個繼承狀態都是 5）及 `0x20002fa1`。兩者和的低八位存入 `0x20002fa0`；下一筆請求的大小是此值乘 16，標記 `0x4c05`，返回位址 `0x4db60`。
- B 分別為 0、1、250、251、255 時，請求大小為 80、96、4080、0、64 bytes。即使大小為零也抵達配置器入口；本檢查不預設其返回值。

8 個繼承狀態 × 4 個 N（1、3、4、255）× 5 個 B，共 160 條路徑；一般 Python 及 `-O` 均通過。本機驗證：`analysis/check_v4160_role_rf_to_heap.py`、`analysis/v131_count_fill_next.py`。這是 V1.31 參考程式、Xwchc、合成記憶體與外設下的結果，不代表裝置上的 N 或 B。
