# 初始化 `0x64298`：三個子函式的寫址

問題是它們能否直接把值寫到計數 byte `0x20003350`。使用 V1.31 參考 carrier SHA-256 `133d37055626caa1ac0f0abd0b8ec4d8c5786a61d52e6a2ef24ae2705aa15a22`；不是裝置量測。以下「筆」是靜態指令位置，不是執行次數。

前提：父函式 `0x642cc/0x642da/0x642c0` 分別將 `0x40025000/0x40024100/0x40024200` 寫入 `0x20003590/0x20003508/0x2000353c`。以下按每次從槽載入時仍為此值、正常返回、被保存暫存器保持的情況計算。

| callee | 直接寫入與剩餘條件 |
|---|---|
| `0x660ce` | 29 筆非堆疊 word store，全以 `0x40025000` 為基址，偏移 `{40,44,48,56,60,72,76,80,84}`（十進位）。唯一子呼叫 `0x66098` 的三個 store 都寫 `0x4002500c`，依序為 `0x1101,0,0x1101`；該 helper 每次重新載入基址。另有一筆 ra 堆疊保存。 |
| `0x638ea` | 無子呼叫或堆疊寫入。六筆 word store 的偏移依序為 `0,0,52,44,44,32`，基址 `0x40024100`。另讀 `0x20003200` 一個 byte 參與運算，不是寫入。 |
| `0x641b0` | 七筆堆疊保存。若通過前段分支，此函式本身的 11 筆非堆疊 store 只涉及 `0x4002420c,0x40024100,0x40025008,0x40024250` 與 RAM byte `0x2000351b`（`0x6427e`: `sb zero,7(s0)`）。該 byte 不是計數。另有五個直接呼叫 `0x63eda,0x6645c,0x67198,0x662da,0x6636e`，未納入以上 11 筆。 |

驗證：取 `[0x638ea,0x63944)`、`[0x66098,0x660ce)`、`[0x660ce,0x66242)`、`[0x641b0,0x64298)` 的 carrier 位元組（檔案位移 = VMA − `0x40000`），用 `rasm2 -a riscv -b 32 -s <VMA> -D <hex>` 走讀至各自的 ret。核對非 sp 的 sw/sb/sh 偏移集合，四段分別為 `6/3/29/11` 個位置；第三個 callee 入口的特殊壓縮讀取不拿來斷言分支必走。只排除上述直接寫址，不排除堆疊重疊、指標被改寫、外設副作用、巢狀呼叫或其他執行緒。
