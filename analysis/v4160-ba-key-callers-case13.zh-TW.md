# 0x114e2 的兩個呼叫點：同一外層事件，兩種欄位

在 SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667` 的 76800-byte APP，半字對齊掃描找到兩條目標為 `0x114e2` 的標準 `jal ra`：`0x11738`、`0x117f2`。它們不是兩個獨立的事件入口。`0x11544` 依入口記錄 byte +2 作 17 路分派，表 `0x1a548` 中只有索引 13 指向 `0x11570`。在這條路徑上第一個呼叫正常返回後，仍會檢查第二種欄位。

`0x10ce0` 在同一記錄的欄位串內按類型查找，找到時輸出內容指標與長度。`0x11630` 查類型 9（此路徑要求長度 22），`0x11746` 查類型 255（要求長度 15）。兩者另有內容與服務結果條件，不是每次都呼叫。重新組鍵時，兩者高三個 byte 都取自外層記錄 +5/+6/+7，低 byte 分別取自查得內容 +6 / +3。第一處另外計算兩個參數；第二處把兩者設零。

**呼叫不等於產生新鍵。** `0x11634` 先令 s1=0。第一條路徑可經 `0x11806` 跳過組鍵；第二條可經 `0x1179c` 或 `0x117b6` 跳至 `0x117e8`，沿用當時的 s1，而非每次都取第二個欄位的低 byte。`0x114e2` 對零鍵不執行已知的鍵寫入。這是原 APP 指令的靜態資料流；跨呼叫解讀以正常返回及保存相關暫存器為條件，不代表觀察到實際事件，也不據此給鍵指定產品身份。
