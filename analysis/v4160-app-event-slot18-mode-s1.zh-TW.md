# v4.1.60：模式 1 入參保留至寫入函式入口

接續[三個入參常數](v4160-app-event-slot18-mode-arguments.zh-TW.md)。本輪只驗證 `0x10bae` 這一支到 `0x1074c` 入口的暫存器傳遞，不推論何時會走到該支。

- `0x10bae/0x10bb2` 建立本地回呼位址 `0x1069e`。`0x107d4` 將 `a2=1` 保存在 `s1`，隨後的 `0x107d6` 呼叫該回呼。對照 `0x1069e..0x106c0` 與其本地子函式 `0xed00..0xed36`：兩者沒有以 `s1` 為目的暫存器，子函式內的分支與回跳均在所核對的範圍內，沒有其他呼叫。
- 若控制流繼續至 `0x107fe`，它呼叫 `0x820c`；該本地例程也不寫 `s1`。在正常返回、記憶體存取成功且控制流未受干擾的條件下，此支到 `0x10806` 仍有 `s1=1`。指令先將它搬到 `a0`，再恢復原保存的 `s1`，最後在 `0x1080c` 尾跳。由此只證得 `0x1074c` 入口的條件式 `a0=1`，尚未證得 RAM 已寫入 1。

離線核對原 APP SHA-256、五個原始指令窗共 200 bytes、回呼位址及兩處本地呼叫目標，另逐指令核對暫存器目的與控制轉移。未連接設備或修改原 BIN／正式來源。下一步核對 `0x1074c` 內四個呼叫是否會改變用於模式寫入的 `s0`。
