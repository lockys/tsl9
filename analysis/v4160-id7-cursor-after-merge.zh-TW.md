# 任務 7 寫回後：游標走到表尾，而非立即重派

承接[事件合併](v4160-id7-return-merge.zh-TW.md)。本機 driver 把剛寫回的 RAM 和暫存器交給[下一段局部模型](v131_id7_cursor_hook.py)，不重新指定游標、回呼指標或任務數。handler 的合成保存區明確提供 `s2=0x20003000`、`s4=0x2000319c`，對應排程器 0x200007ea 和 0x20000832 的基址設定；不是設備堆疊證據。

* 0x2000092a 重讀游標，非零才寫回加一的低 byte：本批 `7 → 8`。兩組事件寫回（0 或 0x47）走向相同。
* 0x20000936 讀取回呼槽 0x200031c8。256 個承接狀態都有完整四個零位元組，**不是把缺值當零**，所以不經 0x2000093c 間接呼叫。
* 0x20000942/946 分別重新讀游標與任務數，兩者皆為 8。無號比較取 0x2000084c（該址指令為清零游標）；本次模型止於分支目標，未執行下一輪掃描。

一般與 `-O` 各驗證 256 個承接狀態、1024 個控制。零游標不增加、255 以 byte 寬度回零；把槽改成 0x55481 時，選呼叫目標 0x55480，止於呼叫邊界，不假設回呼返回。這些是 V1.31 候選映射下的離線測試，非實機回呼或裝置排程紀錄。
