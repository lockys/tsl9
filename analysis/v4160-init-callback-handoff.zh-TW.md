# 0x19b16：兩個不同的函式位址與後續排程

`0x8eac` 直接呼叫 `0x19b16`。在必要的間接呼叫與時鐘初始化均正常返回、保存的暫存器與棧有效時：

1. `0x19b2e` 取槽 `0x40080` 的目標，將 `0x1995c` 作為 a0 傳入，並在 `0x19b34` 把回傳值的低 byte 存入 `gp+388`。APP 在此並沒有直接呼叫 `0x1995c`。
2. `0x19b38` 呼叫 `0x19b56`，其間有多次時鐘相關呼叫。`0x19bcc` 把棧上結構的位址（不是 `0x191c6` 本身）傳入槽 `0x40074`。當下明確寫入的前三個 word 是 `0x191c6, 0xffffffff, 0x03e83e80`。這個 callback 與步驟 1 的事件處理函式不同。
3. 返回 `0x19b3a` 後重新讀 `gp+388` 的 byte，不是沿用原先回傳暫存器。尾跳槽 `0x40058`，參數是 `(目前的 byte, 0x2000, 192000)`。若 `0x1995c` 日後被調用並選中 bit 13 的分支，`0x199bc` 同樣以重新載入的 byte、同一遮罩和延遲呼叫該槽。兩次 byte 讀值不必然相等。

這是 APP 可確認的參數交接；不證明已安裝 resident 的實作、成功排程、立即派發、callback 已執行，或延遲單位。一般與 `-O` 核對固定原 BIN 的指令與地址，並拒絕九處單獨指令變造。
