# v4.1.60：第 18 槽識別值的固定表來源比對

接續[第 18 槽分派路徑](v4160-app-event-slot18-dispatch.zh-TW.md)。本輪只回答：`0x0679` 是否出現在已辨識的初始化資料？這與「是否真的形成一筆佇列記錄」是兩個問題。

- **CAN1 固定表有一筆。** 原 APP `0x19ca8` 的 96 bytes 解為 48 個 little-endian 半字。唯一命中在零起算索引 43，APP 位址 `0x19cfe`（檔案偏移 `0x11cfe`），原始值 `79 06`；相鄰表項是 `0x0678` 與 `0x0332`。
- **兩組已核對的 SPI 初始化常數沒有命中。** 這只排除在這四個常數半字中找到該值，不能排除其他設定或來源。

用 Python `-O` 重跑固定表與 SPI 指令窗核對，再用固定 SHA-256 的原 APP 驗證 48 個表項、唯一命中位置與四個 SPI 常數的比對。未連接設備。固定表命中支持 CAN1 是候選來源，但尚不能把它當成實際接收或模式 1 的證據：上述分派路徑讀取的模式值與固定表項不是同一欄位。下一個查證點是釐清模式選擇是來自佇列記錄還是獨立的 APP 狀態。
