# v4.1.60：APP 傳給 `[0x40074]` 的設定首字

接續[候選複製來源](v4160-app-event-slot18-mode-clock-source.zh-TW.md)，重驗既有 APP 位址線索：`0x19bba/0x19bbe` 計算 `0x191c6`，`0x19bc2` 寫入當前 `sp+0`。同段另寫 `sp+4=0xffffffff` 與 `sp+8=0x03e83e80`；`0x19bca` 將 `sp` 放入 `a0`，`0x19bcc` 呼叫 `[0x40074]`。這次只驗這個呼叫位置，不聲稱是唯一呼叫點或已核對整個設定區。

若實際綁定與 V1.31 的 `0x43f46` 一致、設定通過檢查且首字在複製前未變，前兩輪核對的路徑會把 `0x191c6` 寫到 `0x200031e0`。若這個非零值到模式寫入路徑仍未變，且較早的登記已成功，就不會走候選的第二道零指標早退。這並不證明呼叫順序、一定執行回呼或實機最終寫入模式 1。

Python `-O` 通過兩份映像 SHA-256、34-byte APP 指令窗、兩個常數運算及候選 slot 核對。下一步以 APP 的直接控制流確認這個設定呼叫與模式寫入入口能否排序；未連接設備或修改原 BIN。
