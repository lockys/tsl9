# 原始事件回呼與參數載體

[English](readme.en.md) · [C/C++](../../src/native/receive/runtime_callbacks.c) · [原始證據](evidence.json) · [驗證摘要](summary.json) · [常數指標](constant-reference-audit.json)

新增3個完整原始函式1072B／369指令，C11／C++17原位址碼吻合。接通8614／8C82兩個原本僅有位址參照的回呼，以及既有8B6E缺口；UND由75降至72，沒有新增依賴。

| 原始範圍（結尾不含） | 已確認的靜態行為 |
| --- | --- |
| 8614–888C | 完整48B frame／RA與S0–S9；依原始A1的低16位符號及事件bit分派，保留GP+148/152選擇、1062B資料stride與ROM間接呼叫。第一個RET8684後的全部分支仍在。 |
| 8B6E–8B90 | 保留32B frame，將原A0低8位放SP+15，再對word[0x40174]傳入(773,1,SP+15)。 |
| 8C82–8E18 | 完整48B frame；依序處理旗標1/2/4/8/16/32，含第一個RET8CB6後的分支。旗標2組成26-byte本地載體，含固定字節TSL9、GP+140計數及GP+145資料，再傳入ROM tuple(774,26,SP+4)。 |

26-byte結構呈現廣播資料形態屬推論，未觀察無線傳送；ROM表項、時間單位與硬體效果仍未證。回呼回傳保留原始旗標的XOR行為，不能簡化成任意的16位截斷。四個常數候選19DE0／19DEC／19DFC／1AB34已核對原始AUIPC/ADDI及檔案位置，保存16-byte窗口雜湊供識別；窗口不是已證明的資料長度，也尚未加入typed資料所有者。

主元件17880B code＋674B data，共18554B經原生連結器配置後，逐byte與官方ID2966 BIN相符。來源109個C/H檔、82個原生code單元；166項比較／332個物件通過，舊108檔與973筆產物記錄保持不變。靜態流程999直接轉移中927有實作目標、72只有參照；先前兩個僅載入位址的提供者已接上真實程式。另有328間接轉移、387潛在返回位置；不是完整CFG或執行證明。

整合初試component-v1的檢查器誤將向量表預期長度寫成332B，正向驗證已拒絕；原表始終是328B。修正檢查器後採用component-v2，舊試驗保留但不採用，所有舊code/data保持不變。

候選新增工具：離線事件旗標／26-byte載體檢視器，可比較固定名稱與計數欄位；目前僅提案，不改硬體行為。下一步追查888C／8B90的註冊與輸入處理，以及剩餘提供者／常數長度。全程離線，未執行韌體／HOST模型／ISA模擬或操作硬體。入口0／PT_LOAD=0診斷ELF仍不能燒錄；歷史隱私問題尚待清理，未commit／push。
