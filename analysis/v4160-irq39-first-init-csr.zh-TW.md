# APP 入口至第三個初始化呼叫返回：CSR 0x800 不等於 mstatus

承接 [reset 交接](v4160-irq39-resident-handoff.zh-TW.md)。只核對原 APP；不需要假定 V1.31 已安裝。`0x900c` 進入 `0x9250`；前三個呼叫依序是 `0x18834`、`0x9a42`、`0x1973c`。以各呼叫正常返回、無非同步介入為界，下一個呼叫點是 `0x9260`，並非已進主迴圈。

| PC | 原指令的效果 |
|---|---|
| `0x9a4c`、`0x9a50` | 設 `s2=0x88`，對 CSR `0x800` 執行 CSRRC（rd=x0）。 |
| `0x9a5e` 至 `0x9a92` | 六次直接呼叫，四個不同的 helper；各 helper 的兩分支都只改寫 a 暫存器及時鐘 MMIO，不改 s2。 |
| `0x9ab6`、`0x9abe` | 寫 IRQ39 優先級 byte 與 enable bank 1 的 bit 7，發生在兩條 CSR 指令之間。 |
| `0x9ac2` | 使用同一 s2 對 CSR `0x800` 執行 CSRRS（rd=x0）。未保存進入時的 CSR 值。 |

若該 CSR 按一般可寫位元語意運作，兩步是先清再設 bits 3、7，而非恢復其原值。這兩個編碼的目標都不是 `mstatus` (`0x300`) 或 `mtvec` (`0x305`)；不能單憑 mask 相同就聲稱全域中斷先關後開。晶片對 `0x800` 的特定效果與 IRQ 的實際送達另計。

複核方法：對 SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667` 的 APP，以 `check_v4160_irq_handoff.scan`、基址 `0x8000` 掃描半開區間。`[9008,901a)`、`[9250,9260)`、`[18834,188e2)`、`[9a42,9ad2)`、`[19124,1919c)`、`[1973c,19764)` 分別為 8、5、58、46、48、11 條指令；僅第四區有 SYSTEM，機器字依序是 `0x80093073`、`0x80092073`。呼叫與寫入順序另由原位反組譯核對；區間計數不是動態執行次數。
