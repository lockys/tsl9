# v4.1.60：0x105c4 輸入 addrsig 身分復核

延續 [ABS mapping 對照](v4160-105c4-abs-mapping.zh-TW.md)。在暫存 ET_REL 物件中，依剝除前有效的符號身分（名稱、區段、值、大小、info、other）查找剝除後的唯一對應項目。C11 與 C++17 都從索引 4 移到 3。只恢復 `.llvm_addrsig` 的 `sh_link` 並保留原索引 4，無法找回原身分；把 entry 改成 null-symbol 索引也不能通過。使用重新找出的索引 3 並指向剝除後的符號表，才重現原輸入身分。此驗證只針對本次固定的一筆、一位元組 entry，並非通用 ELF 修復器。

一般 Python 與 `-O` 各完成 20 組比較：兩種語言、五種候選變體、套用 72 個別名前後。重新對應索引的候選沒有額外的聚合符號項目；目標 12 bytes、配置區段、重定位投影與 RISC-V attributes 保持一致。聚合的 `.llvm_addrsig` 仍是基準 10,595 bytes、候選 10,594 bytes，兩者 `sh_link=0`。輸入身分復核不能替代聚合身分驗收。

下一步應檢查保留各輸入符號表、直接交給最終連結的診斷路徑能否重現原配置；不要直接修改聚合的 `sh_link` 或放寬正式驗收。原 BIN 與正式來源未修改，未連接設備；本提交僅發布驗證報告。
