# v4.1.60：第二條 resident 基準欄位讀取路徑

接續[六位元組讀取函式](v4160-resident-six-byte-getter.zh-TW.md)。對同一組 SHA-256 固定的 V1.30／V1.31 參考映像，這次追蹤將狀態內部地址放在來源參數的呼叫，而非只比對欄位位移。

| 參考版 | `AUIPC/JALR` 呼叫窗 | `a1` 來源半開區間 |
|---|---|---|
| V1.30 | `0x67f30..0x67f38` | `[0x20003350,0x20003356)` |
| V1.31 | `0x68096..0x6809e` | `[0x200034a0,0x200034a6)` |

兩版皆傳 `a2=6`、`a0=原 a0+54`，呼叫目標 `0x20000332`。來源是各版狀態的 `+232..237`，並非生成欄位 `+244..255`。兩版映像的 `0x405a2` 均含相同 58 bytes（SHA-256 `558a82658cb54901945d4c2884f2e87e763f64d57c0cafa831307beb44ae0c36`），候選 slot `0x4004c` 也都指向 `0x20000332`。在該 body 按 RAM 地址映射的條件下，`0x20000354..0x20000366` 逐 byte 讀 `a1+i` 再寫 `a0+i`，方向由原始 load/store 欄位確認；不是以函式名稱推斷。若到達該呼叫且指標非零、存取成功，來源範圍不依賴目的物件位址。目的物件是否與全域狀態別名，仍未證實。

兩版的映像雜湊、來源／目的／長度欄位、間接跳轉目標及 58-byte body 均通過 Python `-O` 檢查。每版另用 4 組合成目的位址核對讀取範圍，包括原地、向前一 byte 重疊及 32-bit 環繞；這是局部資料流投影，不是 CPU 或硬體驗證。未連設備或修改原 BIN／正式來源；尚未找到啟動比較器之外讀取生成欄位的證據。
