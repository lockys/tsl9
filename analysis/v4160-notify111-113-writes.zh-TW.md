# 通知 111／112／113：哪些寫入與取消旗標分開？

承接[選擇值 64–66](v4160-selector0-cancel.zh-TW.md)。原 APP SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。`0x167a6` 三次分析的是同一函式的三種輸入，不是依序發生的三次通知。

* 第一表每輪讀 `[gp+96]`，掃 127 對 byte；key 等於通知碼才在 `0x167d4` 呼叫 `0x155d0`，參數是同筆的下一個 byte，不是通知碼。後兩表對索引 1..35 依序重讀 `[gp+100]`、`[gp+104]`；對這三碼，low 必須等於通知碼，且 `(high & 3)==2`。命中才呼叫 `0x1798a(表號,索引)`。一次通知可以不命中，也可多次命中。
* 由 `0x186ba..0x186da` 的 reset copy，初始化來源 `0x1ab60` 的 +84/+96/+100/+104 四個 word 分別為 `0x2000c29c/c494/c594/c694`（後三者同在 `0x2000xxxx`）。三表比對會用的 127 個 key 和後兩表的 140 個 low/high byte 都在 reset 清零區。若只有 reset 的結果而沒有之後的表更新，三種通知均不命中；這不是發送當時的表快照。
* `0x155d0` 前段讀設定指標的 **+4 bit 3**，不是呼叫者最後讀的 **+0 bit 4**；`0x15604` 的直接清零寫到 gp+358，隨後尾跳。`0x1798a` 表 1 路徑寫索引至 gp+376，再呼叫 `[0x40058]`；表 0 路徑經 `[0x4004c]` 要求複製 7 bytes 至棧，依內容可寫 gp+367/+368，再呼叫 `0x1787c`。
* `0x1787c` 的入列支路以 `Q=0x2000c8ac`、`i=U8[Q+1]` 要求複製到 `Q+3+7*i`，並寫 Q+1/Q+2。以單純七 byte 複製檢查全部 256 個索引，目的區間均不含 `0x20004054..57`（指標槽）及 `0x2000c29c`（初始所指首 byte）；不必假定索引一開始就小於 16。計數達 16 跳過入列，後續可能尾跳 `0x17666`。

因此可排除上述固定寫入和有界複製直接改動**初始綁定**；不能排除其他 `0x155d0` 分支、`0x17666`、間接服務、不同的即時指標或棧重疊。呼叫者必須在通知返回後重讀，不能由通知碼預測是否取消。原 BIN 靜態解碼；未連設備。
