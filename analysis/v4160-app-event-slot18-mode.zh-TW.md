# v4.1.60：佇列記錄與分派模式分開讀取

接續[固定表來源比對](v4160-app-event-slot18-source.zh-TW.md)，本輪釐清 APP 的模式值是否從同一筆佇列記錄取得。

- 已核對的佇列續段在 `0x12d84` 呼叫 `0x81aa`，將回傳值用於 `0x12d88` 的零值判斷；若續行，`0x12d8a` 把 `sp+8` 放入 `a0`，`0x12d8c` 再呼叫 `0x14d2e`。因此這個判斷值不是傳入的模式參數。
- `0x14d34` 將記錄指標保存於 `s0`；`0x14d36` 另呼叫 `0x829e`。getter 在 `0x829e` 以 AUIPC 形成 `0x2000c29e`，隨後從 `-745` 的位置讀取一個無號 byte，亦即固定 APP RAM 位址 `0x2000bfb5`。它不以輸入記錄指標計算讀取位址。正常返回後，`0x14d3c` 使用此回傳值作無號範圍比較；值 `1` 對應 `0x1a6b8` 模式表第 1 項 `0x14d5e`。

因此在這條路徑上，記錄首半字與模式是兩次分開的讀取；固定表命中並不能說明何時 APP 模式為 1。未證明 RAM byte 的所有寫入來源、實際時序或任意別名。下個里程碑是盤點此 RAM byte 的初始化及可辨識的寫入者，將直接證據與推論分開。

離線 Python `-O` 通過原 APP SHA-256、3 個指令窗（54 bytes）、3 個 JAL 目標、getter 位址與模式表項；另以反組譯對照三個指令窗。未連設備或修改原 BIN／正式來源。
