# OTA 回覆、清理與重啟路徑

[English](readme.en.md) · [C/C++](../../src/native/receive/ota_replies.c) · [原始指令](evidence.json) · [驗證摘要](summary.json)

新增六個完整原始函式，共334B／127指令、29個私有區塊、18個控制重定位。C11／C++17編譯結果一致，六個既有入口已接上真實實作；展開16E0C、9EA6兩個下游依賴，未解析提供者由77降為73。

| 原始範圍 | 已確認的靜態行為 |
| --- | --- |
| 8E18–8E6A | 讀取GP+150／154半字，與0xFFFE比較，依原分支呼叫ROM slot0x4017C；保留16B frame與所有尾跳。ROM呼叫用途尚待確認。 |
| 99E8–9A24 | 兩次1917E與兩次16E0C呼叫後，清除CSR0x800的0x88位元、寫入0xE000E048，停在9A22自迴圈。符合重啟請求形態；實體效果未證。 |
| 9B8E–9C0A | 保留32B frame，經ROM slot0x40070請求1026B，空指標直接返回；放入兩byte頁號，從原始頁位址搬移1024B，呼叫8A56後經slot0x40068釋放。此函式本身沒有新增頁號防護。 |
| 9EE0–9EF0 | 以參數1呼叫9EA6，恢復原frame後以參數0尾跳99E8。9EA6仍未實作，不推定其持久化效果。 |
| 13E98–13EB4 | A2與A3皆非0時尾跳13B4C，否則尾跳8A56；保留A6/A7暫存與所有參數。 |
| 13F66–13F7E | 取A2低byte置於原SP+15，長度1，呼叫13B4C，再恢復32B frame。 |

更正：8E66直接跳到8E4A的JR T1，會跳過8E48的SP+=16。先前報告誤把未經過的指令算入此路徑，不能據此判定堆疊不平衡。C/C++與原廠bytes原本即正確，沒有改動；實體呼叫端／ROM契約仍未證。舊報告已保留本機；先前最終收據屬歷史快照。

主元件20042B code＋714B data，共20756B經原生連結器配置後逐byte等於官方ID2966 BIN。完整來源112個C/H檔、85個code單元；含獨立指標資料共172項比較／344個物件。舊111個來源與1009筆產物記錄不變。

靜態流程涵蓋6964指令、1146個直接轉移：1072指向已重建指令、74仍僅具參照；6422個一般下一指令位置無缺口，425個可能呼叫返回位置已整理。另有361個暫存器間接轉移、10個MRET與1個EBREAK，尚非完整CFG或實機證明。

首次component-v1因設定把三個既有實作誤列為新依賴而被檢查器拒絕；修正清單後建立全新的component-v2並通過，失敗產物保留，未放寬檢查。

字母E仍只是一段回覆證據，不代表重啟或功能驗證完成。BOOT／APP角色、實體位址別名、ROM／RAM／IRQ與OTA相容性尚未證明；診斷ELF入口0、PT_LOAD=0，不能燒錄。未執行目標／HOST模型／ISA模擬，未操作硬體或網路；歷史隱私問題未清理，未commit／push。

下一步補齊16E0C與9EA6並確認其餘ROM／呼叫契約。值得新增的工具是離線OTA映像區域／完成階段檢視，區分回覆、讀回、清理及重啟證據；目前僅提案，不改既有識別與狀態檢查。
