# v4.1.60：佇列寫入的 C/C++ 重播

接續 [SPI 長度來源](v4160-app-event-queue-length-spi.zh-TW.md)。本輪以既有 `experiments/tsl9-ring-insert/verify.py`，用本機 NDK LLVM 18 在新輸出目錄重新編譯與原位連結 `ring_insert.v3.c`。C11 和 C++17 各得到 92 bytes／32 條指令與原 BIN 相同，各自通過 40 項負向控制；兩路均報 `firmware_ready=false`。

這確認既有重建保留了原指令中的寫入順序與欄位寬度：先以半字寫槽位識別值，再於 `0x12bfa` 以 byte 寫槽位 `+2`；接著重新讀取複製提供者並傳入完整 `a2`。正常返回後才以當時的 `s0/s1` 寫 `+11`。長度欄位的截斷與呼叫參數的寬度不同；本輪未執行提供者或設備，未變更正式來源，也不把已知 SPI 呼叫點的 1–8 推廣到其他來源。

下一步：回到分派樹，核對第 18 槽更新分支所需的模式與記錄識別值，將已驗證的佇列寫入與尚未證實的來源路徑分開。
