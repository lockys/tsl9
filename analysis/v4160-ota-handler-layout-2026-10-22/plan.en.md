# OTA provider and placement evidence plan

[繁體中文](plan.zh-TW.md)

The full goal remains a C/C++ rebuilt BIN usable on the original hardware through its BLE updater. Partial links, numeric bounds and ROM candidates are not compatibility admission.

1. Reuse the `e2369bd` 568-byte component and actual D/P artifacts. Probe one full32-command C switch dispatch. If machine code is identical, preserve the negative result without promoting a model or sweeping compiler flags.
2. Trace real S reply consumers through wrappers, packet assembly, allocation/copy slots and existing TX. Identify numeric-pointer escape and exact conditions for a two-byte-content projection. A simple candidate copy leaf does not discharge other callees, aliasing or asynchronous observers.
3. Re-read selected BOOT ID2580 command bytes and a minimal scheduled transfer. Derive Runtime page bounds from actual unsigned guard/address arithmetic. Numeric subsequent pages are distinct from free Flash, installed BOOT, NV ownership and OTA acceptance.
4. Partially link existing real `source-integrated.o` and the568-byte native object using pinned `ld.lld -r`. Check all original allocation bytes/relocation semantics, nine real providers, the unresolved ROM entry and original caller. Retain old530-byte and new C bodies. Do not reroute entry or use ABS/stubs/defsym/undefined-ignore options.
5. Default checks are metadata-only. Explicit actual paths enable BOOT/Runtime, native/ELF/candidate reads or a fresh partial link. Actual receipts require read-only replay. Repair unpublished checker defects before sealing a single flat CLI.
6. Repeat relevant actual checks/partial links in delivery and publication trees, preserve existing files, then publish the authorized private milestone. Do not recompile the sealed568-byte component or rerun unchanged HOST tests.

`-r` does not establish final relocation/JAL reach or redirect the original caller. Original placement still has a38-byte excess, but exactly530 bytes is not necessary for every valid layout. Future placement needs real providers, live ingress/continuations, observable ABI, Flash/NV/initializer layout and updater-format evidence. No unproved free space or original-byte fallback.

No final ELF, new BIN, target execution/emulation, hardware access or vendor API. Original hardware/ROM/BOOT/RAM/IRQ/Flash/OTA acceptance and recovery remain open.
