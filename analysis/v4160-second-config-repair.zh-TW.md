# 第二個設定區塊：略過、重建及下一個讀取

接續[第一區修復](v4160-config-repair-return.zh-TW.md)。原 APP 的 `0x13224` 讀 D+255（D=`0x2000c494`）。等於 `0x5a` 時，`0x13230` 直接跳到 `0x13238`；這個判斷沒有讀前 255 bytes，不能當成整頁內容驗證。

不相等時，`0x13234` 呼叫 `0x12e86`，它向 `[0x40048]` 請求 `(D,0,256)`。返回後，APP 先在 +255 寫 `0x5a`，再依序於 +0、+4、+8、+12、+16 各寫一個常數 word。若前一步確實填零且無其他寫入，+20..+254 仍為零。這是記憶體配置，不推定五個欄位的用途。

`0x12ee2` 還原框後尾跳 `0x12e54`；後者另開 272-byte 框，向 `[0x4004c]` 請求從 D 複製 256 bytes 到框底，再呼叫 `0x9c0a(0x08077900,框底)`。這次複製長度涵蓋整頁，與第一區的 112 bytes 不同。這不代表頁面已落盤。若所有呼叫正常返回並保留堆疊，回到 `0x13238`；下一次請求是從 `0x08077800` 讀 256 bytes 至另一個 RAM 緩衝 `0x2000c30c`，再檢查它自己的 +255，失敗則呼叫 `0x12f18`。

離線核對原 APP SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`。獨立從指令位元取 RAM 位址、兩個 256 長度、五個 word store 位移與三個跳轉；一般及 `-O` 均通過，六個指令變造均遭拒。未接設備，未假定實際 resident 版本或 Flash 狀態。
