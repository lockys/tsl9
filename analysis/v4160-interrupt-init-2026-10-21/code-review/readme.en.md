# Readable initialization implementation review

The reviewed implementation is `experiments/tsl9-v4160-interrupt-init/src/interrupt_init.c` and its public header. Hosted and freestanding variants share the same business logic; the `TSL9_IRQ_HOST_TEST` conditional selects only the MMIO and CSR access primitives. The independent raw-source basis is the immutable sibling `abi-review/final-audit.json`: original ID2966 runtime SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`, covering 264 original bytes / 94 instructions.

No blocking source mismatch was found. All four helpers use one fresh 32-bit read per invocation, branch on any nonzero `enabled`, perform OR or AND with the complemented mask, write one word, and return that word. Entry `0x9A42` reproduces the six helper calls, the six ordered tail stores, and CSR clear/set mask `0x88`. Its result preserves the final fresh masked word observed in original A0. It does not merge the three independent stores to `0xE000E104`, cache a word between set/clear, restore an old CSR snapshot, invent a success status, or introduce error cleanup.

The host backend records numeric addresses and performs ordinary-memory calculations only. An independent C harness checks all helper domains, zero and nonzero selectors including upper-bit values, complete 20-effect traces with separately supplied fresh samples, final return values, and current CSR changes injected before the last set. It exercises deterministic varied bit patterns without executing original firmware. The expectation table was derived from the sealed original rows, independently of the parent's test implementation.

`audit.py --language both` compiles the same reconstructed C as C11 and C++17 using the shared portable compiler bootstrap. Each mode also compiles three deliberately incorrect variants, then runs those actual host executables and requires assertion rejection: skipped clear-side reads using a cache; restoring a saved entry CSR; and widening one byte write to a word. A compilation failure is not counted as a rejected behavioral mutant. Receipts identify the compiler, actual executable, compile options, logs, source inputs, raw-source seal, and their SHA-256 digests. The review pins the parent's C/H, test files, verification script, and shared compiler helper before and after each mode.

Both independent language suites passed 4 groups / 34,267 assertions, and all six compiled behavioral mutants were rejected. The parent's final suites passed 4 groups / 6,680 assertions per mode, with the 264-byte / 94-instruction raw source gate and 94 rejected raw mutations. `check-review.py` validates the actual executable/compiler digests and receipt closure. One explicitly recorded context pin in the C receipt predates the parent's final `verify.py`; that script is neither compiled nor invoked by the independent harness. All compiled C/H/test and shared compiler-helper inputs match current files. The final parent script is bound by both formal parent receipts and the independent C++ receipt; the older C receipt remains unchanged.

The native primitive uses width-specific `volatile` accesses and volatile CSR assembly with a compiler memory clobber. Hosted behavior does not prove the native compiler emits matching operations; that requires the separate native compilation/IR audit. Even a successful native compilation cannot establish source-identical caller-saved register residue, original stack layout, instruction timing, installed CSR meaning, privilege, interrupt entry/return ABI, physical MMIO effects, or OTA compatibility. The new public symbols are reconstruction symbols, not proven aliases for original firmware addresses. No hardware, original RV32 execution, ISA emulation, or network access is part of this review.
