# 可讀的原生中斷初始化元件

新的 `experiments/tsl9-v4160-interrupt-init/src/interrupt_init.c` 已實際編譯為 RV32 C11 與 C++17。兩種模式產生的原生物件完全相同。初始化函式為 118 位元組、43 條指令；原始 `0x9A42..0x9AD2` 範圍為 144 位元組、46 條指令。四個新的 RCC 輔助函式各為 22 位元組。所有函式使用重建程式的新符號名稱，沒有冒充原始位址符號。

兩種模式都實際連結出 `COMPONENT-ONLY-NOT-FIRMWARE.elf`，沒有未定義符號、函式庫呼叫、可寫資料或占位實作。在診斷用位址 `0x1000` 連結後，初始化函式的機器碼保持一致。此元件尚未替換既有 691 個配置區段映像中的任何區段。

LLVM IR 與實際輸出的機器指令分別驗證相同的 20 項依序效果：清除 CSR `0x800` 的 `0x88` 遮罩；六次重新讀取 RCC 32 位元值及六次 32 位元 RMW 寫入；六項依序的 PFIC 位址寫入，保留原始 byte／word 寬度；最後設定 CSR `0x800` 的 `0x88` 遮罩。傳回的 `A0` 是最後一次重新讀取後的 RMW 結果。此 CSR 序列不是還原先前快照。一般輔助函式的 IR 也保留「零」與「所有非零 32 位元旗標」的選擇行為。每種語言均將四個錯誤版本實際編譯後拒絕：錯誤 CSR 遮罩、錯誤 PFIC 存取寬度、遺失重新讀取，以及杜撰狀態回傳值。

`results.json` 記錄來源、編譯器／連結器／objdump、真實建置收據、物件與連結檔雜湊及驗證限制。本機 build 目錄保留物件、IR、反組譯、日誌及已編譯錯誤版本。從已發布專案重新編譯時不需要這些舊產物。

## 重新執行靜態驗證

需要 Python 3.10 以上，以及支援 RV32IMAC 與 Zicsr 的 LLVM 工具。指定自己環境內的執行檔：

```sh
python3 analysis/v4160-interrupt-init-2026-10-21/native-plan/verify_native.py \
  --project-root . \
  --clang /path/to/clang \
  --linker /path/to/ld.lld \
  --objdump /path/to/llvm-objdump \
  --language both
```

分析工作區的路徑前綴是 `apk-analysis/tsl9-v4160-interrupt-init-2026-10-21/`；發布版本使用 `analysis/v4160-interrupt-init-2026-10-21/`。也可用 `--tool-dir` 指向三個工具所在目錄。每次建置會記錄完整旗標。本次 Windows 驗證採用 Android NDK 27.1.12297006、Clang 18.0.2，主要旗標為 `--target=riscv32-unknown-elf -march=rv32imac_zicsr -mabi=ilp32 -Os -ffreestanding -mno-relax`。若不同編譯器輸出超出驗證器支援的指令或 IR 形式，程式會明確失敗，不會自動放寬檢查。

流程只有本機編譯、連結、ELF 解析、IR 分析及靜態反組譯。機器碼證明只標註直線程式的常數定義與新讀值的運算關係，不建立客體 RAM／CSR 狀態、不執行指令、不模擬 ISA，也不進行硬體 I/O。

`audit.py` 同時提供共用 ELF 解析器及獨立的歷史基準稽核。其主程式會讀取指定的既存來源映像建置；`verify_native.py` 不需要執行此歷史主程式。歷史稽核重新檢查真實 C／C++ 合併物件：691 個非空配置區段、8,280 筆原始 RELA，以及唯一真正未定義的駐留入口 `__tsl9v4160_rom_entry`。另有一個空 `.text` 標記，不提供程式實作。物件中可見一筆從 `0x9258` 指向 `0x9A42` 的直接重定位，沒有其他外部區段直接引用；這不能排除間接引用，也不能證明實機駐留程式的內容。

## 尚待完成的整合條件

1. 118 位元組僅證明此編譯器輸出的初始化函式小於原始 144 位元組範圍；尚未配置到 `0x9A42`、處理其餘 26 位元組、驗證內部／間接引用，或證明原映像佈局相容。完整映像需要新的替換檢查，明確限定可更動的來源並保護其餘所有區段、符號、重定位及資料。舊有不可變的位元組一致性檢查仍須保留。
2. 新函式為 leaf，移除了原本 16 位元組堆疊框架及六組輔助函式呼叫／返回。它遵守一般 callee-saved 暫存器要求，但 caller-saved 暫存器殘值不同。靜態來源可支持最後的原始 `A0` 結果，尚不足以證明完整原始 C ABI、非同步中斷 ABI、中斷期間的暫存器觀察或時序等效。替換原始入口前仍須證明真實呼叫鏈及 IRQ 進入／返回行為。
3. 實際板型、MCU 修訂版、記憶體範圍、已安裝 ROM／駐留服務、PFIC／CSR 行為及真正周邊副作用仍未驗證。原始來源映像仍缺少一個駐留實作；獨立元件連結成功不代表實體 OTA 相容。

沒有執行原始或重建的 RV32 程式。此驗證器沒有產生韌體 BIN、沒有燒錄裝置，結果尚不能用於藍牙 OTA。
