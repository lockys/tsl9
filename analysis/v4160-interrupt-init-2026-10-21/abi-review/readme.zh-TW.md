# ID2966 初始化 ABI 審查

此獨立審查涵蓋原始 runtime SHA-256 `0ee64183daaa140acac7dbb6c0f7c26d1fe625344ed158151731a9b2632fb667`，基址 `0x8000`、入口 `0x9A42` 及四個直接 helper。分析僅讀取原始位元組與靜態 RISC-V 反組譯；未執行原始指令、未模擬 ISA、未接觸硬體，也未證明 OTA 相容。

## 已確認的原始行為

`0x9A42..0x9AD2` 共 144 位元組、46 條指令。`0x19124`、`0x19142`、`0x19160`、`0x1917E` 各為 30 位元組、12 條指令；合計 264 位元組、94 條指令。`audit.py` 核對原檔身分、連續指令範圍、逐條原始位元組、六次直接呼叫及接續位址、CSR 運算元、堆疊進出與既有入口原生指令擷取。JSON 輸出保留完整來源列。

入口先把 SP 減 16，再將 S2、S1、S0、RA 儲存在偏移 0、4、8、12。`0x9A50` 清除 CSR `0x800` 的 `0x88` 位元；`0x9AC2` 設定這些位元。這不是保存並還原原有 CSR。將其稱作中斷遮罩屬於硬體解釋，僅由指令運算元尚無法證明。

| 呼叫位址 | Helper | 每次重新讀取的 32 位元位址 | 遮罩 | 運算 |
|---|---|---|---|---|
| `0x9A5E` | `0x19142` | `0x4002101C` | `0x02020006` | OR |
| `0x9A6A` | `0x19124` | `0x40021018` | `0x0000101D` | OR |
| `0x9A74` | `0x1917E` | `0x40021010` | `0x02020006` | OR |
| `0x9A7E` | `0x1917E` | `0x40021010` | `0x02020006` | AND 補數 |
| `0x9A88` | `0x19160` | `0x4002100C` | `0x0000101D` | OR |
| `0x9A92` | `0x19160` | `0x4002100C` | `0x0000101D` | AND 補數 |

Helper 判斷 A1 是否為零，不是判斷是否等於 1。每次呼叫都重新讀取該 word，包含設定後的清除；外部值可能改變，不能沿用首次讀值。最後的清除在 `0x19172` 讀取、`0x19174` 對 A0 取補數、`0x19178` 計算 AND、`0x1917A` 寫出。

隨後依序寫入：byte `0` 至 `0xE000E42D`；word `0x2000` 至 `0xE000E104`；byte `0x20` 至 `0xE000E424`；word `0x10` 至 `0xE000E104`；byte `0x30` 至 `0xE000E427`；word `0x80` 至 `0xE000E104`。相同 word 位址的三次操作是獨立 store，不能合併數值或改成讀改寫。本範圍沒有 fence 或延遲指令。

## 可讀 C 的最小介面

可採 `uint32_t init_9a42(const io_ops *io)`，搭配同步 `read32`、`write32`、`write8`、`csr_clear`、`csr_set`。回傳值保留原始 A0：**第六次重新讀取的 word** AND `0xFFFFEFE2`。原始程式沒有設定 C 層級的成功狀態；`void` 介面會丟失已觀察到的 A0。主機測試若另外加入狀態，需標示為新增的主機契約。

同一份邏輯可在主機使用一般記憶體記錄 backend，在另外編譯的原生 backend 使用符合寬度的 volatile MMIO 與自訂 CSR 指令。原生 CSR 組語需用 volatile 與 compiler memory clobber，維持編譯時的存取次序。編譯器屏障不等於硬體 fence，無法證明匯流排次序、中斷語義、特權可用性或實體作用。

## ABI 與環境限制

在未中斷、正常返回且堆疊內容未變的路徑，S0/S1/S2、RA 從原本槽位載回，SP 回到入口值。實際指令是**重新讀取堆疊**，不是不可改變的快照；外部若改變 SP 或堆疊，後續讀值與返回目標會改變。最後 helper 正常返回後 A0 為上述遮罩結果；入口返回時 A1 為 0、A4 為 `0x80`、A5 為 `0xE000E000`。其他未儲存 GPR 未被本範圍修改，沒有 GP 相對 RAM 寫入。

一般 C 可維持標準呼叫邊界並回傳觀察到的 A0，但無法保證原始 caller-saved 暫存器殘值、固定 save-slot 位址與次序、指令 PC、完全相同的 prologue 大小、自訂中斷進出慣例或非同步 handler 互動。標準 C 不提供原始 SP/RA 機器狀態。即使只宣稱特定編譯器的暫存器行為，也需審查編譯結果；編譯成功無法證明實際已安裝的執行環境。

若注入主機錯誤，不應自行用 C cleanup 設回 CSR 位元，除非明確標示為新增主機行為；原始直線路徑沒有這種錯誤返回。遇到失敗而停止的主機 trace 只證明已完成的前綴。MMIO 讀與寫不是一組原子操作，本審查不確認實體暫存器名稱、重置效果或讀取副作用。

執行 `audit.py --image <原始 BIN> --r2 <radare2 路徑> --native-capture <initialization_native.c>` 可輸出 JSON。靜態核對只證明此限定範圍的來源對應，並非可執行的原生替代品或可燒錄映像。
