# 主程式服務與周邊設定重建

[English](readme.en.md)

[原始碼](../../src/native/startup/main_services.c)涵蓋五個完整函式，共974B／328指令；同一份C可編譯為C11、C++17，逐byte與原廠碼核對。主元件22840B code＋714B data、1419個RELA、1936個非零FUNC區塊及71個真實別名。這些區塊數不是原始功能數。

| 原始範圍 | 已確認的靜態行為 |
| --- | --- |
| 9334–937E | 32B框架；取得資料後處理前12B，初值0x5AA5，每輪依序呼叫9290三次；9290本體仍缺，沒有讀取實際裝置識別資料。 |
| 12506–1264E | ROM槽40048清除24／36／12B；40080接收119C8、11442回呼位址，回傳低8位寫入狀態；保留400154／400168的數值參數與原始順序。 |
| 14C8A–14CC8 | 清除名義RAM位址2000C794起10B，再寫入兩個0xFFFE半字與四個零byte；此起點緊接先前設定區的名義結尾。 |
| 154A6–1552A | 清除GP＋352起6B，依序呼叫26個原始入口，恢復RA／SP後尾跳18604；沒有把1552A後鄰接函式混入。 |
| 17040–171BA | 註冊16F00回呼；依GP＋108的u32值作DIVU／8,000,000，減一後截低16位寫4000082C，再從該半字新讀值右移一位寫4000083C。保留GPIO式設定與40013000的18B描述子／啟用呼叫。 |

完整參數、PC與名義位址在[初始化契約](initialization-contracts.json)，原始指令在[證據](evidence.json)。ROM槽用途、計時器／SPI／GPIO名稱屬候選解讀；實際時脈、腳位、外部周邊與MCU型號尚未確認，不能據此推定TSL9就是特定WCH料號。

兩種語言的診斷ELF一致；選定23554B在原始位址配置後與官方BIN相同，93個區段只合併相鄰已知byte，不填未知缺口。入口0、PT_LOAD為0，**不是可燒錄韌體**。流程核對涵蓋7912指令、1257個直接轉移、7336個一般順序位置及532個呼叫返回位置；419個暫存器間接轉移、10個MRET與8034→8038的EBREAK／向量資料邊界仍沒有執行期證明。

接上5個舊入口，同時展開31個真實依賴，因此未提供者由70變96；其中92個是直接轉移依賴，3個僅作回呼位址，1個為1A69C的4B不透明預設資料。未以空函式、猜測值或ABS FUNC代替。詳見[待追查清單](next-providers.json)。

目前共117個C/H檔，來源／物件比較182組、364個物件；舊116個C/H、178組比較與1069筆既有產物記錄保持不變。[摘要](summary.json)區分已接受的v3配置與兩次因驗證器舊計數未更新而停止的試次，未把停止的試次列為通過。

值得考慮的新功能是**唯讀啟動診斷**：回報回呼選擇值與時脈／週期／比較值，協助判斷周邊初始化；尚未實作，須先證明ROM API、硬體對應與資料公開方式。本輪沒有執行韌體、HOST模型、ISA模擬或硬體操作；完整啟動、ROM、記憶體、中斷及OTA相容性仍未證明。
