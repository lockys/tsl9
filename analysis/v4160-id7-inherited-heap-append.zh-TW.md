# 用初始化後的 heap 接起 40-byte 配置與入列

相較先前直接指定配置結果，此次從 128 份初始化後的合成 RAM 分別建立兩個獨立分支：空佇列與已有一個獨立節點的佇列。兩邊沿用 heap、ID 欄位 7、任務計數 8，不預填新區塊。另建呼叫框架與 24-byte 訊息來源；沒有重播觸發此次訊息的事件。

- 訊息 wrapper 向 0x20000040 傳 (40,0xf020)。逐指令跑 V1.31 候選 allocator 到 0x20000270，而不是填入 a0；每次得到非空 P，均在 APP pool 內，且 P−2 處的配置標籤為 0xf020。
- 所得 P 共有 5 個：0x200043b4、0x200043cc、0x200043e4、0x200043ec、0x20004404。同一份 RAM 的兩個佇列分支所得 P 相同。256 次是分支重播，不是一次連續配置 256 塊。
- 同一份分支 RAM 上，wrapper 寫入連結字 0、長度 32、標記 255，傳回的訊息指標是 P+8。之後的入列檢查讀回 (0,255)，把標記改為 7，寫入表頭或既有尾節點，再抵達 0x4354a(7,0x8000)。

本機一般及 -O 各通過 256 條配置至入列路徑，並重跑先前 8 條成功與 4 條注入空指標的對照。佇列頭、訊息來源與外設仍屬合成模型；24-byte 複製按成功行為模擬，未執行派送或觀測裝置。這些 heap 樣本沒有出現耗盡，不據此推斷任意狀態配置成功。
