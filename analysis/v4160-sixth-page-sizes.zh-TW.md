# 第六設定區：133-byte 記錄與 256-byte 頁面

依 v4.1.60 原 APP（SHA-256 見同目錄 `check_v4160_sixth_page_sizes.py`），三個 133-byte 請求與底層頁寫入是不同操作：

1. `0x132c8` 請求自 `0x08077500` 複製 133 bytes 至 `D=0x2000c40c`，`0x132e8` 只讀 `D+132`。若為 `0x5a`，走 `0x13304` 還原並返回，不修復。
2. 不等時，`0x132f8` 尾跳 `0x13108`。請求填零 D 的 133 bytes，返回後 `0x1312a` 將 `D+132` 設為 `0x5a`；若填零成功且無其他寫入，記錄是 132 個零加標記。
3. `0x13134` 尾跳 `0x130d6`，請求將 D 的 133 bytes 複製至棧，再呼叫 `0x9c0a(0x08077500, sp)`。`0x9c34` 將目的地與來源指標交給 `0x18ef2`；底層不把 133 當迴圈上限。
4. `0x18efa` 對齊目的地；進入資料迴圈時 `a5=0`（狀態位已清），`0x18f16` 設上限 256。每次讀一個 32 位元 word 並寫一個 word，等待狀態後偏移加 4，直到 256。若輪詢皆退出且存取成功，為 64 個 word。**記錄內容只確定前 133 bytes；不能將其餘 123 bytes 宣稱為零或已恢復的設定。**

驗證方式：`python analysis/check_v4160_sixth_page_sizes.py` 及 `python -O analysis/check_v4160_sixth_page_sizes.py`。檢查原碼的位址、長度、標記、跳轉與迴圈欄位，另對六處指令做變造對照。本結果不證明 resident 複製實作、硬體完成狀態或實際 Flash 內容。
