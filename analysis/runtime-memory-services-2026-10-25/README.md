# ROM 記憶體服務包裝

[English](readme.en.md) · [C/C++ 來源](../../src/native/receive/runtime_memory_services.c) · [指令與參數證據](provider-contracts.json) · [統計](summary.json)

重建14個完整包裝函式，共280B／91條指令。都從0x40048載入指標到T1，傳入目的位址、A1=0與A2長度後尾跳。0x40048是指標儲存位置，不是函式入口。其形狀符合保存的WCH SDK預設tmos_memset介面；原機函式身分、私有ABI與實際記憶體效果仍未證明。

| 原始入口 | A0目的位址 | A2長度（B） |
|---|---|---|
| `0xA37C` | `GP+172*` | 5 |
| `0xB0BA` | `0x2000BEE0` | 12 |
| `0xB5E0` | `0x2000BEEC` | 16 |
| `0xCEAA` | `0x2000BF24` | 20 |
| `0xD196` | `GP+232*` | 4 |
| `0xD4F4` | `0x2000BF5C` | 12 |
| `0xD75A` | `GP+252*` | 5 |
| `0xE0A4` | `0x2000BF68` | 28 |
| `0xF0B0` | `0x2000BF84` | 12 |
| `0xFA50` | `GP+276*` | 5 |
| `0xFB0C` | `GP+284*` | 3 |
| `0xFF44` | `GP+288*` | 4 |
| `0x10158` | `0x2000BFA8` | 12 |
| `0x10276` | `GP+304*` | 4 |

`*` GP為執行時暫存器；工具的數值範圍檢查假設其等於啟動值0x20004000。14組請求長度合計142B，僅為靜態總和，不代表實際執行。條件性目的區間都位於目前初始化清零範圍；E0A4區間也包含先前D76C／D7A4用到的五個狀態byte。這只是位址對照，不代表已驗證清零效果或實車功能。

238組比較／476個物件通過；55,872B原址相符，覆蓋率72.75%。補齊14個入口，仍有71個編譯器未定義符號；此計數不涵蓋未知的間接ROM目標。沒有新增資料或BIN，未執行韌體或連接硬體。

## 唯讀離線工具

需要Python3.10+，不需要編譯器或逆向引擎；在專案根目錄執行：

```sh
python3 experiments/tsl9-runtime-memory-services/inspect-rom-memory-calls.py --json
```

Windows可用`py -3`。只接受固定雜湊的ID2966 V4.1.60原始BIN；不會下載檔案或連接裝置。可用`--sdk-header "$TSL9_SDK_HEADER"`指定既存、固定雜湊的SDK header；未提供時，輸出會標明未核對header。工具僅使用標準函式庫，本輪實跑Windows，其他平台尚未實跑。
