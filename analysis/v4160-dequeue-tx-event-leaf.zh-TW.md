# TX 選好 bank 後是設位，不是呼叫 handler

接續[雙查詢](v4160-dequeue-ccc-repeat.zh-TW.md)。APP `0x8b24..0x8b52` 將 bank 左移兩位，設 a1=1，先寫兩個描述半字，再從 `gp+148+4*bank` 讀 task ID 到 a0，以 `jr t1` 尾跳 `[0x40050]`。此處沒有把封包指標當作 a0 傳給服務。

兩版參考的服務各 64 bytes。在 Xwchc 解讀下，它們只有一條無號條件分支、兩個 ret、沒有 call 或間接派送。都先保存 `0x4002420c` 的 word、寫零、執行 `fence.i`；正常退出時寫回先前讀值。因此「只設事件位」描述的是排程效果，不代表沒有周邊寫入。

| 版本 | 函式 | 任務數（byte） | 待處理事件表指標（word） |
|---|---:|---:|---:|
| V1.31 | 0x4354a | 0x2000319d | 0x200031e4 |
| V1.40 | 0x435d6 | 0x200031ed | 0x20003234 |

若 ID >= 任務數，返回 3，不讀寫事件表。否則讀取該版指標 P，將 `U16[P+2*ID]` 與 1 做 OR，存回半字並返回 0。bit 0 原已為 1 時再投遞不會累計次數。正常返回不表示 handler 已執行，也不表示資料已送出。這是參考 ROM 的同步指令流程，不推斷 IRQ、實機 ROM 身分或實際派送順序。

核對：`python -B analysis/check_v4160_tx_event_leaf.py APP V131-carrier V140-carrier`。固定三份映像身分，核對 APP 尾段、兩個槽值與兩個完整函式；不是指令模擬器。
