# v4.1.60：模式計數回呼的記錄一致性檢查

接續[計數清零與累積](v4160-app-event-slot18-mode-counter-origin.zh-TW.md)。本輪只解讀原 APP 記錄緩衝區上的一致性檢查，不建立封包或執行設備流程。

- `0x1069e` 呼叫本地 `0xed00`，然後在 `0x106ac` 讀記錄 `+10`。`0x106b4/0x106b8` 比較該 byte 與本地函式的結果；相等回傳 1，否則回傳 0。這是上游計數器所使用的回傳值，不是模式值本身。
- `0xed00` 把記錄首兩個 byte 納入 8-bit 加總，以 `+2` 的無號 byte 當作迴圈次數。`0xed20` 在讀取迴圈資料前排除回呼指定的索引；在此呼叫中排除的是對應到比對欄位的索引。因此該欄位只在加總完成後由外層讀取，不會被此加總重複納入。這描述的是正常、成功讀取的本地語意，不推論外層資料來源或實機可達性。

Python `-O` 核對原 APP SHA-256、兩段原指令（88 bytes）與 4 個控制轉移，並以 1,408 組合成記憶體案例比對加總與讀取次序。未修改原 BIN 或正式來源，未接設備。下一步回到 `0x1074c`，整理從函式入口到模式 RAM store 還依賴哪些未確認的呼叫。
