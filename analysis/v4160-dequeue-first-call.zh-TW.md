# 非空記錄出列後：0x82d2 哪些路徑不呼叫子函式？

原 v4.1.60 APP，PC = 檔案位移 + 0x8000。`0x12cae` 傳入 `sp+8`（先前要求複製的 12-byte 記錄），`0x12cb0` 呼叫 `0x82d2`；`0x12cb4` 依回傳值是否非零跳 `0x12cee`。

`[0x82d2,0x838e)` 共 188 bytes、69 條指令；SHA-256 `7a49eb89a2c698b0a9d4a97083329c2a12e200c1f27fbdadec16784a6edb0e30`。按原碼順序，令 R 為記錄，T = 0x2000c794 + 4*i。`i` 從 0 開始，`0x838a` 設 1 後回到 `0x8308`，第二輪結束即返回。下述流程假定正常記憶體存取、完整堆疊、子呼叫若返回則保留所需寄存器；每個欄位以當次讀值為準。

| 跳過本輪兩個呼叫的分支 | 本輪對回傳暫存值 s4 的影響 |
|---|---|
| `0x8312`: U16[T+2] == 0xfffe | 不變 |
| `0x831a`: U8[T+5] != 2 | 不變 |
| `0x8326`: U8[T+4] == 0 | 不變 |
| `0x832e`: U8[R+2] > 8 | **已**在 `0x832c` 把非零 U8[T+4] 放入 s4 |

通過四關時，`0x8356` 經 `[0x4004c]` 請求從 R+3 複製到 sp+6，長度為初讀 R[2]（含零）；返回後重新讀 R[2] 和 T+2，`0x8368` 呼叫 `0x8a56(handle,192,sp+4,新長度+2)`。不能把兩次長度讀取當作同一樣本。

**可排除的範圍：** 若兩輪各自至少命中一個跳過條件，這次 `0x82d2` 沒有子呼叫，因而不經子呼叫重入設定初始化。s4 初值零，`0x8372` 將其送回 a0；即使兩輪都沒有送出，只要有一輪走「長度 > 8」且沒有後續改寫成零，呼叫者仍走非零分支。因此非零不是 TX 成功狀態。任一輪通過四關，則 TX 子樹仍須另查；本結論不涵蓋返回後的 APP 分派或中斷。

重跑：取原 BIN 位移 `[0x2d2,0x38e)`，使用 `rasm2 -a riscv -b 32 -s 0x82d2 -D <hex>`。從入口依序解碼：四個跳往 0x836a 的指令位於 0x8312/831a/8326/832e，全部呼叫點為 0x8356/8368。離線核對區段 SHA、長度總和、跳過目標及 `mv s4,a5` 的位置；未使用實機。
