# v4.1.60：事件回呼如何使用 7-byte 記錄

接續[記錄讀取範圍](v4160-app-event-selector-read-bounds.zh-TW.md)。以下以 `b0..b6` 表示複製到 `sp+8..sp+14` 的七個位元組；若改讀第零筆，以下處理的是重讀後的資料。

- `0x177c4..0x177de` 用 `b1 & 2` 決定是否選擇特殊分支；若設置，再用 `b1 >> 2` 分類。雖然原指令載入前四個位元組，類別位元只來自 `b1`。
- 類別 1 還要求 `b6 & 0x7c` 非零，才切換 `gp+369` 的低位元。若切換後的整個 byte 非零，對 `b4:b5` 所在的小端半字 OR `0x1f00`，因此只改 `b5`。給 `[0x40058]` 的第三參數為 `160 * ((b6 >> 2) & 31)`，不受這次改寫影響。
- 類別 2 用另一個索引 `gp+370` 取表項，保留 `b0/b1`，以表項低三個位元組覆寫 `b2/b3/b4`，保留 `b5/b6`，並對索引執行加一後取餘 7。給同一槽的第三參數改為 `800 * (1 + ((b6 >> 2) & 31))`。兩條算式都使用 `b6`，不使用四位元組載入時一併讀入的 `sp+15`。
- 一般分支，以及上述兩個間接呼叫正常返回到原續段時，都會在 `0x177e4` 把暫存記錄指標交給 `0xc776`。此報告只描述 APP 本段的欄位使用，不假設間接函式保留整份暫存記錄，也不替槽函式或欄位命名。

離線 Python `-O`：原 BIN SHA-256 與 184-byte 指令窗通過；65,536 組分類投影、512 組遮罩與覆寫投影、7 筆表項改寫投影通過。下一步用既有的 `0xc776` / `0xc6a8` 模型核對傳入後欄位是否仍被保留，不把合成提供者結果當成實機證據。
