# v4.1.60：佇列分派進入 `0x10b60` 的條件

接續[正常啟動順序](v4160-app-event-slot18-mode-start-order.zh-TW.md)。只核對原 APP 的正常分派和資料傳遞，不推斷其他入口或實機執行。

- 已抵達 `0x12d78` 時，`0x12d82` 在旗標 bit 3 為 1 時跳過；否則呼叫 `0x81aa`，其回傳為零時也跳過。繼續時 `0x12d8a` 以 `sp+8` 傳給 `0x14d2e`，不是直接使用佇列 RAM 槽位址。
- `0x14d2e` 保存記錄指標，透過 `0x829e` 讀獨立的模式 byte `0x2000bfb5`。大於 6 轉 `0x1549a`；其餘以模式索引 `0x1a6b8` 的相對位移表。七個目標依序為 `0x14d52, 0x14d5e, 0x153ba, 0x153da, 0x153fa, 0x1543a, 0x1547a`。模式 0 的 `0x14d52` 恢復呼叫框架並以原記錄指標尾跳 `0x10b60`。
- `0x10b60` 取記錄開頭的無號 16-bit 欄位。`0x0334`（820）及 `0x03e9`（1001）分別由 `0x10b6a`、`0x10b88` 進入同一個 `0x10bae` 區塊，設定 `a2=1` 再尾跳 `0x107c6`。此處的模式判斷與記錄欄位是兩次不同的讀取；證據到此不等於實機已把模式寫成 1。

Python `-O` 通過固定原 BIN SHA-256、4 個原始指令窗（182 bytes）、7 筆表項、模式位址、4 個分支目標及 3 個 JAL 目標。未改原 BIN 或正式來源，未接設備。下一步核對 `0x107c6` 的返回條件：哪些情況能到寫入函式，哪些會先退出。
