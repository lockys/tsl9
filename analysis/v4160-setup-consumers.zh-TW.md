# 入口輪詢結果在上層控制什麼？

`0x16e88` 返回的是入口輪詢狀態，不是八次設定結果的彙總。原 APP 以兩位元組對齊掃描 `JAL ra,0x16e88`，四處均落在 `0x16f00` 的同一個事件處理函式。這不是間接呼叫或可達性的普查。

- 若事件含遮罩 2，優先走第一條計數路徑；否則遮罩 4 選第二條。兩路各自增加一個 byte 計數器，先截為 8 位，結果大於 2 才清零並在 `0x16f38` / `0x16f6c` 呼叫。返回 0 才接 `0x16dd4(1)` / `0x16dd4(2)`，非零跳過。兩路正常完成均移除已選事件位，而不是把輪詢狀態當作 handler 返回值。
- 前兩個遮罩未選中才考慮遮罩 1。`0x16f86` 先用參數 1，返回 0 才在 `0x16f8e` 用參數 2。任一非零，都走 `0x16fa4`，向槽 `0x40058` 所指函式傳 `(入口 a0,1,48)`。兩次皆零才依序呼叫 `0x9af0` 與 `0x12b24(0)`。在各呼叫正常返回且保存相應暫存器下，兩支最後同樣移除遮罩 1。發出請求不等於已排入或執行重試；皆零也不等於外設已設定成功。

`python analysis/check_v4160_setup_consumers.py` 以固定原 BIN 核對四處直接呼叫、解碼四個分支的 16 組返回字決策及後續目標。不是連續執行整個 handler 或實機觀測。
