# v4.1.60：模式寫入前其餘兩個 resident 候選入口

接續[清零範圍](v4160-app-event-slot18-mode-fill.zh-TW.md)。本次以同一份 WCH V1.31 參考映像核對 `[0x40080]` 與 `[0x4022c]`，區分本體可確認的行為與仍需查證的子呼叫。

- `[0x40080] → 0x43c4e`：48 bytes、16 條指令。依既有 Xwchc 解讀，容量不足時回傳 255；容量足夠時更新登記計數、把回呼指標寫入表格並回傳原索引。此函式不直接寫 `s0`、`s1` 或 `sp`，也不呼叫登記的回呼。表格的實際位置與寫入效果仍取決於初始化狀態。
- `[0x4022c] → 0x43932`：118 bytes、42 條指令。`0x43934` 保存 `s0`，`0x43946` 與 `0x43962` 將其用作區域變數，`0x43992` 從同一堆疊槽還原。區間內三個呼叫目標為 `0x43728`、`0x20000314` 和條件路徑上的 `0x6df1a`。因此單靠這個 frame 的 save/restore 仍不能證明完整呼叫鏈保留 `s0`。

Python `-O` 通過候選映像 SHA-256、兩個 slot、166 bytes 的指令邊界掃描、save/restore 運算元及三個子呼叫目標。下一步先核對無條件呼叫的兩個子函式，再看條件分支是否需要額外前提。未連設備或執行固件，不主張實機綁定或模式 1 寫入已成立。
