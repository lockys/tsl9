# 紀錄解碼與狀態控制

[English](readme.en.md) · [來源](../../src/native/receive/record_state_controls.c) · [合約](provider-contracts.json) · [統計](summary.json)

重建17個相連完整函式，共1,322B／441條指令：四個10位元欄位解碼／封裝、selector優先順序、條件式通知、兩種輸入格式、延遲回呼及ROM表項介面。保留原始volatile存取順序、暫存器、ROM間接尾跳與私有組合語言介面。

四個解碼值快取於GP+244/246/248/250；變更時全部更新，並封裝至GP+252/256，保留第二個word的高24位。selector優先順序為b4.bit6→71、b4.bit7→72、b5.bit0→73、b5.bit1→74，否則70。這些是位元層級證據，不是功能名稱或物理單位。

224組比較／448個物件通過；50,396B原址吻合，覆蓋率65.62%。補齊12個入口並揭露7個下游依賴，仍缺126個提供者。四處回呼位址均接到實際重建函式，七張既有跳轉表重新核對通過。

已確認：原始指令、欄位遮罩、靜態位址算式與呼叫次序。推論：紀錄與狀態變更支援通知鏈。未確認：座椅等功能歸屬、物理單位、ROM/RAM映射、私有ABI、中斷與OTA。沒有目標／硬體執行或新BIN；百分比不是功能完成率或可刷入程度。
