# A2 訊息：釋放的是哪一塊？

接續 [A2 呼叫者](v4160-id7-a2-after-return.zh-TW.md)。在沿用初始化、配置、加到空佇列及取件後的 128 個合成 RAM 案例，以原訊息指標 M 執行 V1.31 參考 RAM 例程 `0x20000110` 至返回 `0x43200`。此處未重播整個呼叫者；外層已將模擬外設字清零，未建模真實中斷或外設。

- 從先前配置器獨立記下的返回值 P 核對 `M=P+8`；配置區塊表頭為 H=P−8。釋放前 H+6 的半字為 `0xf020`，H+4 的容量是 40。釋放器不是直接把 M 減 16 當表頭，而是走配置串列，最後在 `0x20000178` 把恰好 H+6 的標記寫成 0。
- 相鄰的下一塊 F=P+40 原本空閒。`0x200001ce/1d0` 寫回合併容量及下一個連結：H 的新容量是 `40+8+舊 F 容量`，新連結是舊 F 的下一個連結。無向前合併。半字可用量在 `0x200031a2` 先加 40，再加 8；合計 **48**（模 65536）。多出的 8 是不用再保留的一個表頭，不是訊息有 48 bytes。
- 每條已驗路徑共七筆 store，PC 尾碼依序為 `0118,0178,0186,01ce,01d0,01d6,0122`（基底 `0x20000000`）。沒有寫入 `[P,P+40)`：回收不等於抹除內容。
- 本機有限指令重播在一般 Python 及 `-O` 各通過 128 個案例，逐例對照原配置返回值、標記、容量、連結及記帳。假定 V1.31 常駐映射、Xwchc、成功記憶體存取和無干擾；並非真機觀測、其他配置布局的保證，或整份 BIN 的新增覆蓋率。本次僅發布報告。
