# 原廠記憶體／ROM 需求核對

[English](readme.en.md) · [機器可讀證據](evidence.json) · [C/C++ 檢查](../../experiments/tsl9-memory-rom-contract/README.md)

**已確認：V4.1.60 不能直接沿用舊 V4.1.00 的初始化配置。** 以下來自固定 SHA-256 原廠 BIN 的 AUIPC／ADDI、載入、寫入及分支指令解碼；沒有執行韌體。

| 啟動需求 | ID2581 V4.1.00 | ID2966 V4.1.60 |
|---|---:|---:|
| 重設入口 | `0x183FE` | `0x186AA` |
| 初始 GP | `0x20004000` | `0x20004000` |
| 初始 SP | `0x20010000` | `0x20010000` |
| 初始資料來源 | `0x1A7E0` | `0x1AB60` |
| 複製資料長度 | 136B | 128B |
| 清零起點 | `0x20004088` | `0x20004080` |
| 清零終點（不含） | `0x2000C950` | `0x2000C958` |
| 複製＋清零 RAM 範圍 | 35,152B | 35,160B |
| 清零長度 | 35,016B | 35,032B |

當前版本的證據位置：入口 `0x8000`，GP／SP `0x186AA–0x186B6`，資料來源 `0x186BA–0x186BE`，複製／清零 `0x186C2–0x186F4`。已逐 byte 核對既有 startup source map 的 38 條指令，再獨立解碼上述地址及兩版本的迴圈邊界。原始資料內容不在本次公開證據內。

V4.1.60 設定向量基址 `0x8038`、`mtvec=0x803B`、初始 MEPC `0x9008`，並跳往映像之外的 `0x40000`。保存的 WCH SDK 預設函式表為 `0x40034`；索引 5／6 對應 `0x40048`／`0x4004C`，名稱為 `tmos_memset`／`tmos_memcpy`。這些是**存放函式指標的位置**，不是函式入口；原機 ROM 內容、間接呼叫目標及私有 ABI 未確認。

**編譯驗證：** C11 與 C++17 均通過數值需求檢查；兩個 ET_REL 物件沒有非空已配置區段、重定位、未定義符號或程式標頭，沒有新增韌體程式碼。原有重建覆蓋率維持 **69.69%**，本輪新增重建 bytes 為 0。

**尚未確認：** 晶片完整型號與 PCB、實體 RAM／Flash 容量及所有權、ROM 身分與 ABI、中斷模式和優先權、時鐘／腳位、堆疊與堆積使用上限，以及完整 OTA／原機功能相容性。`0x2000C958` 到初始 SP 之間的 13,992B 僅為數值差，不能當成可用堆疊預算；64 KiB RAM 僅為候選容納條件。本輪不產生 BIN、不連線硬體，也不把舊候選映像當成可刷寫依據。

後續優先補齊輸入 selector 依賴 `0xAB08`、`0xAB7C`、`0xECA8`，並保留 `0x1AB48` 為尚未提供內容的資料表依賴。值得後續加入的功能是**按韌體 SHA-256 顯示記憶體／ROM 相容性檢查結果**；目前只有離線檢查，不宣稱已整合 App 或原機。
