# CRC、路由與周邊底層支援

[English](readme.en.md)

[原始碼](../../src/native/startup/platform_primitives.c)重建六個完整原始函式，共356B／134指令、19個私有碼區與7個直接控制參照。C11、C++17產物逐byte吻合；六個先前未解析入口都接到真實碼，沒有新增資料、回呼、外部依賴或替代空函式。

| 原始範圍 | 已確認的靜態行為 |
| --- | --- |
| 9290–92BA | `A0 xor (A1<<8)`後作8輪左移，以bit15決定是否xor多項式0x1021，每輪截低16位。是CRC16更新步驟；9334用0x5AA5起值並每輸入byte處理資料、累加和、前次回傳低8位，不能改稱一般12B單次CRC。 |
| 18604–18630 | 16B框架；從ROM槽40048呼叫清除名義RAM2000C920起56B，再把偏移4設3。後面的自迴圈處理器未混入此函式，未據此命名為時鐘初始化。 |
| 18E1C–18E86 | 16B描述子依序提供mask、模式暫存器偏移、觸發偏移及完整u32 enable。啟用時清0／4的mask、選定模式置位，再清8／12並依trigger設定；16選兩者，其餘用指定偏移。停用分支只清選定模式mask。保留RET之後的所有替代路徑。 |
| 1904A–19076 | 位址為40010000＋(A1&252)＋8，shift為4×(A1&3)。先清一個4-bit欄位，再新讀暫存器，把未額外遮罩的A0移位OR回去；沒有新增參數範圍檢查。 |
| 196C4–1971E | 控制半字保留0x3040，OR描述子前8個半字；次要半字清bit11；第9個描述子半字寫到周邊＋16。完整18B描述子讀取已確認，沒有狀態輪詢或錯誤回傳。 |
| 1971E–1973C | 完整u32 A1非零就設控制bit6，零就清bit6；保留第一次RET之後的停用分支及回跳共用寫入。 |

[契約](provider-contracts.json)及[原始指令](evidence.json)列出所有PC。結合上一輪17040：路由值2分別寫入第6／7路的欄位；mask192選bit6／7、模式偏移0、觸發偏移12、enable1。SPI式描述子前8個半字OR為0x0314，第9個為7，後續呼叫設控制bit6。這些是名義位址與程式行為，沒有讀取實際暫存器。

「SPI／EXTI／AFIO」是對暫存器布局的候選解讀；第6／7路對應哪個實體GPIO、外接控制器型號與數量仍未證明。與[先前硬體候選研究](../public-hardware-2026-10-20/README.md)相容，但本輪未重讀官方SDK，不以舊研究代替本顆TSL9的硬體確認。

主元件23196B code＋714B data、1426RELA、1955個非零FUNC區塊與71個真實別名。兩種語言的診斷ELF一致；23910個選定bytes在原始位址吻合，91個區段只合併相鄰已知bytes。入口0、PT_LOAD0，**不是可燒錄韌體**。流程覆蓋8046指令、1264個直接轉移、7460個一般順序位置與533個呼叫返回位置，沒有一般順序缺口；428個暫存器間接轉移、10個MRET及原EBREAK／向量資料邊界仍缺執行期證明。

目前118個C/H檔；184組來源比較、368個物件通過。舊117個C/H、180組比較及1081筆舊產物記錄不變。未提供依賴由96降到90：86個直接參照、3個僅供位址的回呼及1個1A69C的4B不透明預設資料。[摘要](summary.json)／[下一批入口](next-providers.json)。

可考慮加入**唯讀啟動設定稽核**，回報路由欄位、中斷遮罩／觸發及SPI式控制設定；尚未實作，需先證明實體映射、ROM合約及安全診斷介面。沒有改中斷濾波、時序或原有控制行為，也沒有執行韌體、HOST模型、ISA模擬或硬體操作。完整啟動／ROM／RAM／IRQ／OTA相容性仍未證明。原始build收據留本機，公開新增內容另作增量隱私檢查；舊Git歷史問題仍保留。
