# 0x9ad2：延遲回呼的兩次寫入與旗標讀取端

承接 0x9b76 排程 0x9ad2 的記錄。排程請求與回呼執行必須區分。若控制流真正進入 `0x9ad2`，其 18 bytes 不讀取傳入的 a0，也不再呼叫 provider。依序在 `0x9ad4` 以 byte 寫 `[gp+168]=1`，再在 `0x9ade` 以 32-bit word 寫 `[0x40010814]=2`，然後返回。

這個 RAM byte 與初始化函式 `0x9b4e` 清零的是同一位置。`0x9af0` 每次重讀它，僅為零時才向 `0x40010810` 寫 word 2。`0x9b36` 也重讀它，僅為零時才讀 `0x4001080c`、以 XOR 2 翻轉 bit 1、寫回同址。因此若回呼已執行且旗標維持為 1，這兩個入口都略過各自的外設存取。鄰近的 `0x9ae4` 雖然也寫 `0x40010814`，卻不設定旗標，不能視為同一個操作。

`check_v4160_callback_9ad2.py` 從原 BIN 指令執行這三個入口，在合成記憶體逐筆比對位址、讀寫方向、寬度、值與順序。覆蓋全部 256 byte 旗標 × 四種資料 word，並以回呼寫後的同一記憶體重新呼叫兩個讀取端；一般與 `-O` 均通過。這不證明實機排程、裝置寄存器副作用、板上訊號或腳位用途。
