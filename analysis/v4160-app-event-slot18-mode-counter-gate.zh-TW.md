# v4.1.60：模式 1 寫入函式的計數門檻

接續[佇列分派](v4160-app-event-slot18-mode-queue-dispatch.zh-TW.md)。只核對 `0x10bae` 進入 `0x107c6` 的既有程式路徑，不推論其他入口或實機結果。

- 這條入口把門檻 3 保存到堆疊，把模式值 1 保存到 `s1`，並於 `0x107d6` 呼叫 `0x1069e`。該回呼最後比較本地子程序的回傳與記錄 `+10` 的 byte，相等回傳 1，否則回傳 0。
- 回呼返回 0 時，`0x10810` 清計數 byte 並返回。回傳非零時，`0x107da..0x107e6` 計算 `next=(old+1)&255` 再做無號門檻比較；低於 3 則存回 `next` 並返回。達到或超過 3 才清計數、呼叫 `0x820c(0)`，正常返回後帶 `a0=s1` 尾跳 `0x1074c`。特別地，`old=255` 環繞為零，不會進到寫入函式。
- 在回呼正常返回、保存的門檻／暫存器不變及存取成功的前提下，512 組合成案例的分流為：256 清零返回、3 存回後返回、253 清零後到尾跳。這是窮舉單次分支，不是實機可達計數值的分布，也不是模式 RAM 寫入證據。

Python `-O` 通過原 BIN SHA-256、4 個解碼控制目標、8 條指令核對、512 組合成案例。未修改本機來源或 BIN，未接設備。下一步以原地讀寫來源為依據，核對正常路徑是否能累積到門檻，以及尾跳後的間接呼叫是否仍留下一個可限定的寫入路徑。
