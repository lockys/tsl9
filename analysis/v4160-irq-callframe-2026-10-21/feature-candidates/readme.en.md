# Five safe feature candidates

This is a bounded review of existing local APK-derived source, reconstruction code and saved static reports. It adds proposals only. No tests, compiler run, new download, device access, original/rebuilt target execution or ISA emulation was needed. [candidates.json](candidates.json) contains the exact evidence paths, functions, line ranges, version limits and required proofs for every candidate. `seal.json` binds those source files by complete-file hashes without copying payloads or credentials.

“Original present” below describes an evidenced baseline. The proposed extension has not been implemented or proven absent from the complete original product. Readable JS is an attributed reading projection; its recorded provenance is E13. Old V4.1.00 model addresses must not be assigned to the complete V4.1.60 behavior merely because one predicate matches across versions.

| Priority / proposal | Existing baseline | Useful extension and outstanding proof |
|---|---|---|
| 1. DND explanation and local interval preview | APK `show/update` references DND. Older static contracts contain enable17048, interval16F4A, event170E2 and state reader843A; reconstructed `da_run_pair` preserves value/known boundaries. E1–E5. | An end-user screen explains known, stale and unavailable states and previews relative intervals from explicit inputs. Establish version-specific report fields and freshness before any live status claim. A calendar schedule or hardware timer is unproved; do not issue toggles or schedule commands. |
| 2. Connection and update-stage panel | BLE `init/txCallback/connIsOK`, host `at_success/at_failure`, OTA `rxCallback/Write/Read/Verify`. E1,E6–E9. | Distinguish connection, notification readiness, SDK write callback, actual firmware response and comparison outcome. Attribute stale callbacks and shared-queue replacement correctly. A write callback does not prove Flash success; no extra retries, reconnect or resume behavior is proposed. |
| 3. Local settings snapshot and diff | `app.js/getFunListJs/storage` and original cache removal expose storage seams. Older loader12FDC..13124 references configuration operands but leaves ROM/Flash contracts unknown. E1,E10,E11. | A local allowlisted snapshot of confirmed harmless display preferences and a versioned diff. Begin with no fields until audited. Raw `set/btn` caches have not been proven safe; do not export everything or restore any module setting. Exclude identity, credentials, admin/service/control state. |
| 4. Offline firmware dossier | Existing page/index/checksum checks, exact profile table and image-fidelity reports. E5,E8,E9,E12. | For a selected local file, show hash/length, recorded role/version/provenance and distinct integrity/compatibility/bootability states. Parser limits and provenance still need verification. Hash/checksum equality does not authenticate a file or identify compatible hardware. Provide no download or Flash action. |
| 5. Redacted diagnostic bundle | Original version/connection presentation and explicit transport/OTA boundaries. E1,E6–E8,E12. | A bounded local JSON of nonidentifying versions, public firmware hashes, stage counts and unknown reasons, with a preview. Require a structured allowlist and privacy fixtures; never capture arbitrary logs, raw packets, memory, UID/VIN/MAC, keys or vehicle data. No automatic sharing or new diagnostic device commands. |

The first two are direct end-user app features; they do not depend on adding control functions to firmware. The settings proposal is intentionally a snapshot/diff only until schemas and sensitivity are established. Relative DND interval arithmetic is distinct from a wall-clock scheduler, notification-suppression promise or verified on-device behavior.
