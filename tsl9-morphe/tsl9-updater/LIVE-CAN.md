# 0.6 即時車況／CAN

0.6.1仍保留這些唯讀資料與未知檔位顯示；依使用者要求，門鎖／座椅已改為直接操作，不再依賴B0檔位／車速或車型checkbox。燈光設定的獨立條件保留。詳見 [DIRECT-CONTROLS.md](DIRECT-CONTROLS.md)。

新增第三個原生分頁「即時資料」。B0 車況與 C0 原始 CAN 分開顯示；不把未知 CAN ID 當作已知車輛訊號。

## 取得資料

連線後進入即時資料頁，按「讀取車輛狀態」。在汽車或即時分頁、正常運行模式、驗證完成且無 OTA／車控動作時，沿用原廠 B0[1] 約每秒查詢，A0 約每5秒查詢。CAN／BLE記錄期間允許這些唯讀查詢，TEXT模式及停止傳送中不查詢。

「開始 CAN 接收／記錄」沿用現有 C0 01 或 C0 FF FF ID篩選，沒有任意 CAN 傳送介面。開始後沿用硬體記錄的5分鐘、10000筆、512KiB字元上限，停止時送 C0 00並等待本機write完成。車控／OTA仍與CAN記錄互斥；離開前景會停止記錄。可停止後匯出原有硬體log。

即時 CAN 資料只在 RAM 中彙整最多256個ID，畫面每0.5秒最多顯示最近更新的50個。斷線／更換模組清空即時資料，既有硬體記錄仍可匯出。畫面直接顯示接收中或已停止，資料年齡隨時間增加。

## 欄位定義與證據

依原廠 `app-service.js pages/gauge/gauge.js.rx`（byte offset 213590／0x34256；SHA-256 `c5eb7ae87e5edf310379f19743d720114c9717c3484b8abd30ad8b158affc017`）的顯示公式實作。它是模組B0彙整格式，不是任意原始CAN ID的DBC。

| 畫面欄位 | 原廠解析 | 限制 |
|---|---|---|
| 檔位 | LE32(bytes0..3) bits9..11；1=P、2=R、3=N、4=D | 其他代碼顯示未知及原始值，不改判P |
| 車速原始值 | 同word bits0..8 | 物理單位未獨立核實，不標成km/h或mph |
| 電量百分比欄位 | 同word bits24..30，原廠`RightBottom[0]`加`%` | 101..127視為未提供；仍需硬體核對 |
| 里程 | LE32(bytes4..7)>>>6，除10，原廠加`km` | 至少8bytes；不繼承上一份長回覆的值 |
| 前／後行李廂 | 同word bit1／bit5，原廠命名`frunkIsOpen/trunkIsOpen` | 至少8bytes |
| 車門／車燈遮罩 | bytes0..4的原廠位元公式 | 僅顯示hex，未核實個別bit對應哪個門／燈 |
| 車內估計溫度 | LE32(bytes23..26) bits21..31，乘0.1減40 | 按原廠需至少33bytes才啟用擴展區 |
| 環境溫度 | byte27乘0.5減40 | 同上 |
| 電壓 | LE32(bytes28..31)低12bits乘0.002，原廠加`V` | 同上；測點未確認，不能稱為12V電池電壓 |

最新回覆不足4bytes時清除整份車況；短格式回覆不顯示缺少的選用欄位。B0收到時間、bytes及2.5秒新鮮度另列，收到新回覆不代表所有欄位已經與真車交叉驗證。

CAN ID是訊息通道號；DLC是資料bytes數；次數是目前保留期間該ID的接收次數；Hz是`(count-1)/(last-first)`的平均接收頻率，只有一筆時未知；年齡是距最近一次接收的秒數。ID若被256個上限淘汰，重新收到時該ID統計重新開始，總訊框計數保留。未加入未核實的特定CAN ID名稱或訊號公式。

「欄位意義」按鈕提供以上概念的簡／繁／英文說明。顯示原始bytes需另勾選，預設遮蔽；7DF與7E0–7EF診斷身分資料持續遮蔽。畫面勾選不會改變匯出log的`canData`記錄選項，兩者分開。

## 目前 P 檔問題

使用者0.5.1截圖已收到新B0，但檔位顯示未知、車速0，雖然實車在P。這和完全沒收到B0不同。新版車控提示附原始檔位代碼、即時頁列出代碼與回覆長度。尚缺該次debug log與原廠App儀表對照，不能宣稱已解決實車檔位問題，也不能將未知值當作P解除限制。

## 驗證層級

本機核心測試涵蓋4／8／33bytes、選用欄位不殘留、過期、未知檔位、CAN彙整上限、最新順序及遮蔽。Android測試注入合成B0/C0，檢查真實分頁與資料橋接、顯示／遮蔽切換、斷線清除、沒有自動開始記錄。

使用者3797筆記錄的ID／長度／時序已離線回放成148個ID；回放填入合成bytes，沒有重播到車輛、沒有證明各ID含義。實車車況欄位及車控動作仍待使用者交叉核對。精確APK與測試收據見 `artifacts/tsl9-updater/verification-0.6.0.json`。
